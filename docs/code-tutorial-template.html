The plan

[OPEN WITH ONE CONCRETE QUESTION.] What does attention compute, tensor by tensor, and how do we know our version is correct?

We build it in three steps. First a version that is slow but easy to read. Then a mask, so a token cannot look ahead. Then a check against PyTorch’s own kernel. The derivation lives in the theory post, so we only point to it.

Step 01

Write the naive reference

Goal A function that turns queries, keys and values into outputs, one visible operation per line.

The reference is the version every faster one must match. It should be short and obvious, so we write each operation on its own line and name the shapes.

Line 21 divides by sqrt(d). Without it the scores grow with the head size and the softmax saturates. Line 22 normalises over the last axis, which is the key axis.

Run the shape script. It builds random inputs and prints every intermediate tensor.

The first test checks the one property we can state without any other implementation: every row of weights sums to 1.

Step 02

Add the causal mask

Goal Stop position i from reading any position after it, and prove it with a test.

A language model predicts the next token, so it must not see the future. We set the scores above the diagonal to minus infinity before the softmax. Their weights become exactly zero.

Try the mask yourself. Change the sequence length and the window, and watch the boolean tensor that the code builds.

Break it

Change triu(1) to triu(0). Now the diagonal is masked too, so the first query has no key left. Its row is all minus infinity, and the softmax returns nan.

A nan in the first row is the signature of a mask that removes every key. Check the mask before you check the maths.

Check against PyTorch

Goal Match F.scaled_dot_product_attention to within float32 tolerance, then measure the speed gap.

A reference is only useful if we trust it. We compare it with PyTorch’s fused kernel on random inputs, with and without the mask.

Exercises

  1. Add a padding maskEasy Extend naive_attention with a (B, T) padding mask, and write a test where padded keys get zero weight.
    Hint

    Broadcast the mask to (B, 1, 1, T) before masked_fill.

  2. Find the crossoverMedium Run the benchmark for sequence lengths from 64 to 4096 and find where the fused path starts to win on your machine.
  3. Break the scaleMedium Remove the sqrt(d) and plot the entropy of each softmax row as D grows.
