The plan

Almost every speed and memory decision in a modern language model lives inside one small function. What does that function compute, tensor by tensor, and how do we know each faster version is still correct?

We answer by building it. We start with four lines of PyTorch. We add one idea at a time and test each one. By the end the same four lines run behind a config that covers the attention of Llama, DeepSeek and Swin.

The derivations live in the theory posts, so we link them and move on. Here we implement the idea and look at what happens.

The post has twelve parts. Each stands alone, so you can stop after any of them.

Part 01

Core attention: one function, one head

Goal Write attention with every intermediate tensor visible, and show it equals PyTorch’s version.

Attention takes three tensors. Queries ask. Keys answer how relevant they are. Values hold what gets passed along. Each output row is a weighted average of the value rows, and the weights come from query-key dot products.

Derivation inHow attention moves information

Read the shapes in the docstring first. The leading dimensions are free, so the same function serves one head or many. The rows of scores are queries and the columns are keys. That is why the softmax runs on the last axis: each query spreads its attention over the keys.

The scale matters. If q and k have unit-variance entries, their dot product has variance d. Dividing by sqrt(d) brings it back to 1, so the softmax does not saturate as the head grows.

Run it on the smallest case that shows everything: two queries, three keys, four dimensions.

Shapes in the core function
TensorShapeMeaning
q(B, H, Nq, d)One query vector per head and query position.
k, v(B, H, Nk, d)One key and one value per head and key position.
scores(B, H, Nq, Nk)Query i against key j in cell (i, j).
weights(B, H, Nq, Nk)Each row is a distribution over keys.
out(B, H, Nq, d)Same length as the queries, not the keys.

Self-attention: one sequence, three projections

Self-attention means q, k and v are all linear projections of one sequence. That is all a head is.

Cross-attention: two sequences

Cross-attention changes one thing. The queries come from one sequence, and the keys and values come from another. The output length follows the queries. The other sequence can have any length and even a different width.

Test

We compare our function with the trusted one, on random inputs, with and without a causal mask.

Break it

Remove the 1/sqrt(d). Nothing crashes. The largest weight in each row just climbs as the head grows, and the softmax turns into a hard pick of one key.

The mean top weight in the wrong column goes from 0.42 to 0.91, while the correct column stays near 0.11. Bugs that do not crash are the expensive kind. This is why a numeric test against a reference comes before everything else.

Checkpoint

  • shapes.py prints weight rows that sum to 1.
  • tests/test_core.py passes.
Part 02

Masks: deciding who may read whom

Goal Build every mask you will meet by hand, look at each one, and catch the two classic mask bugs.

A mask is a boolean tensor of shape (Nq, Nk). True means this query may read this key. We use the same convention as PyTorch’s SDPA. The most important mask is causal, and it has one detail that many first versions get wrong.

Padding is different. It belongs to keys, not to pairs. No query should read a pad token, so the mask has shape (B, 1, 1, Nk) and broadcasts over heads and queries.

Multimodal sequences need one more rule. Image patches have no reading order, so patches of one image may see each other in both directions. Text stays causal, and text after the image sees all of it.

Try them. Pick a type and move the sliders. The printed tensor is what the matching function in masks.py returns.

The script prints every mask in ASCII, including two you will see again later. Here are a few of them.

Break it

Two mask bugs come up again and again. The first inverts the mask with triu. The second blocks every key for a query, so the softmax has only minus infinity left to normalise.

A NaN that appears in one whole row is the signature of a fully blocked query. Left padding produces exactly this: a pad token at position 0 can only see itself, and it is masked. SDPA returns zeros for such a row, so our library backend matches it explicitly.

Test

The causality test states the property we care about. It never looks at the mask. Rewrite the future, then check that earlier outputs did not move.

Insight

Test the behaviour, not the tensor. The inverted mask above still has the right shape and the right number of True cells, so a test that inspects the mask could pass. The causality test fails at once: token 0 moved by 0.145 when token 5 changed.

Checkpoint

  • show_masks.py prints eleven masks and each one matches its definition.
  • tests/test_masks.py and the causality test pass.
Part 03

Head sharing: MHA, MQA and GQA

Goal Write multi-head attention, fuse its projections, then share keys and values across heads until one module covers all three.

Heads are a reshape

Multi-head attention does not add a separate network per head. It projects to the full width and cuts the result into H slices, so D = H * dh. Two helpers do the cutting and the gluing.

The contiguous() call is not decoration. After transpose, the elements are no longer in the order view needs, and view refuses to run. See the shape errors in the Break it box below.

Fused projections

Three linear layers mean three matmuls. One wide layer does the same work in one call, and the output is split afterwards. The weight of the fused layer is the three weights stacked. So we can copy one into the other and check the outputs match.

Fusing does not change the maths or the parameter count. On this CPU it is usually slightly slower, and the spread between runs exceeds the gap. In six reruns of scripts/compare_heads.py, for the projections alone, fused was slower in five and faster in one: 32 to 45 ms per call fused against 29 to 36 ms separate. The saved run has 39.21 ms against 38.33 ms. The usual argument for fusing is about accelerators, where one big matmul should use the hardware better than three small launches. We have not measured that on a GPU. GPT-2 style code (c_attn) and nn.MultiheadAttention both fuse.

Sharing keys and values

Queries are used once and thrown away. Keys and values for past tokens stay in the cache for the whole decode. So the cache pays for KV width, while the queries do not. That asymmetry is the idea behind multi-query attention. Keep H query heads, but use a single shared key and value head.

GQA sits between the two. Groups of n_rep = Hq / Hkv query heads share one KV head. The maths is the same once the KV heads are repeated to line up with the query heads.

One module for all three

Since the only difference is num_kv_heads, one class can cover all three. This is the module later tutorials reuse. C4 mirrors a trimmed copy.

Test

Copy the weights across and require equal outputs. Hkv = Hq must give MHA. Hkv = 1 must give MQA. We also tile GQA’s KV weights into a full MHA layer. They agree, which proves GQA is exactly MHA with tied KV heads.

Break it

Shape mistakes are the friendly kind of bug. They fail at once with a message.

Nuance

The parameter table shows GQA is not only about the cache. Going from MHA to GQA with Hkv = 8 also removes 37.5% of this layer’s weights. Whether that hurts quality is an empirical question. Ainslie et al. report quality close to MHA with speed close to MQA. Our tests cover correctness, not quality, so this tutorial makes no quality claim of its own.

  • tests/test_heads.py passes.
Part 04

RoPE and the KV cache

Goal Put positions inside attention, stop recomputing history, and check the memory formula against real tensors.

RoPE inside attention

RoPE encodes position by rotating queries and keys. The rotation has a useful property: the dot product of a rotated query and a rotated key depends only on how far apart they are. We build the tables once.

Derivation inHow models know where they are

This layout pairs dimension i with dimension i + d/2. It is the Llama and Hugging Face convention, and matching it lets us test against their code directly.

Two modes of attention

Generation runs in two modes with very different shapes. Prefill processes the prompt: Nq = Nk = N. Decode processes one new token: Nq = 1, and Nk = T, the whole history. Past keys and values never change, so we store them.

Theory inThe mechanics of LLM inference
Prefill and decode
TensorPrefillDecode at length T
q(B, Hq, N, dh)(B, Hq, 1, dh)
k, v used(B, Hkv, N, dh)(B, Hkv, T, dh)
scores(B, Hq, N, N)(B, Hq, 1, T)
position_ids0 to N-1T - 1 only

The dynamic cache reallocates at every step because of torch.cat. A static cache reserves the whole buffer up front and writes in place. The address never changes, which compiled graphs need.

Break it

Two decode bugs produce wrong text without any error. First, is_causal=True looks like the obvious flag. But SDPA aligns it top-left, so the new token sees only key 0. Second, forget the offset and RoPE restarts at position 0 for every new token.

The cache equivalence test catches both of them. This is why our SDPA backend only uses is_causal when Nq == Nk, and otherwise builds the bottom-right mask.

Test

Cached decoding must equal the full forward. We run it for MHA, GQA and MQA, on both cache types. A second test compares the whole module with Hugging Face’s LlamaAttention, using the same weights.

The KV memory formula

The cache holds one key tensor and one value tensor per layer. So its size is:

M_KV = 2 * L * B * S * Hkv * dh * b

Here L is layers, B is batch, S is sequence length, and b is bytes per number. Do not trust a formula you have not measured. The benchmark fills the cache through real forward passes and compares byte counts. These rows ran on CPU. On a Mac the script also reads the MPS allocator.

Formula and tensors agree exactly in every row. The formula counts only the cache. A real process also holds weights, inputs and allocator overhead, so the machine needs a bit more.

The second half of that output applies the verified formula to a full-size layer stack. These numbers are computed, not measured.

A 128K-token context costs 64 GiB with MHA and 16 GiB with GQA at Hkv = 8, in bf16, before a single weight is loaded. That is why cache layout is an architecture decision. Try your own numbers.

Part 05

Sparse, local and linear attention

Goal Show that a sparse mask saves nothing on a dense kernel, then build two kernels that really do save work.

A window mask, measured

A sliding window lets each query see only its last W keys. Part 2 already has that mask, so the first attempt is one flag: window_size=256. Most scores are now blocked, so this should be fast. Measure it first.

The scores (chunked) column prints n(2W - 1), a round upper bound. The loop computes a little less, 457,984 at N = 1,024, because the first chunk has no chunk before it.

Read the mask + sdpa column against full causal. At N = 16,384 the window is about 98% sparse, yet the masked call takes 959 ms against 259 ms for the full causal call. The sparse version is about 3.7 times slower. The mask does not remove any work. It adds a dense (N, N) tensor to build and read, and it forces the kernel off its causal shortcut.

Insight

A sparse mask on a dense tensor is still computationally dense. The scores are computed first and thrown away afterwards. Time follows the shape of the tensor, not the number of True cells in the mask.

Make the kernel know about the window

The fix is to stop computing what we will discard. Cut the queries into chunks of W. A chunk can only reach its own positions and the W - 1 before them. So one small attention call per chunk covers every allowed pair.

The last column of the output is the result. At N = 16,384 the chunked kernel takes 31.5 ms, about 30 times faster than the masked call. It also scales linearly: each doubling of N roughly doubles its time. The dense columns roughly quadruple.

Test

A faster kernel is only useful if it computes the same thing. We check it against the naive masked version, with windows shorter than, equal to and longer than the 37-token sequence, and during decoding.

Local plus global

A pure window can never carry information far in one layer. Longformer adds a few global tokens to the band. A global token reads every position, and every position reads it.

Block-sparse layouts

BigBird and similar designs think in blocks of tokens, not single tokens. Our version is for teaching: a local band of blocks plus a few global blocks, expanded to token level.

Now push the density down and time the dense path. The layout goes from 51% to 3% of pairs, and the time does not move.

This is why real speed-ups need a specialised kernel. BigBird on a GPU has to gather the allowed keys into a smaller tensor before the matmul. FlashAttention has to skip whole tiles. A mask alone can do neither, because a dense kernel has no way to act on it. We return to tile skipping in part 8.

Linear attention: change the kernel

The window approach keeps softmax and limits the keys. Linear attention takes the other route. It drops the exponential and uses a feature map phi, so that the score is a plain dot product phi(q) . phi(k). Then matrix multiplication can be reordered.

The same product in two orders, with a feature size of d
OrderIntermediateShapeCost
[phi(Q) phi(K)T] Vquery-key matrix(B, H, N, N)O(N² d)
phi(Q) [phi(K)T V]key-value summary(B, H, d, dv)O(N d²)

Causal linear attention is a recurrence

Causality needs each query to see only a prefix. So the summary becomes a running sum: S_t = S_(t-1) + phi(k_t) v_t^T. Then y_t = phi(q_t) S_t, divided by the same product with z_t. That is an RNN whose hidden state is the matrix S.

The first line shows that the reordering is exact. The state stays (1, 2, 8, 8) while the sequence grows. The recurrent and parallel forms agree to 3.6e-07.

Nuance

Linear attention is a different kernel, not an approximation of softmax. On the same inputs the mean difference is 0.111, while the output standard deviation is 0.217. That is large. Also, our causal training path uses the parallel form, and that form is quadratic in N again. The linear cost applies to the non-causal form and to decoding.

Performer-style random features (advanced)

This part is a research direction, not something current language models use, and our version is simplified for learning. Performer picks a random feature map whose dot product estimates the softmax kernel in expectation. More features mean a better estimate.

The error falls from 0.0403 to 0.0118 as m grows from 16 to 4,096. It falls slowly. The cost of the linear form is O(N m²), so large m cuts into the saving that motivated it.

Checkpoint

  • bench_window.py shows the mask columns growing fourfold per doubling, and the chunked column growing about twofold.
  • linear_demo.py prints 2.4e-07 for the reorder and 3.6e-07 for the recurrence.
  • tests/test_linear.py and the chunked tests in tests/test_backends.py pass.
Part 06

Attention over images, and between modalities

Goal Reuse the same module for image patches, make it local with windows, and connect images to text in the three common ways.

Theory inInside a modern vision encoder Theory inOne transformer, two modalities

A ViT layer is MHA without a causal mask

Patches do not arrive in an order, so a ViT layer needs no causal mask. Cut the image into patches and flatten them, and you have the (B, N, D) tensor that attention already takes.

To see attention work on content, we skip the learned projections and use raw pixels as q, k and v. The image is a dark background with one bright square. Pick a query patch.

Query 29 is inside the square. Its weight lands on the square, mostly on two bright patches. Query 0 is in the background, and it spreads over the square too, because bright patches have the largest dot products with everything. Raw dot products favour large norms. Learned projections and QK-norm exist partly because of this.

Windows: make it local, then let information cross

Global attention over patches costs N², and N grows with the square of the image side. Swin limits each patch to a small window. The key step is the reshape: each window becomes its own short sequence, and the windows move to the batch dimension.

Without the shift, a token could never leave its window, however many layers we stack. The cyclic shift has a side effect: a shifted window can now hold pixels from opposite image borders. They are not neighbours, so we block them.

Test

When one window covers the whole image, windowed attention must equal global attention. It is the shortest proof that partition and merge do not scramble anything.

2D positions

A grid needs row and column information. We show three standard answers. The first adds absolute 2D sine and cosine features to the patches. The second learns a bias for each (dy, dx) offset inside a window, as in Swin. The third is axial 2D RoPE, which rotates half of each head by the row and the other half by the column.

The two 2D RoPE scores with the same offset agree: -1.9130 for (5, 3) to (2, 1), and -1.9130 for (15, 13) to (12, 11). A different offset gives a different score. The 1D property from part 4 survives on the grid.

Learned queries: Q-Former and Perceiver

A language model should not pay for every image token. Cross-attention already gives us the tool: the output length follows the queries, so a fixed set of M learned queries gives M tokens for any image size. Q-Former and the Perceiver resampler differ in how the queries talk to each other.

Insight

At 1,369 image tokens with 30 text tokens, early fusion computes 1,957,201 scores per self-attention layer. A 32-token resampler brings that to 3,844, a factor of about 509, and the figure no longer depends on image resolution. The cost is that everything the language model learns about the image must fit through 32 tokens.

Three fusion patterns

Early fusion puts image and text in one sequence, and the multimodal mask from part 2 does all the work. Cross-attention keeps them apart, and text reads the image in extra layers. Gated cross-attention adds a learned gate that starts closed, so a frozen language model is unchanged at the start of training.

The last two lines are the gate test in numbers. At initialisation the block returns its input exactly, with a difference of 0.0. Open the gate and the output moves by 0.376.

Part 07

Multi-head latent attention

Goal Build DeepSeek-style MLA in four steps, and see what it pays for its small cache.

GQA shrinks the cache by sharing heads. MLA asks a different question: must we store per-head keys and values at all? It stores one small latent per token, and rebuilds per-head keys and values from it when they are needed.

Here are the projections. Each one belongs to a step below.

Step 1: compress

c_kv = W_DKV h maps each hidden state to r numbers. This is what goes in the cache.

Step 2: reconstruct

[k_nope; v] = W_UKV c_kv expands the latent back into per-head keys and values on the fly. The two helper methods are short.

Step 3: keep RoPE out of the latent

There is a catch. RoPE rotates keys by position. If we rotate the latent, the rotation cannot pass through the linear map W_UK. If we rotate the rebuilt key instead, we have to rotate the entire history again at every step, so the cache saves little compute. DeepSeek’s answer is to split the key in two. A large part has no position. A small part, k_pe, has RoPE and is shared by all heads. It is cached already rotated.

MLA shapes for the demo, with T cached positions
TensorShapeCached?
c_kv(B, 1, T, r)Yes
k_pe(B, 1, T, dr)Yes, after rotation
k_nope(B, H, T, dn)No, rebuilt from c_kv
v(B, H, T, dv)No, rebuilt from c_kv
q(B, H, N, dn + dr)No
out(B, H, N, dv)No

Step 4: compare the cache

MLA caches 160 bytes per token per layer here, 12.8 times less than MHA and less than MQA. The last block of the output shows the cost. MLA has more parameters than GQA or MQA at this size. And the rebuild has a time cost, which part 12 measures.

Absorption: skip the rebuild

Rebuilding K for the whole history at each decode step looks wasteful, and we can avoid it. q_nope . (W_UK c) equals (W_UK^T q_nope) . c. So we can fold W_UK into the query and W_UV into the output, and run attention directly on the latents.

Test

Absorbed and explicit must agree. The cache test also checks the claimed size from the formula.

Nuance

A low-rank cache can only store what passes through r. Our tests prove the code is correct, not that this rank is enough for a trained model. Quality at a given r is an empirical question, and this tutorial does not train anything. The numbers here say only what the cache and the compute cost.

Checkpoint

  • mla_demo.py prints 160 bytes per token for MLA and errors below 1e-6 for both decode paths.
  • tests/test_mla.py passes.
Part 08

SDPA, online softmax and FlashAttention

Goal Swap the kernel without changing the answer, then write the FlashAttention algorithm ourselves to see why it needs no score matrix.

SDPA: the trusted fast path

So far, the softmax layers have called one function, attend. Now we fill in what sits behind it. The first backend hands the work to PyTorch. Most of this function exists for one reason: the decode alignment bug from part 4.

Test

Every CPU backend must match the naive reference, with no mask, with a causal mask, and with a window.

The IO problem

Look at what the naive backend does at N = 8,192. It writes every score to memory, then reads them all back for the softmax. On one head that is 67 million numbers. With four heads in fp32, the score matrix alone is about 1 GiB, before the softmax makes its copy.

The theory post on memory explains why this hurts more than the arithmetic does. Compute has grown much faster than memory bandwidth, so a kernel that moves a large matrix in and out of slow memory spends its time waiting. FlashAttention never writes that matrix to slow memory. It computes small tiles that fit in fast on-chip memory and keeps only running statistics.

Theory inWhy fast GPUs still wait for memory

Online softmax: normalising without the whole row

Tiling has one obstacle. Softmax needs a denominator over the whole row and the largest value of that row for stability, but a tile holds only part of a row. The answer is to keep running values and correct them. We keep three per query row:

The running statistics, for one tile of queries
NameShapeMeaning
m(B, H, bq, 1)The largest score seen so far in this row.
l(B, H, bq, 1)The sum of exp(s - m) so far: the denominator.
acc(B, H, bq, dv)The sum of exp(s - m) v so far: the numerator.

When a new tile raises the maximum from m to m_new, everything accumulated earlier was computed against the wrong base. Multiplying by exp(m - m_new) fixes it. Run it on one query and six keys, split into two tiles of three, and watch this happen.

In tile 1 the maximum rises from 0.112 to 0.589, so the old sums shrink by alpha = 0.621. At the end acc / l matches softmax @ v to every printed digit, and we never held all six scores at the same time in the running values.

The full function is two nested loops around those same lines.

At N = 512 the output matches naive to 7.15e-07, and 28 of 64 tiles are skipped. Skipping is the second saving. The same two conditions in the loop cover causal masks and sliding windows, which is how FlashAttention gets the window speed-up that a dense mask cannot.

Measure every backend

Same inputs, same answer, different kernels. Each cell runs in a fresh process, so that one measurement cannot hide in another’s memory.

Three things stand out. First, sdpa is about 17 times faster than our naive backend at N = 8,192, and its peak extra memory stays near 10 MB. Second, sdpa and sdpa_flash track each other: 300 ms and 282 ms at N = 16,384. On this machine sdpa_flash is PyTorch’s CPU flash kernel, and sdpa can pick that kernel by itself. Third, our tiled Python loop takes about as long as naive, 1,919 ms against 1,853 ms at N = 8,192, while the peak extra memory falls from about 3 GB to 4 MB. Python runs the loop over tiles here, so read this as the memory result of the algorithm, not as its speed.

Nuance

These numbers are from a CPU, and CPU memory behaves differently from a GPU’s HBM and SRAM. They show the algorithm. The GPU run later in this part shows the speed-up on one H100. The CPU flash kernel and the CUDA kernels are different programs, so the sdpa_flash row says nothing about a GPU. Peak memory here is the growth of a process high-water mark, so small values are noise. Read the column at large N only.

The real kernels are GPU-only

Our tiled backend models the algorithm. We do not attempt a production kernel. The flash backend calls the real one, through the flash-attn package when it is installed, or through PyTorch’s built-in FlashAttention-2 kernel. The flash-attn package was not installed for the run below, so flash took the second route.

We ran this path once, on one NVIDIA H100 80GB HBM3 in bf16, with PyTorch 2.15.0 built for CUDA 13.2. The flash backend is PyTorch’s FlashAttention-2 through SDPA, the same kernel as sdpa_flash. The tests marked gpu come first.

The skipped test is the window-and-decode test, which needs the flash-attn package. So Tri Dao’s kernels are not measured. The seven passing tests compare the PyTorch FlashAttention-2 and memory-efficient kernels with naive. Now the same backend table as before, on the GPU.

This is one run and the hardware is a GPU in bf16, so do not set these cells beside the CPU table. At N = 16,384, sdpa_flash takes 0.6 ms with 4 MB of extra memory. naive takes 21.0 ms with 10,496 MB. That is 35 times faster and about 2,600 times less memory. sdpa_efficient takes 1.6 ms and sdpa_math 22.2 ms. Both flash and memory-efficient kernels keep extra memory near 4 MB, and the two unfused paths need more than 10 GB. This is the memory argument of the theory post, measured. Our tiled loop is far slower here, 14,759 ms, because it launches many tiny kernels from Python. It still holds its extra memory near 36 MB.

One result is only partly explained. The flash row takes 1.0 ms at N = 16,384, against 0.6 ms for sdpa_flash, and it is slower at every length although the kernel is the same. Our wrapper adds Python work on each call. A failed import flash_attn costs about 0.09 ms, measured on the CPU machine. That does not account for the whole gap, and we did not look further. Cells under 1 ms are also rough, since the table prints one decimal.

All the kernels sit behind one small table. A new kernel is one new line here, and no attention class changes.

Part 09

Dropout, biases and bounded logits

Goal Add the small tricks that shape the logits, and look at the distribution each one produces.

Theory inWhy transformers do not explode

Attention dropout

Attention dropout removes whole query-key links, then rescales what is left so that the expected output does not change. PyTorch hides this inside SDPA. Here it is in the open.

A mask is a bias

Part 2 used masked_fill with minus infinity. That is one case of a broader idea: add any tensor to the logits before the softmax. Causal and window masks are biases that take only the values 0 and minus infinity. ALiBi uses a linear penalty on distance instead, with a different slope per head. Because the backends accept a float mask, all of these compose by addition.

Head 0 charges 2.0 to read four tokens back. Head 7 charges 0.016 for the same distance. So some heads act locally and others read far, and no position table has a length limit.

QK-norm and soft-capping

Dot products grow with the square of the activation scale. If activations drift up during training, the logits grow fast and the softmax collapses onto one key. Two small changes bound the logits. QK-norm normalises q and k per head before the dot product. Soft-capping squashes the logits themselves.

Follow the plain rows. At 16 times the activation scale, the largest logit is 1,360, the top weight is 0.992, and the entropy is 0.02 against a uniform 5.55. Attention has become a hard pick. QK-norm does not move at all, because the norm removes the scale. Soft-cap keeps the logits below its cap of 5.

Nuance

A bounded logit is not a useful one. In the output, the capped entropy at scale 16 is 4.84, close to uniform, and the top weight is 0.008. Nearly every logit sits at plus or minus 5, so there is little left to choose between keys. If activations outgrow the cap, you trade a collapsed softmax for a flat one. This is why the cap is usually set well above normal logit sizes, as a guard rail. Also, SDPA has no soft-cap argument, so our SDPA backend raises an error rather than silently ignoring it.

Research variants

Four short variants close this part. They are not equally mainstream, so please do not read this list as a menu of equals. Each one keeps the shape contract.

The variants in variants.py
VariantThe changeStatus
Normalised (cosine)Logits are a learned temperature times cos(q, k)Used in shipped vision models such as Swin V2
Talking-headsLearned mixing of heads before and after softmaxResearch
DifferentialThe difference of two softmax maps, so that shared noise cancelsResearch
GatedA sigmoid gate on each head’s outputRecent research

We only run these. We do not train them, so nothing here says whether any of them is better. The tests check shape, causality and gradients.

Test

QK-norm has a clean bound. After RMS normalisation each vector has norm sqrt(d), so the logit is at most d / sqrt(d). We assert it at two activation scales.

We now have many modules and many kernels. Their combination would be a mess if each module knew about each kernel. It does not, because part 8 already split them. The config writes that split down.

Real attention layers become a few lines of YAML. This one is the Llama-style layer. On a GPU machine, change its last line to backend: flash and nothing else moves.

The middle block is the point of the design. The same GQA weights give the same output on the four backends it tries, to about 1e-7. The DeepSeek-like config has 149 million parameters and caches 576 numbers per token per layer. It builds on the meta device, so that line costs no memory.

Insight

Keeping architecture and backend apart makes the tests cheap. A new kernel only has to match naive on one signature, and then the layers that call attend get it. test_every_architecture_runs_on_every_backend has 25 cases, from 5 architectures and 5 backends. Of the 20 pairs for MHA, MQA, GQA and MLA, 19 run and match naive. It found one real limit. Flash kernels want equal widths for q, k and v, but MLA has dn + dr for q and k and dv for v. So MLA on sdpa_flash is skipped, with the reason written in the test. In the 5 linear cases the backend does nothing, because LinearAttention.forward never calls attend. This test also leaves out cross, window_chunked, sdpa_efficient and flash. Those have tests of their own elsewhere.

Part 12

Benchmark the zoo

Goal Measure training, prefill and decode for each architecture on one machine, and find out what each design really costs.

Part 8 compared kernels on fixed inputs. This benchmark compares whole attention layers. Every layer has D = 256, 8 query heads and B = 1, and every cell runs in a fresh process. The longest run is N = 16,384. GQA naive is the same layer as GQA on the naive kernel, and it keeps the score matrix for autograd, so its peak memory reaches about 25 GB at that length. A second run on one GPU follows the CPU analysis.

That is a lot of numbers. The chart lets you read one metric at a time. Both axes are logarithmic, so a line with twice the slope grows twice as fast in powers of N.

Four patterns stand out at N = 8,192.

  • Head sharing shrinks the cache and, at B = 1 on this CPU, slows backward. MHA, GQA and MQA have caches of 16, 4 and 2 MB. Their forward times are 175, 145 and 124 ms. Their backward times go up as KV heads fall, 424, 923 and 1,909 ms, and that order holds at every length in this run.
  • MLA pays in compute. Its cache is close to MQA’s, but a training forward takes 1,384 ms against 175 ms for MHA, and decode takes 3.85 ms per token against 1.26 ms. Part of this is the rebuild. Part is that unequal widths keep it off the flash kernel on this CPU. We ran the explicit path, not the absorbed one.
  • A mask on a window is slower than no window. local mask takes 390 ms where plain GQA takes 145 ms. local chunked takes 55 ms, and its prefill throughput is typically above 100,000 tokens per second and does not fall as N grows, while every other softmax layer does.
  • Linear attention wins decode only. Its decode is typically about 0.25 ms per token and shows no trend with length, with a constant 0.03 MB state. Its parallel training form is among the slowest here: 1,268 ms forward.

Why backward slows when KV heads are shared, at small batches

The backward column was a surprise, and bench_zoo.py uses B = 1 throughout. The profiler puts nearly all of the gap inside one PyTorch op, _scaled_dot_product_flash_attention_for_cpu_backward, where the time rises from MHA to GQA to MQA. Our layer reaches that op with enable_gqa=True, which hands the shared KV heads to SDPA without a copy. So bench_backward.py adds one more way to run the layer. It copies K and V up to 8 heads first, so the flag stays off.

Start with part 3 of the output: one layer, B = 1, N = 8,192. MQA backward takes 1,874 ms with the flag and 270 ms with the repeat. GQA takes 954 ms and 271 ms. MHA, which has no flag, takes 288 ms. So the repeat brings both back to MHA’s level. Forward stays between about 100 and 130 ms. The last block shows the same output, with parameter gradients within 8.7e-11.

Part 1 shows that the flag does not add work. It loses parallel speed-up. At 1 thread every path takes about 460 to 470 ms. From 1 to 8 threads, the paths without the flag speed up about 6 times in this run, and load on this shared machine moves that figure. The flag paths speed up 3.69 times with 4 KV heads, 1.91 times with 2, and 0.90 times with 1. With one KV head, 8 threads are no faster than one.

Part 2 shows that batch size matters. At N = 2,048, the flag / repeat ratio for MQA falls from 4.43 at B = 1 to 2.22 at B = 2, 1.72 at B = 4 and 1.13 at B = 8. For GQA it goes 2.44, 1.58, 0.93 and 1.01. An earlier run of the same script gave 1.66 for MQA at B = 4, and 0.98 at B = 8. So the gap remains at B = 4 for MQA, and it closes once B × HKV reaches 8: at B = 4 for GQA and at B = 8 for MQA. Rows with the same product also have similar ratios: 2.44 and 2.22 at a product of 2, 1.58 and 1.72 at a product of 4.

These patterns fit one explanation: with the flag, this backward kernel runs in parallel only across batch × KV heads. That is an inference from the timings, because we did not read the kernel’s source. The memory cost of repeat_kv is not measured. All of this is CPU, in fp32, and it says nothing about a GPU. The attnzoo layers keep the flag, so the backward columns above include this cost.

A direct probe of one SDPA call explained it. With one query and a cache of about 2,000 keys, the default choice took 78.84 ms when the cache length was new, and 0.144 ms when the same shape came again. With cuDNN excluded, the call took 0.05 ms either way. That probe script is not in the repo, and the numbers come from the code writer’s notes. Insight

A benchmark can time a setup step instead of the operation. Here the signal was a number that did not move with N: 60 to 75 ms of prefill at every length. When a timing ignores the size of the problem, look for a cost that is paid once per shape.

Nuance

The tables above are one attention layer on a CPU, in fp32. A full model adds feed-forward layers and a head. The GPU run below suggests several CPU gaps do not carry over. Cells at N = 8,192 and above are one measured call after a warm-up, and decode times below about 1 ms are close to the noise on a shared machine. So read their order of magnitude, not the digits. Nothing here measures model quality, and quality is the other half of choosing a design.

Key insights and nuances

  • Test behaviour, not tensors. An inverted mask has the right shape and the right count of True cells. The causality test still catches it at once. Part 2
  • The dangerous bugs do not crash. A missing scale, the wrong decode flag and a forgotten position offset all give plausible output. Only a numeric comparison finds them. Part 1 and Part 4
  • GQA is exactly MHA with tied KV heads. We proved it by tiling weights across, and the output matches. The cache saving comes from sharing, not from a new mechanism. Part 3
  • The cache formula is exact, so cache layout is an architecture decision. It matched tensor bytes in every row, and it puts a 128K context at 64 GiB for full MHA in bf16. Part 4
  • A sparse mask on a dense kernel is still dense, and on this CPU it is slower than no mask. Falling density from 51% to 3% left the time flat. Only a kernel that knows the window saves work. Part 5
  • Linear attention is a different kernel, not a fast softmax. Its decode cost is constant, but its parallel training form is quadratic again. Part 5
  • At small batches, sharing KV heads can slow training through one flag. At B = 1 and N = 8,192 on this CPU, MQA backward took 1,874 ms with enable_gqa and 270 ms with the KV heads repeated first, with the same output. The gap remains at B = 4 for MQA, and closes once B × HKV reaches 8. Part 12
  • A timing that ignores N may be timing setup. On the H100, cuDNN attention cost 60 to 80 ms for each new shape, and the first zoo run measured that, not attention. Part 12
  • A small cache can move the cost elsewhere. MLA caches little and takes far longer per forward pass here on its explicit path. Part 7 and Part 12
  • Online softmax is an exact algorithm. It matches naive to about 1e-6 while holding one tile. CPU timings show the algorithm. On one H100 in bf16, the fused FlashAttention-2 call was 35 times faster than naive at N = 16,384, with about 2,600 times less extra memory. Part 8
  • A cap can flatten attention as badly as a blow-up sharpens it. When activations outgrow the cap, entropy returns to near uniform. Part 9
