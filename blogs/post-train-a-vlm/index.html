The plan

When a vision-language model starts to prefer the true answer after post-training, did it look at the image, or did it learn which words tend to win?

Most of this tutorial exists to answer that question with numbers. A VLM can lower a preference loss without using a single pixel. It can also raise a visual reward by gaming the reward. Both failures look like progress on a training curve.

So we build the alignment stack on images where we know every fact exactly. We draw the image ourselves, so we know the true colour, count, position and text. That makes every preference label and every reward exact, and it lets us run controls that real datasets cannot.

We post-train a real pretrained model, HuggingFaceTB/SmolVLM-256M-Instruct. The tiny VLM from C7 and C8 is not capable enough for this. Preference learning and RL refine a model that can already do the task sometimes. A model that cannot read a colour gives DPO and GRPO nothing to refine.

Clone the repo once. Every command below runs from its root, using this virtual environment.

Nuance

Every run here is short, 60 to 150 update steps, with one seed and a held-out set of 30 to 150 items. The numbers are real, and they are small. A difference of a few points is inside the noise of a set this size, and the text says so where it matters.

Results come from two machines, a CPU and an H100, and each result names which. Treat them as a working demonstration of each method, not as a benchmark of SmolVLM.

Step 01

Draw scenes where the truth is exact

Goal A seeded image generator, and questions whose answers we compute instead of annotate.

A scene is a few coloured shapes and one printed word on a white canvas. Objects live in distinct cells of a 3 by 3 grid, so they never overlap. Each pair of colour and shape appears at most once, which keeps every question unambiguous.

Questions come with a sentence template that has one slot. This is what makes hallucination negatives cheap later: a rejected answer is the same sentence with one slot changed.

Next, load the model. SmolVLM normally splits a large image into tiles. Our scenes do not need that, so we switch it off. One 512 by 512 tile gives 64 image tokens instead of 1,088, which makes every later step faster.

Step 02

Generate hallucination negatives

Goal Turn every question into a preference pair, in two versions: one that needs the image, and one that does not.

A multimodal preference example has four fields: image, prompt, chosen, rejected. The chosen answer states the true fact. The rejected answer is a hallucination we manufacture, and it comes in five kinds: wrong colour, wrong count, wrong object, false OCR and wrong spatial relation.

How we draw the wrong value matters more than anything else in this step. So we write two samplers that share everything else.

Try both. Pick a kind, switch the sampler, and read the note under the pair.

A note on true values. If we let true counts follow the scene generator, they skew towards 1 and 2. Then a rejected answer of 3 would mostly appear on the rejected side, and text alone would predict the label. So build_pairs picks the target true value first, uniformly, then searches for a scene that has it.

Nuance

Balanced means balanced in the values we thought of. A real leak needs a joint distribution that is not exchangeable, for example a link between the prompt and the wrong value, or between the wrong value and the sentence length. In these outputs, BUS becomes two tokens and CAT stays one, which is a place such a link could hide.

So we do not trust the sampler by design. Step 6 tests it.

Test

A negative must be false for this image, and balanced values must appear about equally on both sides. test_negatives_are_always_false and test_balanced_pairs_are_exchangeable check both.

Checkpoint

  • You can read a pair and predict the answer only by looking at the image, on the balanced side.
  • On the biased side, you can often answer without the image. Keep that in mind for step 6.
Step 03

Turn one pair into tensors

Goal A batch where chosen and rejected share an image, and only answer tokens carry a label.

Each pair makes two rows. Both rows hold the same prompt ids, and then their own answer. We tokenize the answer separately and append it. That keeps the prompt ids identical to what generate() conditions on, so we train on the same probabilities the model samples from.

Now build the batch. Rows are padded on the right, labels are -100 outside the answer, and each row keeps an index into a smaller tensor of distinct images.

Look at what actually comes out. Two pairs give four rows and two images.

Label the whole row instead of the answer. In build_batch, change the label line to labels[i, : len(r)] = r, and run the test.

To debug this, read the numbers. The test expects 3 labelled tokens in row 0 of its tiny batch and finds 11, which is the length of the whole row. So the prompt is being scored as well.

The bug is quiet in training: the log-probability sum grows, and no shape error appears. Only a test on the label mask catches it.

Step 04

Compute sequence log-probabilities, naively and then fast

Goal One number per row: the log-probability of its answer, verified against the Hugging Face loss, with the vision encoder run only once per image.

Everything in DPO and GRPO reduces to one quantity, the sum of log-probabilities over answer tokens. The tensor work is three lines: shift, log-softmax, gather.

Read it line by line. logits[:, :-1] drops the last position, because nothing follows it. labels[:, 1:] drops the first label, so position t lines up with token t+1. The mask marks positions whose target is a real answer token.

clamp_min(0) exists only so that gather does not see an index of -100. Multiplying by the mask then zeroes those positions. The result is one log-probability per answer token, and zero everywhere else.

The naive way to get logits is to hand pixel_values to the model. It runs the vision encoder once per row. But chosen and rejected share an image, and G rollouts share an image. So we run it once per distinct image and write the features into the placeholder slots ourselves.

Test

Compare against a trusted implementation. Our sum must equal minus the Hugging Face mean cross-entropy times the number of answer tokens. The tests use a tiny random Idefics3 with SmolVLM’s module layout, so they run offline in seconds.

Now measure what the fast path saves. One forward and backward pass on one image and G rollouts, with all three model parts trainable. We run it on the CPU, and again on an H100 with one more group size.

Break it

Forget the index. In forward_logits, pass feats to merge_image_tokens instead of feats[batch.image_index]. Now there are features for each image, but slots for each row.

The message never mentions images. To debug it, print three numbers: feats.shape, batch.input_ids.shape and slots.sum(). Each row needs its own copy of the features for its image, so slots.sum() must equal rows times tokens per image.

There is a worse form of this bug. If rows and images happen to match in number, nothing raises, and rows can silently read the wrong image.

Step 05

Write image-conditioned DPO by hand

Goal The DPO loss with the image inside every term, trained on balanced negatives, with no second model in memory.

The derivation is in the theory post. Here is what the loss looks like in code. The image does not appear in this function, because it is already inside each log-probability.

Derivation inTeaching a model what we prefer

Each log-ratio asks one question: did the policy raise or lower this answer, compared with where it started? We multiply by beta, take chosen minus rejected, and pass the margin through -logsigmoid. At the first step policy and reference are the same model, so both ratios are about 0, the margin is about 0, and the loss is ln 2 to four digits. Any other first value means a bug.

The standard loss needs a reference model. A full second copy of SmolVLM costs about 1 GB. We avoid it in two ways.

First, the reference never changes, so we score every training pair once and keep the numbers. Second, we train a LoRA adapter, whose zero initial state means a fresh adapter leaves the model exactly at the reference.

Compare this with a trusted implementation, TRL 1.17.1. Its default loss line in DPOTrainer is -F.logsigmoid(self.beta * delta_score), which is the same as ours. It also accepts a PEFT model and disables the adapter to get the reference, as our lora_disabled can.

One difference matters here. TRL has a precompute_ref_log_probs option, but it raises an error on vision datasets, because it processes images on the fly.

Our pairs are small and synthetic, so scoring them once is cheap. We write the loss by hand so nothing is hidden, not because the library is wrong.

TheoryHow LoRA changes a model without rewriting it

The figure shows something the loss hides. In all five worked pairs the log-probability of the whole chosen sentence fell, for example from −7.33 to −35.26 in the OCR pair. Most of that fall sits in the tokens that the chosen and rejected sentences share, and in the trailing period, which cancel in the margin. In the OCR pair the shared prefix The word is went from −6.38 to −32.59 of the 27.93-nat decline, while the true-answer token CAT went from −0.95 to −0.08.

Step 06

Check whether the preference needs the image

Goal Two judges that cannot see: a text-only probe on the dataset, and the VLM on grey images.

Nothing in the DPO loss forces the model to use the image. If the words predict the label, the cheapest way to lower the loss is to learn the words. Agrawal and colleagues showed the same effect for VQA, where models learned answer priors from biased splits. So we test for it directly, in two ways.

Judge 1: a text-only probe on the dataset

This judge never loads the model. It is a logistic regression over word counts, predicting which of two answers was chosen. Its features flip sign when the two answers swap, so it cannot learn to prefer whichever comes first.

On balanced pairs the probe scores 49% on held-out data, which is about chance. On biased pairs it reaches 100% for colour, count and object, and 99% for OCR. Spatial stays at 58% on both sets, because a flip of left and right has no text-only hint. The biased total is 91% only because spatial pulls it down.

Each kind has 100 held-out pairs, so a score of 58% is within about two standard errors of 50%. The probe is a single fit on one seed.

Insight

Exchangeability gives this check a clean zero. If (a, b) and (b, a) are equally likely as (chosen, rejected), then any scorer that ignores the image is right on one and wrong on the other. So it scores 50% in expectation, whatever its priors are.

Any held-out score above 50% on such a set must come from the image. You do not get this guarantee on natural data, which is why the stratification in step 2 is worth its few lines.

Judge 2: the VLM on a grey image

The second judge is the model itself. We replace every image with a grey square of the same size and score the same pairs. The code path is the same: we only swap the images passed to pair_batch.

The VLM stages of the figure come from the two CPU DPO runs. The pretrained model scores 79.3% on balanced pairs with the real image and 47.3% with a grey one. That 47.3% matches the 50% of a blind scorer, and the gap above it is evidence that the model reads the pixels.

The shortcut shows up in one place. On biased pairs with a grey image, the pretrained model already scores 83.3%, because the wrong values are easy to reject from words alone. Biased DPO raised that to 90.0%, and balanced DPO lowered it to 57.3%. The gap exceeds the binomial noise of 150 pairs, but the two numbers come from two different training runs, and seed-to-seed variance is unmeasured.

Even the 57.3% hides a surviving shortcut. Per kind it is colour 50.0%, count 100%, object 30.0%, OCR 53.3% and spatial 53.3%, so the count pairs are still all answered correctly without the image. This is why a blind score should be read per kind and not only in total.

The effect on balanced pairs with the real image is weaker. The balanced run scores 88.7% and the biased run 84.0%. That gap is 7 pairs of 150, so one seed cannot show it is real. We read it as the direction we expected, and not as a measurement.

Break it

The biased run is itself the failure. Train it next to the balanced run and compare them on balanced pairs, as the figure does in its last stage.

Step 08

Build visual GRPO

Goal G sampled answers per image, rewards from the scene, relative advantages, one policy update.

GRPO needs no value model. For each image and prompt it samples G answers and compares them with each other. The method comes from DeepSeekMath, and the theory post covers why it works. We only add the image.

Derivation inHow reinforcement learning teaches models to reason

Rollouts are sampled at temperature 1 with no top-k or top-p, so that we sample the policy we then differentiate. Every row in a group shares one image, so the fast path from step 4 pays off here most.

Read the third group. All eight samples are wrong and identical, so every advantage is zero. Nothing is learned from that image, however bad the answers are.

Now read rollout 6 of the first group. It starts with the right number, but it scores 0, because exact_match compares the whole answer and the model kept talking. So this reward also teaches the model to stop. That is what we want here, but it is a choice the reward makes for us.

One training step, from the script. It is short because the pieces already exist.

Nuance

We set the KL weight to zero by default and take one update per batch. The loss function grpo_loss supports a KL term and clipping for several updates per batch, but the training script makes one update, so the ratio is 1. Dr. GRPO from Liu and colleagues drops the standard-deviation scale, among other changes, and group_advantages offers that variant. Setting these differently is a real choice to evaluate.

Checkpoint

  • test_group_advantages_are_relative_within_each_image and test_on_policy_grpo_gradient_is_advantage_times_score pass.
  • A flat group gives zero advantage in your own printout.
Step 09

Ask whether RL improved perception or reasoning

Goal The same GRPO run three times, with different parts allowed to learn, and tests that separate seeing from counting.

Counting is SmolVLM’s weakest skill here, so it is the task with the most room to move. We run GRPO on it with exact-match reward, three times. The seed and the data are the same. Only the trainable set changes, and the devices do not all match: the first two runs used an H100 and the third used the CPU.

An accuracy gain alone does not separate perception from reasoning. So we measure three things after each run.

  • Counting from pixels. The training task itself, on 100 held-out images. Always answering 1 scores 55% on this set, so every score is read against that.
  • Counting from text. We write the objects in the prompt and show a grey image. Here perception is not needed, but the answer format and the answer prior still matter.
  • The perception probe. A fresh linear probe from mean-pooled image features to per-shape counts. It is fit on 600 scenes and scored on 200 others, with the pretrained features and with the features after each run. If the pretrained score is already high, the counts were readable before RL.

A first version of this probe had no intercept. It scored 0.000 on features that held the answer, because the centred features give predictions of count minus the mean count, which run from -1.3 to +1.7, so rounding never matches. A score of exactly zero is a bug and not a finding.

The fix is the ym term in the listing, and tests/test_probe.py checks one case that is readable and one that is not. Every probe number in this post comes from the fixed script.

One more run needs no model. It prints how often each answer occurs in the held-out counting questions and in the training images, so a counting score can be read against the best constant answer.

The connector plus LLM run most likely collapsed to a constant answer of 1. Its training reward over the last 8 steps, 0.344, equals the share of 1 answers among the last 32 training images (11 of 32). Its groups were flat from about step 6 (52 of the 54 steps after it), and the logged sample for each of the 4 images in steps 46 to 59 was 1. or One.. Its held-out 55% is the majority rate and not a counting gain.

Its held-out score of 60% against 55% is within the noise of 100 questions. The pretrained 8% is below any constant guess because the model writes out-of-range numbers ( 5 at step 0), so much of the rise is learning the answer range and prior.

The LLM-only run cannot change the vision tower or the connector by construction, yet it ends at about the same held-out score as the runs that can. That does not separate counting from learning the answer range and prior, and this probe does not either.

Step 10

Hack the reward on purpose

Goal Train on a weak reward, watch how the policy responds, and build the monitors that catch it.

The prompt is List the colors of the shapes in the image. The weak reward is recall: the fraction of true colours mentioned. A caption that names every colour earns full marks. Hallucinated colours cost nothing, which links this step back to the start of the tutorial.

The monitors are small. We count the colours named, the colours named that are not in the image, the answer length, and a strict reward we do not train on. We log them on every step, whatever the training reward is.

The weak reward was gamed. Trained on recall, the policy reached recall 1.00 by naming 5.46 colours per answer, and 2.98 of them were not in the image. Its honest F1 on 50 held-out scenes fell from 0.765 to 0.703. In training, the honest F1 monitor fell from 0.85 to 0.63 while the training reward rose from 0.88 to 1.00.

The F1 reward did not show this. It reached F1 1.00 with 0.00 colours not in the image, and 2.48 colours named per answer. One line in the reward closed the exploit. That is a result about this reward and this task, and not a general claim about reward design.

Each run is one seed, scored on 50 scenes with four possible colours. By the last 8 steps nearly every group was flat, 1.00 for the recall run and 0.97 for the F1 run, because the reward was saturated. So the runs stopped learning because there was nothing left to push on. The F1 run reaching exactly 1.00 also shows the task is easy once the reward is right, so it says little about harder rewards.

Key insights and nuances

  • On a balanced set, any scorer that ignores the image averages 50%, so a score above 50% must come from the image. The text-only probe scored 49% on held-out balanced pairs and 91% on biased ones. Step 6
  • Read a blind score per kind, not only in total. The biased total of 91% hides 100% on colour, count and object, because spatial pairs stay at 58%. A left-right flip gives the words nothing to leak. Step 6
  • A shortcut shows up in the grey-image score, and it survives per kind. On biased pairs, DPO on biased negatives moved the grey-image score from 83.3% to 90.0%, and DPO on balanced negatives moved it to 57.3%, with count still at 100%. Both are one seed on 150 pairs. Step 6
  • A broken reference looks like a head start. With the reference set to zero, the first batch shows a loss far below 0.69, and nothing raises. A first loss other than ln 2 is a bug. Step 5
  • A preference margin can grow while the whole chosen sentence gets less likely. In five worked pairs the drop sat mostly in the shared prefix and trailing tokens, and the true-answer token often rose. That looks like format drift, and it is descriptive, not isolated. Step 5
  • Precomputing the reference is a choice that libraries may not offer for images. TRL 1.17.1 raises an error for that option on vision datasets. It works here because our pairs are small and synthetic. Step 5
  • A reward can pay in full for a useless answer. A whole-image box scores 1.00 on center_in_box and 0.038 on IoU. Audit a reward with hand-written bad answers before training on it. Step 7
  • A group with no spread teaches nothing. When all 8 rollouts for an image are the same wrong answer, every advantage is zero. Hard tasks can stall this way, however bad the answers are. Step 8
  • Encoding each image once matters more as G grows, but the gain depends on the machine. On the CPU it was 3.33 times faster at G = 4 and 7.65 times at G = 16. On the H100 it was 1.10 times at G = 4 and 2.99 times at G = 32. Step 4
  • A probe at its ceiling cannot show improvement, and a probe at zero is a bug. The fixed perception probe scored 99.5% on pretrained features and 99.0% to 99.5% after RL. Counts were already linearly readable before RL, and the LLM-only run reached a similar score without changing the features. Step 9
  • Compare a counting score with the best constant answer. Always answering 1 scores 55% on the held-out set. The connector plus LLM run scored 55% and its training reward equals the share of 1 answers, so it most likely collapsed to a constant. Training reward and the held-out score also use different scoring, so they are not directly comparable. Step 9
  • A zero from a first-word scorer can be a format effect and not a skill. The pretrained model scored 0% on the written-list control because it answers in sentences such as “There are 2 squares.”. Check what the model writes before reading a zero. Step 9
  • Mixed hardware turns an ablation into a footnote. Two counting runs used an H100 and one used the CPU, so the three rows are one experiment and not a controlled comparison. Step 9
  • A weak reward is gamed within 60 steps. Recall reward gave recall 1.00 with 2.98 colours per answer that were not in the image. F1 reward gave F1 1.00 with 0.00 such colours. Step 10

Exercises

  1. Grounding with GRPOHard Add a task that asks for the box of a named object, using box_reward. Train it on the weak center_in_box reward and then on IoU. Log mean box area as the monitor.
    Hint

    SmolVLM rarely writes four numbers unprompted. Give the format in the prompt, and count how many rollouts parse at all. If none parse, every group is flat, and nothing is learned.

  2. Measure the shortcut per kindMedium Make only OCR biased in wrong_value and leave the rest balanced. Train DPO and report grey-image accuracy per kind. Does the shortcut stay in OCR, or does it reach the other kinds?
  3. Make the shapes smallerMedium Make object sizes smaller in sample_scene and rerun the perception probe on the pretrained features. Find the size at which counting stops being linearly readable.
    Hint

    A 16-pixel patch merges into one token per 64 pixels. Objects smaller than that share a token.

  4. Switch off the std scaleEasy Pass scale_by_std=False to group_advantages and compare counting after 60 steps. Then compare the fraction of groups with one correct answer at each setting, to see how Dr. GRPO changes the weight of those groups.
  5. A better shortcut meterHard Replace the bag-of-words probe with a small sequence model trained on the same pairs. Can a stronger blind judge beat 50% on the balanced set? If it does, you have found a leak in the generator, and you should fix it.
