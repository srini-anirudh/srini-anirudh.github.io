Reading an image versus writing one

Show a vision-language model a photo of a small red house on a green hill. Ask it what it sees. It answers in one short sentence. Now ask the same model to draw that photo. Almost nothing in its design helps.

Every earlier post in this series built a model that reads images. A vision encoder turns pixels into a few hundred visual tokens. A connector maps them into the language model. The language model writes text, one token at a time. (Posts 02 and 03 cover those parts.)

The output of that model is always text. Text is short. It is discrete. Every position is a choice among a fixed vocabulary of words. A softmax over that vocabulary, trained with cross-entropy, is a good fit for it.

An image is none of those things. It is large. Its values are continuous. Neighbouring values are strongly correlated, so they cannot be chosen one by one without care. The encoder that reads an image throws most of the pixel detail away on purpose, because understanding does not need it. Drawing needs all of it back.

This post asks two questions. First, what has to change if one model must also write images? Second, should understanding and generation share one model at all, or is that a convenience that costs quality? We build the answer from the bottom up. We start with why images are hard to output. Then we look at how images are turned into things a transformer can emit. Then we compare the three main ways people have built models that both see and draw. Finally we look at the evidence on whether the two skills help each other.

The figure shows the asymmetry. The reading path ends in a word. The writing path ends in a grid of pixel values that must agree with each other. The rest of this post is about the machinery on the writing path, and about whether it can share a trunk with the reading path.

Why an image is hard to output

Count the bits

Start with size. A text vocabulary of 150,000 entries carries at most about 17 bits per token, since log2 150,000 ≈ 17.2. A thirty-token answer therefore carries at most about 520 bits.

A 512 × 512 RGB image has 786,432 values. At 8 bits each, that is about 6.3 million bits. The real information content is far lower, because images are redundant. But the output still has to be specified at that size. Some component has to put a value on every pixel.

Size alone is not the problem. A model could emit a long sequence. The deeper problem is that the values depend on each other.

Why you cannot simply regress the pixels

The simplest idea is regression. Give the model a caption c. Train it to output an image f(c) and penalise the squared error to the real image x. This fails, and the reason is worth deriving because it shapes every design below.

The training loss is the expected squared error over all images that match the caption:

L(f) = Ex ~ p(x | c) ‖ x − f(c) ‖² ∂L / ∂f = −2 E[ x − f(c) ] = 0  ⇒  f*(c) = E[ x | c ] The minimiser of squared error is the conditional mean. For a caption with many valid images, the mean of those images is not one of them.

Take the caption "a cat sitting on a sofa". In half the training images the cat sits on the left. In the other half it sits on the right. The squared-error optimum puts a half-transparent cat on both sides. With thousands of possible poses, colours and backgrounds, the average is a blur.

Text does not have this problem. A softmax over words can put 50% on "left" and 50% on "right". Sampling then picks one. The model never has to emit the average of two words.

So an image generator needs a way to represent a distribution with many separate modes, and a way to commit to one of them. There are two standard ways to do that. They are the subject of the next section.

Nuance

Regression to the mean is not only a textbook concern. BLIP3-o compared training a unified model to predict CLIP image features with a plain mean-squared-error loss against a flow-matching loss. With MSE, the predicted features became nearly deterministic for a given prompt, so the outputs lacked diversity. Flow matching restored sampling and gave better images. Any design that asks a language model to "regress the next image embedding" inherits this limit unless a sampler sits after it.

Two ways to generate an image

One piece at a time: autoregression

The first way is the one language models already use. Cut the image into a sequence of pieces x1, …, xn. Write the joint distribution with the chain rule:

p(x | c) = ∏i=1…n p(xi | x<i, c) The chain rule is exact. Each factor is a distribution over one piece, conditioned on everything already generated.

If each piece is a discrete token from a codebook, each factor is a softmax. The model can be trained with ordinary cross-entropy. At sampling time, the first tokens commit to one mode, for example "the cat is on the left". Later tokens are conditioned on that choice, so they stay consistent with it. This is how DALL·E, Parti, Chameleon and Emu3 draw.

The cost is the number of steps. With a key-value cache, each token costs one forward pass. A 512 × 512 image cut into 1,024 tokens needs 1,024 sequential passes. The order is also arbitrary. A raster scan goes row by row, so the top-left corner is decided before the model has any idea of the bottom-right.

All at once, many times: diffusion and flow matching

The second way works on the whole image in parallel. Corrupt a clean image x0 with Gaussian noise ε. Train a network to undo a small amount of that corruption. At sampling time, start from pure noise and apply the network many times.

Rectified flow, the form most recent unified models use, makes this very simple. Interpolate in a straight line between data and noise. Train the network to predict the direction of that line:

xt = (1 − t) x0 + t ε,    t ∈ [0, 1] Lflow = E ‖ vθ(xt, t, c) − (ε − x0) ‖² sample: xt−Δ = xt − Δ · vθ(xt, t, c),   from t = 1 to 0 The loss is a squared error again. It works here because it is evaluated at a noisy point, and the sampler takes only a small step before asking again.

This deserves a moment, because the previous section said squared error produces blur. The network does learn a conditional mean. But it is the mean direction at one noisy point, not the mean image. At high noise, that direction points toward a blurry average. The sampler moves a small distance and then re-evaluates. Each step commits a little more to whichever mode the current noisy image is closest to. After enough steps, the trajectory ends at one sharp image. Denoising diffusion (DDPM) and flow matching differ in the noise schedule and the prediction target. They share this logic.

The cost is again the number of passes, but now each pass covers the whole image. Transfusion samples with 250 diffusion steps. Flow models often use far fewer.

Points between the two

Several methods sit between pure raster autoregression and pure diffusion. They matter because unified models borrow them.

  • Masked parallel decoding. MaskGIT starts with every token masked. A bidirectional transformer predicts all of them at once. It keeps the most confident predictions and re-masks the rest. After a small number of rounds every token is filled in. The paper reports decoding up to 64 times faster than raster autoregression. Show-o uses this inside a language model and reports about 20 times fewer sampling steps than autoregressive generation.
  • Next-scale prediction. VAR predicts a 1 × 1 token map, then a slightly larger map, up to the full grid. All tokens of one scale are predicted in parallel. Coarse structure is decided first. VAR reported an FID of 1.73 on ImageNet 256 × 256 with about 20 times faster inference than its autoregressive baseline.
  • Autoregression over continuous tokens. MAR keeps the autoregressive order but drops the codebook. Each continuous token is sampled by a small diffusion head. This removes quantization error and keeps sequence modelling.
  • Discrete diffusion. UniDisc, MMaDA and Lumina-DiMOO treat both text and image tokens with a masked, diffusion-style process. Generation order is no longer left to right for either modality.

Insight

Text generation has one obvious order. Image generation does not. That single fact explains much of the design space. Raster autoregression borrows the text order and pays for it in steps and in early commitments made without global context. Diffusion, masked decoding and next-scale prediction all exist to decide global structure first. A unified model that wants one decoding loop for both modalities must accept the raster order for images, or give images a second, parallel loop.

Image tokenizers: what the model actually emits

A transformer cannot emit 786,432 pixel values directly at a useful cost. Almost every system first compresses the image with a learned autoencoder. The model generates in the compressed space. A decoder turns the result back into pixels. This compression step is called the image tokenizer, even when its output is continuous.

Vector quantization

The VQ-VAE is the starting point. An encoder E maps the image to a grid of vectors. Each vector ze is replaced by its nearest entry in a learned codebook {e1, …, eK}. The index of that entry is the token. A decoder D reconstructs the image from the chosen entries.

k* = argmink ‖ ze − ek ‖,    zq = ek* L = ‖ x − D(zq) ‖² + ‖ sg[ze] − zq ‖² + β ‖ ze − sg[zq] ‖² sg is stop-gradient. The second term moves codebook entries toward encoder outputs. The third term, the commitment loss, keeps encoder outputs near their chosen entries. The argmin has no gradient, so the decoder's gradient is copied straight through to the encoder.

VQGAN added a perceptual loss and an adversarial loss to this recipe. Those losses let the decoder produce sharp textures from a coarse grid. That is what made a 16-fold downsampling practical. Most discrete unified models still use a VQGAN-style tokenizer.

How many tokens an image costs

With a downsampling factor f, an H × W image becomes (H/f) × (W/f) tokens. Each token carries at most log2 K bits.

  • Chameleon encodes a 512 × 512 image into 1,024 tokens from a codebook of 8,192. That is at most 13,312 bits, about 470 times fewer than the raw 6.3 million.
  • Emu3 encodes a 512 × 512 image into 4,096 tokens from a codebook of 32,768. It uses 8 × 8 spatial compression. That is at most 61,440 bits, about 100 times fewer than raw.
  • Janus generates at 384 × 384 with a 16-fold downsampling tokenizer and a codebook of 16,384. That gives 576 tokens per image.

The decoder fills in the rest. It is trained to make the missing detail plausible, not exact. That is why tokenizer quality caps generation quality. Chameleon's authors name this directly. Their tokenizer struggles to reconstruct images with a lot of text, which upper-bounds the model on heavy OCR tasks.

Keeping the codebook alive

Vector quantization has a well-known failure. Many codebook entries are never chosen, so they never receive gradient and stay dead. A large nominal codebook can behave like a small one. Several fixes followed, and each one shows up in today's unified models.

  • Low-dimensional, normalised codes. LlamaGen projects codes to a low dimension and ℓ2-normalises them. Lowering the code dimension from 256 to 8 improved both reconstruction and codebook usage. Its tokenizer reached 97% usage with a 16,384-entry codebook.
  • Finite scalar quantization (FSQ). Project to a handful of dimensions and round each one to a few fixed levels. The codebook is implicit, the product of the levels, for example [8, 8, 8, 5, 5, 5]. There is nothing to collapse. The FSQ paper reports usage near 100% without auxiliary losses.
  • Lookup-free quantization (LFQ). MAGVIT-v2 shrinks the code dimension to log2 K and quantises each dimension to its sign. There is no codebook lookup at all. This makes very large vocabularies trainable. Show-o uses an LFQ tokenizer with 8,192 entries.

Other shapes for the token sequence

  • Residual quantization. RQ-VAE stores a short stack of codes per position. Each code quantises the error left by the previous one. A 256 × 256 image fits in an 8 × 8 map of stacks.
  • Multi-scale tokens. VAR quantises the same feature map at several resolutions with one shared codebook. This is what makes next-scale prediction possible.
  • One-dimensional tokens. TiTok drops the 2D grid. A transformer encoder summarises a 256 × 256 image into as few as 32 tokens. SEED produces a short one-dimensional sequence with causal dependency between tokens, so later tokens depend on earlier ones as words do.
  • Continuous latents. Latent diffusion uses a VAE without quantization. The FLUX VAE that BAGEL uses downsamples by 8 and keeps 16 channels per position. There is no codebook. Generation must then use diffusion, flow or a continuous-token head.

What a tokenizer should keep: meaning or pixels

A reading model and a drawing model want different things from the same image.

Understanding wants meaning. The encoder should map two photos of the same house, taken in different light, to nearly the same features. CLIP and SigLIP are trained for exactly that. They match images to captions, so they keep what captions describe and discard what captions ignore.

Generation wants detail. The tokenizer must keep the exact shade of red, the slope of the roof and the texture of the grass, because the decoder has to put them back. A VQGAN is trained for that. It keeps what reconstruction needs, whether or not a caption would mention it.

These goals pull a shared tokenizer in opposite directions. The cleanest evidence comes from an ablation in the Janus paper.

The Janus ablation

The Janus team trained the same 1.3B model six ways. They changed only the visual encoder and the training task. Figure 4 plots their reported numbers.

Read the bars in pairs.

  • A against D. Using a pixel-reconstruction VQ tokenizer for understanding is very costly. MMBench drops from 69.4 to 35.0. Generation barely changes: FID 8.72 against 8.53.
  • B against C. Even a tokenizer with semantic supervision loses when it must also serve generation. MMBench is 52.7 when the semantic tokenizer is trained on both tasks and 62.1 when it is trained on understanding only. That gap is the interference inside one shared encoder.
  • D against E. With decoupled encoders, unified training costs little. MMBench is 69.4 for the unified model and 70.6 for understanding alone.
  • D against F. Joint training did not hurt generation. FID is 8.53 for the unified model and 8.92 for generation alone.

One detail cuts the other way. Run B, the semantic tokenizer, generated better than run D (FID 7.11 against 8.53). The authors offer two reasons. Semantic tokens are easier prediction targets. And the semantic tokenizer was larger. Semantics may help drawing, not only reading.

The same tension inside generation itself

The conflict is not only between reading and drawing. It also appears between reconstruction and generation, inside a pure generator.

  • MAGVIT-v2 scaled the vocabulary of a VQ tokenizer. Reconstruction kept improving. Generation quality improved at first and then got worse for very large vocabularies. A bigger vocabulary is easier to decode but harder to predict.
  • VA-VAE found the continuous version. Raising the per-token feature dimension of a VAE improves reconstruction. But the diffusion model on top then needs much more capacity and training to generate well. Aligning the VAE latent space to a pretrained vision foundation model eased this.
  • REPA aligned the hidden states of a diffusion transformer with features from a pretrained self-supervised encoder. Training sped up by over 17.5 times for the same quality.

Insight

"Semantics for reading, pixels for drawing" is too simple. VA-VAE and REPA show that generators also train faster when their internal features are semantic. Janus run B shows the same in a unified model. The better summary is: a generator wants semantic structure in the middle and pixel detail at the end. That is the design logic behind models that generate semantic features and leave pixels to a separate diffusion decoder.

Four ways out

Work since 2024 has tried four ways to resolve the tension.

  1. Decouple the encoders. Janus, Janus-Pro and JanusFlow read with SigLIP and draw with a separate tokenizer or VAE. One transformer processes both. BAGEL and Mogao also use two visual encoders. This is the simplest fix and the evidence above favours it.
  2. Build a tokenizer that serves both. VILA-U trains one vision tower with a contrastive loss and a reconstruction loss. QLIP balances the two losses dynamically and reports that they need not conflict. UniTok argues that the conflict comes from the limited capacity of a discrete token space, not from the two objectives. It adds a multi-codebook quantizer and reports 0.38 rFID with 78.6% zero-shot ImageNet accuracy. TokenFlow uses two codebooks, one semantic and one pixel-level, linked by shared indices. Tar projects its codebook from the language model's own vocabulary.
  3. Generate semantic features and decode them separately. Emu2, MetaMorph, BLIP3-o and UniWorld have the language model produce CLIP- or SigLIP-like features. A diffusion model, trained separately, turns those features into pixels. The language model never handles pixel detail.
  4. Make one encoder do both from a generative start. Harmon shares a masked autoregressive encoder and reports that its features are strong enough for understanding. Show-o2 builds two paths on top of one VAE latent. One path is distilled toward SigLIP for semantics. The other keeps low-level features.

Nuance

Janus and UniTok seem to disagree about whether understanding and generation conflict in one tokenizer. They measured different things. Janus compared fixed-capacity tokenizers trained jointly, and the shared one lost. UniTok varied capacity and found the loss shrinks once the discrete space is large enough. Both can be true. If you must share a tokenizer, budget for extra capacity and semantic supervision. If you cannot, decouple.

Three ways to build a model that sees and draws

We now have the parts. A model that both sees and draws must decide three things. What representation does it emit for an image? What process turns that representation into pixels? And how much of the network do the two tasks share?

The answers cluster into three families. The architecture gallery draws Janus, JanusFlow and VILA-U on its standard plate; here we focus on the logic that separates the families.

  • Bridge models. A language model reads images as usual. To draw, it emits a small set of conditioning vectors. A separate diffusion model turns them into pixels. The two networks share no weights.
  • Fully autoregressive models. Images are converted to discrete tokens. One transformer predicts text tokens and image tokens with the same next-token loss. A tokenizer decoder turns the image tokens into pixels.
  • Hybrid models. One transformer predicts text tokens with a next-token loss and denoises continuous image latents with a diffusion or flow loss. Both losses update the same trunk.

The families differ most in where the bottleneck sits. In a bridge model, everything the language model knows about the image to be drawn must fit through a small set of vectors, often 64. In an autoregressive model, every image token must pass through a categorical choice, which loses whatever the tokenizer could not encode. In a hybrid model, there is no narrow interface inside the network, but the trunk must learn two very different tasks. The next three sections take each family in turn.

Bridge models: a language model that hands off to a diffusion decoder

The bridge idea is to reuse two strong pretrained parts. A multimodal language model already understands prompts and images. A diffusion model already draws well. Train a small interface between them.

Regressing image embeddings

GILL was an early example. It kept a text-only language model frozen and learned a mapping from its hidden states into the text-embedding space of an off-the-shelf text-to-image model. It could also decide whether to retrieve an image or generate one.

Emu took the next step. It encodes images with EVA-CLIP and compresses them into a fixed number of causal visual embeddings. The language model is trained on interleaved sequences to classify the next text token or regress the next visual embedding. A Stable Diffusion decoder is fine-tuned to turn those embeddings into images. Emu2 scaled this to 37B parameters, with 64 visual embeddings per image and an SDXL-initialised decoder. It reported strong in-context learning, for example subject-driven generation from a few examples.

DreamLLM avoided regressing CLIP features. It feeds a set of learnable "dream queries" into the language model. Their outputs condition Stable Diffusion, and the image loss comes from the diffusion model itself, through score distillation. A special token predicts where in a document an image should go, so DreamLLM can write interleaved documents.

SEED kept discrete tokens but made them semantic. Its tokenizer uses BLIP-2 features and a causal Q-Former, so the codes form a one-dimensional sequence with left-to-right dependency. A frozen unCLIP Stable Diffusion decodes them. SEED-LLaMA trained a language model on these tokens with plain next-token prediction. Kosmos-G aligned a multimodal model's output space with CLIP and used it for subject-driven generation from interleaved inputs. NExT-GPT extended the bridge to video and audio decoders.

Learning from understanding first

MetaMorph (Visual-Predictive Instruction Tuning) asked how much generation data a language model needs once it already understands images. It fine-tunes LLaMA-3 8B to predict SigLIP image features with a cosine loss, alongside ordinary visual instruction data. A diffusion "visualizer" turns the predicted features into pixels.

The findings are among the most useful in the field. Trained on generation data alone, the model struggled even with over 3 million image-text pairs. Trained jointly with understanding data, it could generate with as few as 5,000 generation samples and gave good outputs with 200,000. Section Synergy or interference returns to what this implies.

Freezing the language model

MetaQuery pushed the bridge to its simplest form. It keeps the multimodal language model completely frozen. A set of learnable queries is appended to the input. Their final hidden states pass through a trainable connector into a diffusion model, which is trained with its usual denoising loss on image-caption pairs. Because the language model never changes, understanding cannot degrade. The authors report that this matches fully fine-tuning the language model for generation while being much cheaper.

BLIP3-o studied the design choices inside this family. It compared VAE latents and CLIP features as the target, and MSE against flow matching as the loss. CLIP features with flow matching won on both training efficiency and image quality. It also compared joint training against sequential training: first understanding, then generation with the backbone frozen. Sequential training kept understanding intact and still produced strong generation. The 8B model uses a frozen Qwen2.5-VL-7B backbone, about 25 million open and 30 million proprietary images, and a 60,000-sample instruction set generated with GPT-4o. It reports 0.84 on GenEval.

UniWorld conditions generation on features from a multimodal model and a contrastive semantic encoder, with 2.7 million training samples. Qwen-Image, a generation model, uses Qwen2.5-VL as its condition encoder for an MMDiT. For editing, it feeds the input image both to Qwen2.5-VL for meaning and to a VAE for exact appearance. OmniGen2 and Step1X-Edit follow the same split between a multimodal reader and a diffusion writer.

Nuance

Bridge models are often described as "not truly unified" because the two networks share no weights. That framing misses why people build them. MetaQuery and BLIP3-o freeze the reader on purpose. Understanding quality is then guaranteed, and generation can be added without risk to it. The cost is the bottleneck. BAGEL's authors argue that a few dozen conditioning vectors lose information in long-context multimodal reasoning. Choose a bridge when understanding must not regress and the drawing task is mostly prompt-to-image.

Everything as tokens: fully autoregressive models

The opposite design removes every special part. Turn images into discrete tokens. Add those tokens to the vocabulary. Train one transformer to predict the next token, whatever its modality.

From text-to-image to early fusion

DALL·E (2021) modelled text and image tokens as one stream with a single transformer. Parti framed text-to-image as translation into ViT-VQGAN tokens and scaled an encoder-decoder transformer to 20B parameters. CM3leon added retrieval augmentation and instruction tuning to a decoder-only model that could go in both directions, text to image and image to text.

Chameleon made this a full multimodal foundation model. It is "early fusion": images are tokens from the very first layer, with no separate vision encoder. A 512 × 512 image becomes 1,024 tokens from a codebook of 8,192. The 7B and 34B models were trained on about 2.9 trillion text-only tokens, 1.5 trillion text-image tokens and 400 billion interleaved tokens, for 9.2 trillion tokens seen in total.

Chameleon's most transferable lesson is about stability. The standard LLaMA architecture diverged late in training. The authors traced it to the softmax, which is invariant to adding a constant to its inputs, when the modalities have very different entropy. Sharing all weights across modalities lets one modality's logits slowly grow. They needed query-key normalisation (QK-Norm), z-loss on the output logits, and for the 34B model a re-ordering of the normalisation layers. BAGEL later added QK-Norm for the same reason. (Post Why Transformers Do Not Explode covers these tools in the text-only setting.)

Anole fine-tuned the released Chameleon weights for interleaved image-text generation. Lumina-mGPT built a family of autoregressive models with a flexible representation for varying aspect ratios.

Emu3: next-token prediction only

Emu3 trained an 8B transformer from scratch on text, images and video with only next-token prediction. Its tokenizer, based on SBER-MoVQGAN, maps a 512 × 512 image or a four-frame clip to 4,096 tokens from a codebook of 32,768. Images keep their aspect ratio. Special tokens mark line breaks and frame breaks, and the resolution is given as plain text.

Two details matter for anyone training such a model. First, image tokens greatly outnumber text tokens, so Emu3 weights the loss on vision tokens by 0.5 to stop them dominating. Second, generation quality came largely from post-training. Emu3 ran quality fine-tuning on images filtered by preference scores, raised the resolution from 512 to 720 pixels, and then applied DPO on human-ranked samples. The post-trained model outperformed SDXL on the benchmarks the authors report.

Janus and Janus-Pro: decoupling inside an autoregressive model

Janus kept one autoregressive transformer but gave it two visual inputs. SigLIP-Large at 384 × 384 feeds understanding. A VQ tokenizer with a 16,384-entry codebook and 16-fold downsampling feeds generation. Each has its own two-layer MLP adaptor. A new head predicts image tokens. The base language model was DeepSeek-LLM 1.3B, and training took seven days on 128 A100 GPUs.

Janus-Pro changed the recipe, the data and the scale, and the changes are instructive.

  • Recipe. Janus spent two thirds of its stage-two generation steps on ImageNet class names, to learn pixel dependencies. Janus-Pro moved that work into a longer stage one with the language model frozen. It found the model could learn pixel dependencies there. Stage two then trained directly on dense text-to-image data.
  • Mixture. The supervised fine-tuning ratio of understanding, pure text and generation data changed from 7:3:10 to 5:1:4. Slightly less generation data kept generation strong and improved understanding.
  • Data. About 72 million synthetic aesthetic images were added, for a 1:1 ratio of real to synthetic data in pretraining. The authors attribute the more stable generations to this.
  • Scale. Janus-Pro comes in 1B and 7B sizes. The larger model's losses converged noticeably faster for both tasks.

Janus-Pro-7B reports 0.80 on GenEval, against 0.61 for Janus and 0.74 for Stable Diffusion 3 Medium. It reports 79.2 on MMBench. The authors also name the limit. Input and output resolution is 384 × 384, which hurts OCR and leaves small faces under-detailed.

Scaling and post-training discrete models

Liquid trained language models from 0.5B to 32B parameters on text plus image generation. It reports that the performance drop from unified training shrinks as the model grows, and that starting from a pretrained language model saves about 100 times the training cost of starting from scratch. VILA-U used a unified vision tower so the same discrete tokens serve both directions.

X-Omni addressed the main complaint about discrete generation: artifacts and weak instruction following. It combines a semantic image tokenizer, a 7B autoregressive model and an offline diffusion decoder, and uses reinforcement learning to improve generation. Emu3.5, a 34.1B model pretrained on more than 10 trillion interleaved tokens drawn mostly from video frames and transcripts, also uses large-scale RL. Its tokenizer has 131,072 vision codes. To fix speed, it converts token-by-token image decoding into parallel prediction with a "discrete diffusion adaptation", reporting about 20 times faster per-image inference. The authors report image generation and editing comparable to Gemini 2.5 Flash Image.

Discrete diffusion instead of left to right

Some discrete models drop the left-to-right order. Show-o keeps causal attention for text but predicts image tokens with MaskGIT-style mask prediction under full attention. It calls the combined mask "omni-attention". It is built on Phi-1.5 (1.3B) with an LFQ tokenizer of 8,192 codes, so a 256 × 256 image is 256 tokens. UniDisc, MMaDA and Lumina-DiMOO go further and use masked discrete diffusion for text as well. MMaDA adds a reinforcement learning stage designed for diffusion models.

Insight

A fully autoregressive image model is, mechanically, a language model with a larger vocabulary. LlamaGen showed what follows from that: existing LLM serving frameworks sped up its image generation by 326% to 414% with no new code. The same is true for training stacks, RL libraries and quantisation tools. The appeal of this family is less about image quality than about inheriting the whole language-model toolchain.

One transformer, two losses: hybrid models

Hybrid models keep the best generation process for each modality. Text is predicted token by token. Images are generated by diffusion or flow over continuous latents. Both run inside the same transformer.

Transfusion

Transfusion is the reference design. A VAE encodes each image into a latent grid. The grid is cut into patches. Each patch becomes one continuous vector in the sequence, between a begin-of-image and an end-of-image marker. Text tokens and image patches share every transformer layer.

Two changes make this work.

  • The attention mask. Attention is causal across the sequence, as in a language model. But patches of the same image may attend to each other in both directions. An image is generated all at once by denoising, so it needs to see all of itself. The ablations show that replacing this intra-image bidirectional attention with causal attention hurts text-to-image generation.
  • The loss. Text positions get the language-modelling loss. Image patches get a diffusion loss. The two are added with a weight:
LTransfusion = LLM + λ · Ldiffusion,    λ = 5 LLM is cross-entropy per text token. Ldiffusion is the noise-prediction error per image. The weight was set from preliminary experiments.

At inference, when the model samples a begin-of-image token, decoding switches modes. Pure-noise patches are appended and denoised over 250 steps. Then text decoding resumes.

The comparison with the token approach was controlled. At matched compute, Transfusion beat a Chameleon-style model for text-to-image at less than a third of the compute. It matched image captioning at 21.8% of the compute. Surprisingly, it also reached the same text perplexity at 50% to 60% of the compute. Adding small U-Net down and up blocks around the transformer let each image be compressed to as few as 16 patches. The largest model, 7B parameters trained on 2 trillion tokens, generated images on a par with similar-scale diffusion models and text on a par with Llama 1.

Nuance

In a hybrid model, the same image tokens are both a generation target and an input for understanding. These want different things. For generation the image must be noised; for understanding it should be clean. Transfusion found that captioning suffered when images placed before their captions were heavily noised. Capping the noise at half the schedule in those cases improved captioning with under 1% effect elsewhere. BAGEL solved it structurally: it keeps a noised copy for the loss and a clean copy, plus SigLIP features, for anything that comes after. Any hybrid design has to decide what later tokens are allowed to see.

Sharing less of the trunk

The next question is how many weights the two tasks should share. Several models answer "attention only".

  • MonoFormer shares one transformer for both, with the only difference being the attention mask: bidirectional for diffusion, causal for autoregression.
  • LMFusion starts from Llama-3. It keeps the text weights frozen and adds a parallel set of image-specific feed-forward, attention projection and normalisation layers. The modalities meet only in shared self-attention. Text ability is preserved exactly. The authors report better image understanding and generation than a from-scratch Transfusion at half the compute.
  • BAGEL calls this a Mixture-of-Transformer-Experts. It duplicates every weight of a Qwen2.5 language model. One copy processes text and SigLIP2 tokens. The other processes VAE tokens. Both see each other through shared attention in every layer. The model has 7B active and 14B total parameters. In a controlled 1.5B study, this layout beat both a dense model and a mixture-of-experts model at equal compute, with the largest gap on generation.
  • JanusFlow puts rectified flow inside a 1.3B language model, with SDXL-VAE latents, decoupled encoders, and an alignment loss that pulls generation features toward the understanding encoder's features. That is REPA applied inside a unified model.
  • Mogao combines deep fusion, two vision encoders, interleaved rotary position embeddings and multimodal classifier-free guidance to generate long interleaved sequences. Show-o2 moves Show-o to flow matching on a 3D causal VAE from Wan2.1, so images and video share one representation, with Qwen2.5 1.5B and 7B backbones. UniFluid does autoregression with continuous image tokens on Gemma, and reports that the balance weight between the two losses decides whether the tasks help or hurt each other.

Insight

The trend across LMFusion, BAGEL and the Janus line is to share attention and separate everything else. BAGEL's controlled comparison is the clearest evidence: duplicating the feed-forward and projection weights per modality, at no extra compute per token, beat a single dense trunk. The tasks benefit from seeing each other's tokens. They do not benefit from computing with the same weights.

What is known about closed native models

The products that made unified models widely visible are closed. Their technical details are mostly unpublished, so it is worth separating what the developers stated from what others inferred.

OpenAI, GPT-4o image generation. OpenAI's system card addendum of 25 March 2025 states that image generation is embedded natively in the omnimodal GPT-4o model, rather than handled by a separate tool. It says the model can take images as inputs and transform them, and can reliably render text in images. It describes the approach as significantly more capable than the earlier DALL·E 3 models. It does not give the architecture.

Google, Gemini native image output. Gemini 2.0 Flash introduced image output from the Gemini model itself, and Gemini 2.5 Flash Image followed. Google has not published the architecture. Open papers use both as comparison points: Step1X-Edit benchmarks against GPT-4o and Gemini 2.0 Flash for editing, MME-Unify evaluates Gemini 2.0 Flash as a unified model, and Emu3.5 compares itself with Gemini 2.5 Flash Image.

Outside inference. GPT-ImgEval trained classifiers on generated images and concluded that GPT-4o's images look more like the output of an autoregressive model with a diffusion-based decoding head than of a next-scale model. UniWorld argued from editing behaviour that GPT-4o likely uses semantic encoders rather than VAEs to read input images. Both are informed guesses, not disclosures.

The practical point is narrower than the speculation. These systems showed that a single assistant can edit an uploaded image by instruction, keep the subject's identity, and render legible text. That raised the bar for every open model in this post, and most of the 2025 work was a response to it.

Does seeing help drawing, and does drawing help seeing

The strongest argument for one model is synergy. If the two skills help each other, a unified model should beat two separate ones of the same total size. The strongest argument against is interference. If they compete for capacity, each will be worse. The evidence supports a more specific answer than either.

Evidence that understanding helps generation

  • Data efficiency. MetaMorph's model generated poorly from generation data alone, even with over 3 million pairs. With understanding data in the mix, 5,000 generation samples were enough to start and 200,000 gave good results.
  • Which data helps. In MetaMorph's grid of runs, adding visual question-answering data improved understanding and generation more than adding the same amount of generation data. Generation data helped too, but less.
  • Which skills correlate. General, vision-centric and text-and-chart question answering correlated strongly with generation quality, each with a Pearson correlation above 0.85. High-resolution question answering correlated moderately, around 0.7. Knowledge-heavy benchmarks such as MMMU correlated weakly. The skills that transfer are perceptual, not encyclopaedic.
  • Knowledge in the prompt. MetaMorph and later WISE-style tests show that a language-model trunk can draw concepts that require world knowledge, where diffusion models with frozen text encoders often fail.
  • Semantic features in editing. BAGEL found that feeding both SigLIP2 and VAE features of the input image beat VAE features alone on editing, with the largest gap on edits that require reasoning.

Evidence of interference

  • Shared tokenizers. In the Janus ablation, sharing a semantic tokenizer between tasks cost about 9 MMBench points against training it for understanding alone.
  • Optimisation. BAGEL found that the diffusion loss prefers a larger learning rate and the language loss prefers a smaller one. It also found that raising the share of generation data lowered the diffusion loss while leaving the language loss roughly unchanged. It resolved both with separate loss weights and by sampling generation data more often.
  • Stability. Chameleon's divergence came from sharing all weights across modalities with different entropy.
  • Scale dependence. Liquid reports a measurable drop from unified training that shrinks as models grow from 0.5B toward 32B. UniFluid reports an inherent trade-off that a well-chosen loss weight turns into mutual gains.

Does the model use both skills together at test time

Training-time synergy is not the same as a model using one skill to perform the other. RealUnify tested this directly with 1,000 human-annotated tasks. Half need understanding to guide generation, for example drawing the result of a reasoning step. Half need generation to aid understanding, for example mentally reconstructing a shuffled image.

The best open-source model averaged 37.5% on the understanding-guides-generation tasks. When the same tasks were split into an explicit "understand, then generate" pipeline, BAGEL improved from 32.7% to 47.7%. The knowledge was present but not used end to end. Splitting the other category into "generate, then understand" made results worse: models fell back on understanding shortcuts. A pipeline of two specialist models, Gemini 2.5 Pro for understanding and GPT-Image-1 for generation, reached 72.7%.

Insight

The synergy is real but lopsided and mostly happens during training. Understanding makes generation data-efficient, and perceptual understanding skills track generation quality. Generation helps understanding much less. At test time, current unified models do not spontaneously route knowledge from one skill into the other, as RealUnify's stepwise results show. If a product needs understanding to inform drawing, make that step explicit, for example by planning in text before generating.

The training recipe

Across families, open unified models follow a similar sequence of stages. The details that differ are the ones that decide quality.

Stages

  1. Alignment. Train only the new parts: adaptors, image heads, connectors. Keep the backbone frozen. Janus trains its two adaptors and image head this way. BAGEL first aligns SigLIP2 to Qwen2.5 by training only the MLP connector on captioning. Janus-Pro found a frozen language model can even learn basic pixel dependencies here.
  2. Unified pretraining. Unfreeze the trunk. Mix text-only data, image-text pairs in both directions, and interleaved documents. BAGEL and Emu3.5 lean heavily on video-derived interleaved data, where consecutive frames give natural "edit" pairs with consistent identity.
  3. Supervised fine-tuning. Instruction data for understanding, high-quality prompts and images for generation, and editing triplets of source image, instruction and target.
  4. Preference optimisation and RL. Emu3 applied DPO to human-ranked generations. X-Omni, T2I-R1, MMaDA and Emu3.5 use reinforcement learning with image rewards. The mechanics carry over from preference optimisation for text and from RL for vision-language models; the rewards here are detectors, preference models and VLM judges.

Data

  • Recaptioning. Web alt-text is short and noisy. Most models recaption images with a VLM. BLIP3-o used Qwen2.5-VL-7B for all its captions. Emu3 attributes its strength on dense prompts to synthetic labels. Transfusion notes that synthetic captions raised a small model's GenEval from 0.433 to 0.498 in Stable Diffusion 3's experiments, and chose to use only natural data for simplicity.
  • Synthetic images. Janus-Pro added about 72 million synthetic aesthetic images. BLIP3-o built a 60,000-sample instruction set by prompting GPT-4o. BAGEL used FLUX.1-dev to render targets for its reasoning-before-generation data.
  • Quality filtering. Emu3 selected fine-tuning images by averaging three preference and aesthetic scorers.
  • Editing pairs. InstructPix2Pix generated pairs with GPT-3 and Stable Diffusion. MagicBrush annotated over 10,000 triplets by hand. ImgEdit curated 1.2 million pairs with a pipeline of a VLM, a detector and a segmenter.

Post Mixing Data Without Losing Capabilities covers the general theory of mixtures; the unified-model specifics are below.

Balancing the two losses

The published loss weights look contradictory. Emu3 multiplies the image-token loss by 0.5. Transfusion multiplies the image loss by 5. BAGEL samples four generation examples for every understanding example. These are not disagreements. They correct for different ways of counting.

In Emu3 every image token gets its own cross-entropy term, the same as a text token. A 512 × 512 image contributes 4,096 terms; its caption contributes a few dozen. Without a correction, image tokens would supply almost all of the gradient. The weight of 0.5 reduces that share. In Transfusion the diffusion loss is computed once per image and averaged over its patches. A whole image then counts about as much as one text token, so it is weighted up. The general rule is to check how each loss is normalised before copying a weight from a paper.

Nuance

A falling loss is not evidence that the mixture is right. BAGEL found that more generation data lowered the diffusion loss while the language loss stayed flat, and that the two losses wanted different learning rates. Janus-Pro found the opposite lever for its supervised stage: slightly less generation data improved understanding without hurting generation. Mixture choices need downstream evaluation on both skills, not loss curves.

Classifier-free guidance

Almost every model in this post samples images with classifier-free guidance. It is worth deriving because it changes what the model outputs.

During training, the condition is dropped some of the time. Janus replaces the prompt with a pad token 10% of the time. The same network then models both p(x | c) and p(x). At sampling time, the two predictions are combined:

ℓg = ℓu + s · (ℓc − ℓu) log pg(x) = log p(x) + s · log p(c | x) + const ℓc and ℓu are the conditional and unconditional logits for the next image token (for diffusion, the two noise predictions). The second line follows from Bayes' rule: the difference of the two log-probabilities is an implicit classifier log p(c | x), and guidance raises it to the power s.

With s = 1 the model samples its true conditional distribution. With s > 1 it favours images that make the prompt more likely, at the cost of diversity. Janus uses s = 5 by default. Emu3 used a guidance scale of 5.0 for its compositional benchmark. Guidance doubles the forward passes, because both predictions are needed at each step.

Unified models extend guidance to several conditions. BAGEL drops text tokens with probability 0.1, SigLIP tokens with probability 0.5, and clean VAE tokens with probability 0.1, so it can guide on each separately. Mogao uses a multimodal form of guidance for interleaved inputs. UniTok reports that its tokenizer makes guidance much less necessary: without guidance, its gFID on ImageNet fell from 14.6 to 2.5.

Tasks that need both skills at once

Text-to-image generation alone does not need a unified model. A diffusion model with a good text encoder does it well. The case for unification rests on tasks where reading and drawing must happen in one context.

Instruction-based editing

"Make the bicycle blue and remove the bag." The model must find the bicycle and the bag, understand the instruction, change exactly those regions, and keep everything else, including identity and lighting. InstructPix2Pix trained a diffusion model on synthetic edit pairs. Emu Edit added recognition tasks to its multi-task editing training. Step1X-Edit uses a multimodal language model to read the image and instruction and a diffusion decoder to draw.

Editing is where the two kinds of image features meet most clearly. Preservation needs the exact appearance, which a VAE keeps. Following a semantic instruction needs meaning, which a semantic encoder keeps. Qwen-Image feeds the input image to both. BAGEL found that both together beat the VAE alone, especially on edits that require reasoning about the request.

Interleaved generation

A how-to guide with a picture after each step, or a story with illustrations, needs text and images in one sequence, each conditioned on everything before it. Chameleon's human evaluation found its mixed-modal answers competitive with Gemini Pro and GPT-4V on prompts that expect interleaved output. DreamLLM, MM-Interleaved, Mogao and Emu3.5 target this setting.

Subject-driven and in-context generation

"Draw this dog, from the photo, on a beach." Kosmos-G and Emu2 handled this from interleaved image and text input without per-subject fine-tuning. OmniGen and OmniGen2 treat many such tasks as one instruction-following problem; OmniGen2 introduced the OmniContext benchmark for subject consistency.

Reasoning before drawing

If understanding does not flow into generation spontaneously, one fix is to make the model write its plan first.

  • GoT builds generation chains-of-thought: an explicit text plan of semantic and spatial relations, written by Qwen2.5-VL, that a diffusion model then follows. Its dataset has over 9 million samples.
  • T2I-R1 trains Janus-Pro with RL over two levels of reasoning: a semantic plan of the prompt and the token-by-token image generation itself. It reports a 13% gain on T2I-CompBench and 19% on WISE.
  • Guo and colleagues applied test-time verification, DPO and a step-wise reward model to autoregressive generation, improving Show-o's GenEval score by 24%.
  • BAGEL has a thinking mode that reasons in text before generating or editing.

Drawing to reason

The reverse direction uses generated images as intermediate thoughts. Multimodal Visualization-of-Thought has the model draw its spatial reasoning steps as images, with a loss that keeps the visualisations coherent. Visual Planning plans entirely in images, trained with GRPO, on navigation tasks such as mazes. Post Thinking With Images covers reasoning that uses images, and post From VLMs to VLAs covers models that predict the visual consequence of actions. BAGEL reports future-frame prediction and navigation, and Emu3.5 describes world exploration and manipulation, as capabilities that emerged from video-heavy interleaved data.

How unified models are evaluated

A unified model needs three kinds of evaluation: understanding, generation, and the combination. Understanding uses the standard VLM benchmarks covered in Measuring What a VLM Can Do. This section covers the other two.

Distribution metrics

Fréchet Inception Distance (FID) fits a Gaussian to Inception-network features of real images and another to generated images, and measures the distance between them:

FID = ‖ μr − μg ‖² + Tr( Σr + Σg − 2 (Σr Σg)1/2 ) μ and Σ are the mean and covariance of the features. Lower is better. FID measures realism and diversity of a set, not whether any one image matches its prompt.

Papers report it on ImageNet for class-conditional generators, and zero-shot on COCO-30K or MJHQ-30K for text-to-image. CLIPScore measures image-caption agreement with CLIP embeddings. It is cheap but rewards what CLIP notices and misses counting and spatial relations.

Prompt-following benchmarks

GenEval checks object-level facts with a detector: single objects, pairs of objects, counts, colours, positions and attribute binding. DPG-Bench has about 1,000 dense prompts with many objects and relations. T2I-CompBench++ has 8,000 compositional prompts in four groups: attribute binding, relationships, numeracy and complex compositions. WISE has 1,000 prompts across 25 subdomains that require world knowledge, such as cultural common sense or natural science, scored with its WiScore metric. Learned preference models, such as HPSv2 trained on about 798,000 human choices and ImageReward trained on 137,000 expert comparisons, estimate human judgement.

Editing and unified benchmarks

MagicBrush and the Emu Edit benchmark evaluate instruction editing. GEdit-Bench is built from real user requests; BAGEL scores it with GPT-4.1 as judge. ImgEdit-Bench scores instruction adherence, editing quality and detail preservation. For the combination, MME-Unify adds tasks such as commonsense question answering with image generation, and RealUnify tests whether one skill helps the other. BAGEL's IntelligentBench uses 350 examples scored by GPT-4o.

Choosing a design, and what is still open

A short decision guide

  • You have a strong VLM and must not hurt it. Use a bridge with a frozen reader, as in MetaQuery or BLIP3-o. Train generation with flow matching on semantic features or with learnable queries into a diffusion decoder.
  • You want one loop and the LLM toolchain. Use an autoregressive model, but decouple the reading encoder as Janus does, and plan for parallel decoding or a diffusion decoder at the end, as Emu3.5 and X-Omni do.
  • You want the best images per unit of compute and long interleaved context. Use a hybrid with shared attention and modality-specific weights, as LMFusion and BAGEL do. Keep a clean copy of each generated image for later tokens.
  • In every case. Read with a semantic encoder. Recaption training images. Weight losses after checking their normalisation. Evaluate both skills and their combination.

Image token counts also drive serving cost in every design. A 4,096-token image in the context is expensive to read back, not only to write. Post The Cost of a Picture covers that arithmetic.

Open problems

  • Test-time synergy. Models learn faster together but rarely use one skill to perform the other unprompted. RealUnify's gap between end-to-end and stepwise results is the measurement to watch.
  • Representation. No tokenizer yet gives top understanding, top reconstruction and easy generation at once. Unified tokenizers are closing the gap, but most strong systems still use two encoders.
  • Fine detail. Small text, faces and exact layout remain hard at the resolutions most open unified models use. Janus-Pro names 384 × 384 as its limit.
  • Speed. Raster decoding of thousands of tokens is slow. Parallel decoding and few-step flow samplers help, but each changes the training objective.
  • Evaluation. Generation metrics depend on judges, rewriters and caption sources. Benchmarks for interleaved and reasoning-heavy generation are young and small.
  • Provenance and safety. A model that edits real photos convincingly raises misuse risks that text-only models do not. GPT-ImgEval examined how detectable GPT-4o's outputs are by existing forensic models. Watermarking and provenance metadata are part of deployment, not an afterthought.

Key insights and nuances

  • Regression cannot draw. Squared-error regression returns the mean of all valid images. Every working generator needs a sampler, either a softmax over tokens or iterative denoising. (Why an image is hard to output)
  • Image order is a design choice. Text has one natural order; images do not. Raster autoregression, masked decoding, next-scale prediction and diffusion are different answers. (Two ways to generate)
  • The tokenizer caps quality. A discrete model cannot draw what its tokenizer cannot reconstruct; Chameleon names OCR-heavy images as its limit. (Image tokenizers)
  • A pixel tokenizer is a poor reader. In the Janus ablation, reading through a VQ tokenizer cut MMBench from 69.4 to 35.0, while generation barely changed. (What a tokenizer should keep)
  • Generators also want semantics inside. REPA, VA-VAE and Janus run B all show semantic features help generation. Semantic structure in the middle, pixels at the end. (What a tokenizer should keep)
  • Share attention, separate the rest. BAGEL's mixture of transformer experts beat dense and mixture-of-experts layouts at equal compute. (Hybrid models)
  • Hybrids must decide what later tokens see. Noised images make poor context; BAGEL keeps a clean copy. (Hybrid models)
  • Synergy is lopsided and mostly in training. Understanding data makes generation data-efficient; test-time use of one skill for the other is weak. (Synergy or interference)
  • Loss weights correct for counting. Emu3's 0.5 and Transfusion's 5 fix opposite normalisations. (The training recipe)
  • Check GenEval provenance. Prompt rewriting and synthetic captions move scores by several points. (How unified models are evaluated)
