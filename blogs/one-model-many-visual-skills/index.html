From a model that sees to an assistant

A pretrained vision-language model has learned that pixels and words go together. Ask it a question about a receipt and it may continue the caption instead of answering. This post is about the step that fixes that.

Here is the concrete question. We have a model that went through vision-language pretraining. It can describe images in the style of web alt text. We want one assistant with many skills. It should read the text in a photo and answer questions. It should reason over a chart and pull fields out of an invoice. It should point at an object and hold a normal conversation. How do we get there with one set of weights?

The answer has a simple core and many details. The core is supervised fine-tuning on examples of the behaviour we want. The details are where the work is. Skills compete for the same parameters. Formats clash. The language model can forget how to write. The data is often written by another model, with that model's mistakes. This post builds each of these ideas from the ground up.

Two earlier posts on this site cover the language-only versions of these ideas. Teaching a Language Model to Follow Instructions covers supervised fine-tuning (SFT) and loss masking. Mixing Data Without Losing Capabilities covers data mixtures, gradient interference and forgetting. I will reuse their results and focus on what changes when images enter.

Pretraining and post-training

Start with what does not change. Both stages train the same network with the same next-token loss. The difference is the data.

In pretraining, the model sees image-text pairs and interleaved web documents. It learns the joint distribution of images and the text that tends to appear near them. We can write this as Ppretrain(x, I), where I is an image and x is text. The loss covers every text token.

Lpre(θ) = − E(I, x) ∼ Dpre ∑t log pθ(xt | x<t, I) Every text token is a target. The image is context.

In post-training, each example has three parts. There is an image I, an instruction x, and a response y. We now want a conditional distribution: the right response given the image and the instruction. The loss only covers the response.

LSFT(θ) = − E(I, x, y) ∼ Dinst ∑t log pθ(yt | y<t, x, I) Only response tokens are targets. The image and the instruction are context.

The two lines differ in two places. The sum runs over different tokens. The expectation runs over a different distribution. That second difference does almost all the work. A web caption says "sunset over the bay, shot on a 50mm lens". An instruction example says "Q: What time of day is it? A: Evening. The sun is low on the horizon." Same loss. Very different behaviour learned.

This is behaviour cloning, as the SFT post explains. The model imitates the responses in the data. So the data decides the behaviour. Everything in the rest of this post is about which responses to put in that data, in what proportion, written by whom, and in which order.

The first open recipe made this concrete. LLaVA (Liu et al., 2023) took a frozen CLIP encoder and a language model. It first trained only a projection on 595K filtered CC3M image-text pairs. It then trained the projection and the language model on LLaVA-Instruct-158K: 58K conversations, 23K detailed descriptions and 77K complex-reasoning examples. A text-only GPT-4 wrote these from COCO captions and bounding boxes. The model never saw GPT-4 look at an image. The point was that instruction format, not new visual knowledge, was the missing piece.

Insight

Capability and style come from different data. Vision-Flan built 187 human-annotated tasks with 1,664,261 instances. Its authors found that GPT-4-synthesized conversational data "does not substantially enhance VLMs' capabilities but rather modulates the model's responses to human-preferred formats", and that about 1,000 such samples were enough for that effect. In practice: spend most of the budget on task coverage, and a small, clean set of assistant-style data to set the voice.

Anatomy of an instruction example

Before we talk about mixtures, we need to see one example the way the model sees it. A conversation with an image is not a sequence of tokens yet. Three steps turn it into one.

First, a chat template serializes the turns. Special tokens mark where each turn starts and ends, and who is speaking. Qwen2-VL, for example, uses the ChatML format with <|im_start|> and <|im_end|>.

Second, each image becomes a placeholder token such as <image> at the position where the user attached it. The text tokenizer never sees the pixels.

Third, just before the forward pass, each placeholder is replaced by the image's visual tokens. These come from the vision encoder and the connector, as described in Inside a Modern Vision Encoder. In LLaVA-1.5, a 336-pixel image through a ViT-L/14 encoder gives a 24 × 24 grid, so 576 visual tokens. With tiling or native resolution, the count grows with the image size.

Which tokens receive loss

The loss mask mt is 1 on positions we want the model to produce and 0 elsewhere. For a multimodal chat, the rule is short. Assistant tokens get 1. The assistant's end-of-turn token also gets 1, because the model must learn when to stop. Template tokens, user text and every visual token get 0.

L(θ) = − ∑t mt · log pθ(st | s<t) s is the full serialized sequence. mt ∈ {0, 1} selects the assistant tokens.

Visual tokens never get loss in standard SFT. There is nothing to predict there. They are continuous vectors, not entries in the vocabulary. So the image shapes the gradient only through attention: it changes the predicted distribution at the assistant positions.

One consequence is easy to miss. In the example in Figure 1, the sequence has about 1,190 positions. Only 16 of them carry loss. The visual tokens make up almost the whole sequence and cost almost all the compute. Yet the training signal comes from a handful of answer tokens.

Multiple images and multiple turns

With several images, each gets its own placeholder in the order it appears. Some templates number them, as in <image_1> and <image_2>. Others rely on order alone. The text then refers to images by order ("the second chart") or by an explicit label ("Image 2"). The model must learn to bind that reference to the right block of visual tokens. Position encodings that mark image boundaries help here. How Models Know Where They Are covers the multimodal rotary scheme (M-RoPE) used by Qwen2-VL.

Multi-turn conversations are packed into one sequence. Every assistant turn gets loss in the same forward pass. A later turn can depend on an earlier image, so the model learns to keep track of which image a question is about.

Nuance

How the loss is averaged changes the mixture you actually train on. With a per-token average over the batch, a source's share of the gradient signal is its sampling weight times its answer length. Suppose half the examples are one-word VQA answers (about 2 loss tokens) and half are detailed captions (about 150). The VQA half then receives 0.5 × 2 / (0.5 × 2 + 0.5 × 150) ≈ 1.3% of the token-level signal. With a per-example average, it receives 50%. In practice: decide which normalization you use, and state mixture weights in loss tokens as well as examples.

The capabilities we want

"One assistant" hides a long list of skills. Each needs its own data, and some need their own output format. It helps to write the list down before choosing data. Figure 2 walks through it.

Some terms need a short definition.

  • Perception means reporting what is there: recognising objects, their attributes, how many there are, the text written on them (OCR, optical character recognition) and where they sit relative to each other.
  • Visual question answering (VQA) comes in three kinds. Extractive VQA copies the answer from the image, as in reading a sign. Abstractive VQA states something not written anywhere, as in "Is the person happy?" Knowledge-based VQA needs facts outside the image, as in "Which country is this flag from?"
  • Document understanding covers full-page OCR, key-value extraction (pulling "Total: $42.10" into a field), tables, charts, forms, diagrams and question answering over documents. The post How VLMs Read Documents goes deep on this family.
  • Grounding ties words to places: a box, a point or a mask for a referring expression. When Language Must Point covers the output formats.
  • Multi-image and video skills compare images, track change and follow events over time. Seeing in Time covers video.
  • Reasoning chains several of the above, as in reading two bars from a chart and subtracting them.
  • Structured output means answers in a fixed schema: JSON fields, an HTML table, chart data or code from a screenshot.
  • Safety covers refusing harmful requests, protecting privacy, and ignoring instructions written inside an image.
  • Tools and agents means emitting actions: a click on a screen, a crop-and-zoom request or a function call. VLMs That Act covers this family.

Two properties of this list drive the rest of the post. First, the outputs differ a lot in length and form. A count is one token. A detailed caption is two hundred. A box is a few numbers. Second, the skills share almost all their parameters. The same attention heads that read a chart also write a poem. That is why they can help each other, and why they can hurt each other.

The multimodal task mixture

The training set is a mixture of many smaller datasets. In language-only SFT, we index the parts by task and domain. With images, we add a third index: the modality configuration of the input.

D = ∑m, t, d λm,t,d · Dm,t,d , ∑ λ = 1 m: modality configuration (text-only, one image, several images, video). t: task (caption, VQA, OCR, grounding, reasoning). d: domain (natural photos, documents, charts, screenshots, medical images). λ: the sampling weight of each part.

Why is this harder than mixing language-only SFT data? There are four reasons.

The axes multiply. Four modality settings, ten task families and five domains already give two hundred cells. Most cells have little or no data. Some have millions of examples. A naive mixture is dominated by whichever cells happen to be large.

Examples have very different costs. The cost of an example depends on its visual tokens. A high-resolution document tiled into many crops can cost ten times more compute than a low-resolution photo. So "10% of examples" and "10% of compute" are different mixtures.

Examples carry very different amounts of signal. As the nuance above showed, a one-word answer and a two-hundred-token caption contribute very different numbers of loss tokens. So weights in examples, in compute and in loss tokens can all disagree.

Formats conflict. Academic datasets answer in one word. Assistants answer in paragraphs. Grounding data answers in coordinates. The model has to learn when each format applies. The next section shows what goes wrong when it cannot tell.

Cambrian-1 (Tong et al., 2024) is a careful public study of this problem. It collected about 10M instruction examples (Cambrian-10M) and curated them to 7M. One key step was a cap on each source. Very large sources were subsampled so that no single dataset dominated. The authors found the best cap to be between 250K and 350K examples per source. They also found that balancing general, OCR and language data was crucial.

Insight

Capping the largest sources helps more than adding more of them. Cambrian-1's per-source threshold worked best between 250K and 350K examples. Beyond that, extra examples from one source mostly add redundancy and pull the mixture toward that source's format and domain. In practice: cap each dataset first, then tune weights between capability groups.

Apple's MM1.5 study (Zhang et al., 2024) went further. It grouped SFT data into categories: general, text-rich, science, math, code, referring and grounding, multi-image, and text-only. It then measured how each category moves each capability group. Text-rich data improved text-rich and knowledge benchmarks. Science data improved knowledge benchmarks. Referring and grounding data enabled that capability. The final mixture was 80% single-image, 10% multi-image and 10% text-only data.

The mixing post on this site describes the same picture as a transfer matrix. Each row is a capability. Each column is a data source. Each entry says how much a little more of that source moves that capability. Figure 3 lets you play with a small, made-up transfer matrix of this kind.

The toy model is deliberately simple. It still shows the main pattern. Pushing one source up raises its own capabilities quickly at first, then slowly. Meanwhile, everything else loses share. Some losses are mild dilution. Others are real conflicts, which the next section explains.

Negative transfer between visual skills

Negative transfer means that training on task A makes task B worse. The mixing post derives the mechanism from gradients: when the gradients of two tasks point in opposing directions (a negative dot product), a step that helps one hurts the other. See Why tasks interfere. In VLMs, a few specific pairs cause most of the trouble.

Short answers against conversation

This is the classic case. Academic VQA datasets such as VQAv2 and GQA have very short answers: "yes", "2", "red". They are large, clean and cheap. They teach real perception. But if they are mixed into chat data without any marker, the model cannot tell when a short answer is wanted. It learns that answers about images are short. Then a user asks "Describe this photo" and gets "A bus."

LLaVA-1.5 (Liu et al., 2023) named the problem and fixed it with one sentence. InstructBLIP, an earlier model, had an "inability to balance between short- and long-form VQA". The LLaVA-1.5 authors traced this to "ambiguous prompts on the response format" and to not fine-tuning the language model. Their fix was a response-format prompt appended to every short-answer question: "Answer the question using a single word or phrase." Multiple-choice data got "Answer with the option's letter from the given choices directly."

The idea generalises. Molmo (Deitke et al., 2024) prefixes academic questions with a style tag, for example "vqa2:" for VQAv2. In the authors' words, "The model learns to use these styles only when requested." Cambrian-1 saw the same failure, which it called the "answer machine" effect: models "default to outputting short, curt responses". It also fixed it with system prompts.

Insight

The short-answer conflict is a conditioning problem, not a capacity problem. LLaVA-1.5, Molmo and Cambrian-1 each kept large short-answer datasets and recovered long-form behaviour by adding a marker to the input. Once the style is predictable from the input, the two styles stop competing for the same conditional distribution. In practice: give every dataset whose style you do not want by default an explicit marker, and keep the marker at inference when you want that style.

OCR-heavy data against natural-image semantics

Text-rich data (documents, receipts, screenshots) asks the model to copy characters exactly. Natural-image data asks it to name and describe. These pull attention in different directions. A mixture heavy in OCR can make descriptions of photos more literal, for example listing every visible word. A mixture light in OCR leaves the model unable to read. MM1.5's category study is the cleanest public evidence that text-rich data mainly moves text-rich and knowledge benchmarks.

Documents against natural images

Documents need high resolution. A 224-pixel view of an A4 page makes the text unreadable. Photos are fine at low resolution. If both share one image pipeline, one domain is either starved or overpaid. Most modern recipes handle this with tiling or native resolution, as in LLaVA-NeXT's AnyRes grids or Qwen2-VL's dynamic resolution. The trade-off then moves into the token budget, which The Cost of a Picture covers.

Coordinates against fluent language

Grounding data asks for numbers in a strict format. Shikra (Chen et al., 2023) showed that boxes can simply be written as numbers in plain text. Qwen2-VL writes boxes as (x1,y1),(x2,y2) normalised to [0, 1000) between special box tokens. Qwen2.5-VL switched to absolute pixel coordinates of the input image. A large share of such data can leak numbers into ordinary answers, or make the model reluctant to answer without a box. Special tokens around coordinates play the same role as a format prompt: they mark the mode.

Video against images

Video spends its token budget on many frames at low resolution. Images spend it on one frame at high resolution. Training heavily on video can weaken fine detail. Training only on images leaves the model with no sense of time. LLaVA-OneVision's answer was to train single-image skills first and then add a mixed stage with images, multi-image sets and video.

English against other languages

Most instruction data is English. A model tuned on English alone tends to answer in English, and its ability in other languages can drop. The multilingual subsection below gives the evidence and the fix.

Language forgetting

A VLM is built on a language model that already writes, codes, does maths and follows instructions. Multimodal training updates the same weights. So the first question to ask after tuning is simple: how much of that did we lose?

Define the text-capability change as the score on a text-only suite after training, minus the score of the original language model.

ΔStext = Stext(θafter) − Stext(θLLM) Stext: a fixed text-only suite, for example MMLU for knowledge, GSM8K and MATH for maths, HumanEval for code, plus an instruction-following and a safety set. A negative value is forgetting.

Why does forgetting happen? The mixing post gives the general answer in What forgetting actually is. In short, gradient steps on the new data move weights that the old skills relied on, and nothing pulls them back. Multimodal SFT adds a specific pressure. The new data has short, formulaic, image-bound answers. The language model's prior over long, careful text is not exercised at all.

The evidence is consistent across recipes.

  • VILA (Lin et al., 2023) found that "re-blending text-only instruction data" into SFT "not only remedies the degradation of text-only tasks, but also boosts VLM task accuracy."
  • NVLM (Dai et al., 2024) added high-quality text-only SFT data. Its decoder-only 72B model raised the average text score on MMLU, GSM8K, MATH and HumanEval from 79.8 for its Qwen2-72B-Instruct backbone to 84.1. Multimodal training with good text data improved text ability rather than eroding it.
  • Qwen2.5-VL's SFT set has about 2 million entries, split evenly: 50% pure text and 50% multimodal.
  • LLaVA-1.5 included 40K text-only ShareGPT conversations. The authors credit them for an unplanned skill: the model answers in the user's language, "partly due to the multilingual language instructions in ShareGPT".
  • DeepSeek-VL (Lu et al., 2024) kept "at least 70%" language data during joint vision-language pretraining to preserve language ability. Note that this ratio is for pretraining, not SFT.
  • Wings (Zhang et al., 2024) treats text-only forgetting as an architecture problem. It adds small extra learner modules beside the attention layers to counter the drift.

Nuance

Text replay is cheaper than it looks. MM1.5 varied the text-only weight in its SFT mixture from 0 to 0.2 and found it had "minor effects" on multimodal benchmarks. VILA saw multimodal accuracy go up with text replay. So the usual fear, that replay steals capacity from visual skills, is weak at SFT scale. The 70% figure from DeepSeek-VL applies to pretraining. In practice: start SFT with 10% to 50% high-quality text data and measure ΔStext, rather than skipping replay to save budget.

Nuance

Standard benchmarks miss the most important kind of forgetting. Prismatic removed the 40K text-only ShareGPT examples from the LLaVA-1.5 mix. The change "has little impact on benchmarks" but "negatively impacts the safety" of models built on base (non-chat) language models. VLGuard found the same: benign multimodal fine-tuning can erase the language model's safety alignment. In practice: put a refusal and safety suite into the capability vector you track during training.

Vision forgetting

The vision encoder can forget too. If we unfreeze it during instruction tuning, its weights move toward whatever the language model's loss rewards. Does the encoder become less useful as a general visual representation?

There are two separate questions here, and they are often mixed up.

Does the encoder itself get worse? The public evidence is mixed. Prismatic (Karamcheti et al., 2024) found that "finetuning the visual backbone significantly degrades performance", most of all on localisation tasks such as RefCOCO and OCID-Ref. Cambrian-1 found the opposite: "Unfreezing the vision encoder is widely beneficial." ShareGPT4V found that tuning only "the latter half of the vision encoder's layers achieves optimal results" in its pretraining stage. LLaVA-OneVision unfreezes the encoder with a learning rate five times smaller than the language model's.

Nuance

Prismatic and Cambrian-1 disagree on unfreezing the encoder, and the setups explain much of it. Prismatic trained on the LLaVA-1.5 data mix, which is small and contains localisation data that punishes a drifting encoder. Cambrian-1 trained on millions of examples. The recipes that unfreeze successfully also tend to protect the encoder: ShareGPT4V tunes only half its layers, and LLaVA-OneVision uses a 5× lower learning rate. In practice: unfreeze only with enough data, a reduced learning rate, and a grounding benchmark in the evaluation set.

Does the VLM use what the encoder knows? This is a different failure. Fu et al. (2025) compared VLMs with their own vision encoders on vision-centric tasks such as depth estimation and correspondence. The VLMs often did worse than a simple readout of the encoder they were built on. The information was present in the visual tokens. The language model did not use it. Earlier, "Eyes Wide Shut" (Tong et al., 2024) found image pairs that CLIP-style encoders embed almost identically, and showed that VLMs built on them fail on those pairs.

Insight

A VLM that fails a visual question has not necessarily lost the visual information. Fu et al. found VLMs scoring below a readout of their own encoder on vision-centric tasks. The fix for that failure is not a better encoder. It is data or training that makes the language model read the tokens it already has. In practice: before changing the encoder, probe its features directly on the failing task.

How should we measure vision forgetting? A direct test is to freeze the encoder before and after tuning and compare linear probes or nearest-neighbour retrieval on a fixed set of vision tasks. Few VLM papers report this. Most report only end-to-end benchmark scores, which mix up the two questions above.

Where instruction data comes from

We now know what the mixture should cover. The next question is where the examples come from. There are seven main sources. Each has a typical failure.

Human annotation

People write questions and answers, or captions, for real images. This is the most reliable source and the most expensive. Molmo's PixMo-Cap (Deitke et al., 2024) is the best recent example. Annotators described each image aloud for 60 to 90 seconds, which gave dense captions for 712K images. Speaking is faster than typing and harder to shortcut with a model. PixMo-Points added 2D points for 1.98M referring expressions on 229K images.

Benchmark conversion

Many labelled datasets already exist: VQA, captioning, OCR, charts, grounding. Conversion wraps each one in instruction templates. MultiInstruct (Xu et al., 2022) did this early for 62 tasks. InstructBLIP (Dai et al., 2023) converted 26 datasets and held 13 out for zero-shot evaluation. M3IT (Li et al., 2023) collected 40 datasets with 2.4 million instances and 400 hand-written task instructions, with key tasks translated into 80 languages. Vision-Flan grew to 187 tasks. The Cauldron, built for Idefics2, gathered 50 vision-language datasets in one format. Converted data is cheap and correct, but its answers are short and its style is narrow.

A language model writing from annotations

A text-only LLM can turn annotations into rich instructions. LLaVA-Instruct-158K was written by GPT-4 from COCO captions and boxes. SVIT scaled the idea using Visual Genome annotations. PixMo-CapQA generated 214K question-answer pairs from Molmo's own human captions. The LLM never sees the image, so it cannot invent visual details that the annotations lack. It can still invent details that the annotations imply, for example a fork near a plate.

A VLM teacher

A strong multimodal model looks at the image and writes the answer. ShareGPT4V (Chen et al., 2023) collected 100K detailed captions from GPT-4V, trained a captioner on them, and produced 1.2M captions. LVIS-Instruct4V prompted GPT-4V with LVIS images to write about 220K instructions. ALLaVA and LLaVA-Video-178K follow the same pattern. This gives the richest text per dollar. It also copies the teacher's mistakes into the student.

Two findings explain the figure. POPE (Li et al., 2023) showed that "objects that frequently appear in the visual instructions or co-occur with the image objects are obviously prone to be hallucinated." LURE (Zhou et al., 2023) found that "dominant hallucinations occur in the latter part of the descriptions." LRV-Instruction (Liu et al., 2023) showed a related bias: instruction sets built from positive descriptions rarely contain questions whose correct answer is "that is not in the image". Models trained on them learn to say yes.

Insight

Hallucinations in synthetic data are not random noise that averages out. POPE found that hallucinated objects track the objects that are frequent or co-occurring in the instruction data itself. A teacher's co-occurrence bias therefore becomes a systematic bias in the student. In practice: verify object mentions in teacher output against the image (with a detector, a grounding model or human spot checks), and add negative questions whose answer is "not present".

Programmatic tasks

Some tasks can be generated with a known answer. Draw a clock with a chosen time, render a counting scene, or compose a CLEVR-style scene from a program. PixMo-Clocks has 826K synthetic clock examples. The answer is correct by construction, so there is nothing to hallucinate. The risk is a narrow visual style that does not transfer to real photos.

Synthetic documents and charts

Rendering is the scalable path for text-rich skills. Donut's SynthDoG renders synthetic documents for OCR pretraining. PixMo-Docs asked a text-only LLM to write code that renders charts, tables, documents and diagrams, then generated questions from the code. CoSyn (Yang et al., 2025) scaled the same code-guided idea. Docmatix, built for Idefics3, has 2.4 million images and 9.5 million question-answer pairs from 1.3 million PDFs. Because the source data or code is known, answers can be checked exactly.

Execution and verifier filtering

The last source is not new data but a filter on the others. Qwen2.5-VL kept a reasoning example only when the model's output matched the expected answer, a form of rejection sampling. InternVL 2.5 scored text data with an LLM, removed low scores, and ran repetition detection. Its authors found that "merely thousands of examples" with repetitive patterns could make the model "spiral into repetitive loops", especially in chain-of-thought answers.

Nuance

A tiny fraction of bad data can control a visible behaviour. InternVL 2.5 traced repetitive generation loops to a few thousand anomalous samples in a multi-million-example mixture. Aggregate benchmark scores barely move, but users see the loops. In practice: filter for degenerate patterns (repetition, truncation, template leakage) separately from general quality scoring.

Multi-image, video and multilingual data

The sections so far assumed one image and English text. Three extensions need their own data, and each changes the mixture.

Multi-image data

A model trained only on single images often handles two images poorly. It may mix up which question is about which image. LLaVA-NeXT-Interleave (Li et al., 2024) built M4-Instruct to address this: 1,177.6K samples across 14 tasks from 41 datasets. It covers four settings: several images, several video frames, several 3D views, and several patches of one image. Treating all four as "many images in one sequence" lets one model share skills across them. MM1.5 gave multi-image data 10% of its final mixture.

Video data

Video instruction data is expensive to label by hand, so most of it is synthetic. LLaVA-Video-178K (Zhang et al., 2024) is a clear example. GPT-4o described each video at one frame per second in three levels: every 10 seconds, every 30 seconds, and for the whole video. Each level used the earlier descriptions as context. The set has 178,510 videos, 178K captions, 960K open-ended questions and 196K multiple-choice questions. The video post covers frame sampling and token budgets.

LLaVA-OneVision shows how video fits into a mixture. Its final stage, about 1.6M examples, mixed single-image, multi-image and video data after a 3.2M single-image stage. The authors report that skills transfer across these settings. In their words, "strong video understanding and cross-scenario capabilities are demonstrated through task transfer from images to videos."

Multilingual data

Which languages do open VLMs cover, and how? Most recipes are English-first with some Chinese. LLaVA-OneVision's knowledge stage included 92K Chinese captions. InternVL 1.5 trained on a bilingual English and Chinese dataset. Qwen2-VL reports reading text in images in "most European languages, Japanese, Korean, Arabic, Vietnamese, and others."

There are three ways to get non-English data. Translation turns English instructions into other languages, as M3IT did for 80 languages. Native collection gathers images and text from each culture. Text-only replay in many languages keeps the language model's own multilingual ability alive, which is what LLaVA-1.5 saw with ShareGPT.

Pangea (Yue et al., 2024) is the most direct study. It built PangeaIns, about 6M instructions across 39 languages. The first part is English instructions translated with a strong LLM. The second part is about 1M culturally specific images, captioned and questioned in their own language. The third part is existing multilingual datasets. Its ablation on the English share is the clearest public evidence on this question.

Insight

Some English data helps other languages, but too much hurts them. In Pangea's ablation, multilingual performance peaked with 40% English data, and "performance drops sharply when English data reaches 100%." Training on non-English data alone was also weak. English data seems to carry skills that transfer across languages. In practice: keep a large English core for skills, and give at least half the mixture to other languages if multilingual quality matters.

Detailed captions and short answers

Two kinds of data dominate most mixtures: detailed captions and question answering. They look similar. They teach different things.

A detailed caption teaches coverage. To write one, the model must attend to every region of the image and say something true about each. ShareGPT4V's main result was that replacing LLaVA-1.5's 23K detailed descriptions with 23K GPT-4V captions, and pretraining on 1.2M of them, improved a wide range of benchmarks. Molmo's first stage is caption training on PixMo-Cap. The aim in both cases is a model that notices everything.

Question answering teaches selection. To answer "What does the sign say?", the model must find one region, read it, and ignore the rest. It must also stop. A caption-only model tends to answer every question with a description.

There is a cost to long captions. LURE found that hallucinations concentrate late in long descriptions. A model trained to always write more learns to keep going after it runs out of grounded content. So the length of training captions is itself a hyperparameter. Very long captions raise coverage and raise the rate of unsupported claims.

Nuance

Longer captions are not free coverage. LURE's finding that "dominant hallucinations occur in the latter part of the descriptions" means each extra sentence has a higher chance of being false than the one before. Molmo's speech-based captions avoid a teacher model entirely, which removes one source of this. In practice: verify or trim the tail of long synthetic captions, and pair caption data with QA data that rewards stopping.

Reasoning SFT

Some questions cannot be answered in one step. "By how much did revenue grow from Q1 to Q4?" needs two readings and a subtraction. Reasoning SFT trains the model to write the intermediate steps before the answer.

Formally, the response becomes a rationale z = z1 … zk followed by an answer y. The model factorises the joint probability step by step.

pθ(z, y | x, I) = ∏i=1..k pθ(zi | z<i, x, I) · pθ(y | z, x, I) The loss mask now covers both z and y. Each step can attend to the image and to all earlier steps.

Why does this help? Each step is a smaller prediction that the model can get right. And each step is extra computation before the answer. Thinking in Tokens explains why chain-of-thought adds serial compute.

Where do rationales come from? ScienceQA (Lu et al., 2022) collected lectures and explanations for science questions. Multimodal-CoT (Zhang et al., 2023) split generation into two stages, first the rationale and then the answer, so the answer can use a rationale that was built from the image. LLaVA-CoT trained on 100K examples with four explicit stages: summary, visual interpretation, reasoning and conclusion. Visual CoT (Shao et al., 2024) annotated 438K question-answer pairs with a bounding box of the key region, so the reasoning first says where to look. MAmmoTH-VL built 12M instruction pairs with rationales using only open models, with rewriting and self-filtering. Qwen2.5-VL used rejection sampling: keep only rationales whose final answer is correct.

Does the rationale actually use the image?

This question matters because rationales from text-only teachers can be fluent without being visual. MathVerse (Zhang et al., 2024) tested models on versions of maths problems with less text and more diagram. Many models relied "heavily on textual questions". Some scored more than 5% higher with no image at all. On vision-only versions, accuracy fell below the no-image scores.

Insight

A correct rationale is not evidence that the model looked. MathVerse found models that score higher without the diagram than with it. The direct test is counterfactual: change the image in a way that should change the answer, and check that the rationale changes with it. In practice: add image-swap or image-removal checks to reasoning evaluation, and prefer rationales that cite regions, as in Visual CoT, so the check is easy to automate.

Grounded rationales make that check easier. If each step names a region, a verifier can look at the region. My own work on document grounding uses this idea for documents: Building Grounded Document Intelligence describes chain-of-thought where each step is tied to a mask on the page. Reasoning trained by reinforcement learning, where the reward checks the final answer, is the subject of Rewarding What the Model Sees and Thinking With Images.

Staged curriculum or joint mixture

Most open recipes train in stages. A common shape is: align the connector, then train general instructions, then add OCR, documents and high resolution, then reasoning, then grounding and tools. Is this staging necessary, or would one joint mixture do as well?

There are three good reasons to stage.

  • Protect the language model from a random connector. A freshly initialised connector produces meaningless visual tokens. Gradients from them can damage the language model. Training the connector alone first avoids that.
  • Pay for resolution late. High-resolution tiling multiplies visual tokens. Learning basic alignment at low resolution and moving to high resolution later saves compute.
  • End on the target format. The last data a model sees has an outsized effect on its behaviour. Ending on clean assistant-style data sets the final voice.

There is also one good reason not to. Each stage can forget the one before it. A long pipeline of narrow stages is a forgetting machine unless each stage replays the earlier data.

The evidence is split. Prismatic found that the separate alignment stage "can be eliminated without impact on performance, reducing compute costs by 20-25%". Cambrian-1 found that "two-stage training is beneficial; more adapter data further improves results." Molmo keeps a simple two-stage pipeline: caption pretraining, then fine-tuning on a mixture. LLaVA-OneVision uses four stages and argues the single-image stage helps transfer to video.

Nuance

Prismatic and Cambrian-1 disagree on the alignment stage, but they test different amounts of alignment data. Prismatic used the LLaVA-1.5 data mixture, with its 558K-pair alignment set. Cambrian-1's finding comes with "more adapter data further improves results". A small alignment stage adds little. A large one can act as useful extra pretraining. In practice: skip a short alignment stage, but treat a large one as continued pretraining and judge it by its compute cost.

Read across the tabs and a pattern appears. Almost every recipe freezes something at some point. Almost every recipe trains the language model in the final stage. The vision encoder is treated most differently: frozen throughout (LLaVA-1.5), unfrozen gently (LLaVA-OneVision), trained early and frozen late (Qwen2-VL), or adapted with low-rank updates (Idefics3).

A practical rule follows. Stage when the stages differ in what is trainable or in sequence length. Within a stage, use one joint mixture, and replay a slice of earlier data in later stages.

Evaluating while training

With many skills in one model, a single score cannot tell you whether a mixture change helped. We need a vector.

S(λ) = [ SVQA, SOCR, Sdoc, Schart, Sground, Stext, Ssafety ] Each entry is a fixed, held-out suite for one capability group. λ is the mixture. Choosing λ is a multi-objective problem: we want every entry high, and they compete.

When objectives compete, there is usually no single best mixture. There is a set of mixtures where no capability can go up without another going down. This set is the Pareto front. Any mixture below the front is wasted: some other mixture is at least as good on every capability. The mixing post derives this view for language models.

Two ways to pick one point on the front are common. A weighted sum, ∑ wk Sk, picks the point that a chosen set of priorities favours. A constraint picks the best point for one capability subject to floors on others, for example "maximise documents subject to Stext ≥ the base model minus one point". Constraints are easier to defend, because they say what you refuse to lose.

A few practical rules make the vector trustworthy. Benchmarks and metrics have their own post, Measuring What a VLM Can Do, so here I list only what matters during training.

  • Use benchmarks that need the image. Cambrian-1 ran benchmarks with vision disabled. ScienceQA-IMG, MMMU, MathVista and AI2D showed less than a 5% gap between vision on and vision off. MMStar (Chen et al., 2024) was built to remove such questions. A mixture change cannot be judged on a benchmark that ignores the image.
  • Score the format you trained. Short-answer benchmarks need the format prompt. Without it, a well-trained conversational model is marked wrong for being verbose.
  • Track text and safety from the first checkpoint. As the forgetting section showed, these drift silently.
  • Use a shared harness. VLMEvalKit and LMMs-Eval implement many benchmarks with consistent prompts, which makes runs comparable.

Insight

Some popular benchmarks cannot see a mixture change because they barely need the image. Cambrian-1 measured less than a 5% gap between vision enabled and disabled on ScienceQA-IMG, MMMU, MathVista and AI2D. A mixture that improves visual perception may not move them at all, and a mixture that improves text reasoning may look like a visual gain. In practice: make mixture decisions on vision-dependent suites, and read the others as text-reasoning signals.

What is still open

Several questions do not yet have good public answers.

  • Mixture laws for VLM SFT. Language models have early work on predicting capability from mixture weights. For multimodal SFT, most mixtures are still tuned by hand with ablations. How Vision-Language Models Scale covers what is known about scaling.
  • How much synthetic data is too much. Recipes range from no VLM-teacher data (Molmo) to mostly teacher data. There is no controlled study of where student quality starts to fall as the teacher share grows.
  • Encoder health. Few papers report probes of the vision encoder before and after instruction tuning. Without them, vision forgetting and readout failure cannot be separated.
  • Multilingual balance beyond 39 languages. Pangea gives one data point on the English share. How the best share changes with the number of languages and their data sizes is open.
  • Whether staging matters at scale. The disagreement between single-stage and multi-stage results may depend on model size and data size. No public study maps it.
  • Where SFT ends and preference tuning begins. Hallucination is partly a data problem and partly a training-objective problem. The next posts on aligning VLMs and RL for VLMs pick up the objective side.

You should now be able to reason about a multimodal SFT recipe from first principles. Look at the serialized example and its loss mask. Write down the capability vector. Ask what each source teaches, which formats conflict, what replay protects the language model, and which data was written by another model. The next post takes up the evaluation side in depth.

Key insights and nuances

  • Capability and style come from different data. Vision-Flan found GPT-4 conversational data mostly sets the response format; about 1,000 samples were enough. Task coverage builds the skills. (Pretraining and post-training)
  • Loss normalization changes the real mixture. Under per-token averaging, one-word answers can receive about 1% of the signal even at 50% of the examples. (Anatomy)
  • Cap the largest sources. Cambrian-1's best per-source cap was 250K to 350K examples. (Mixture)
  • Format conflicts are fixed by conditioning, not by removing data. Format prompts (LLaVA-1.5), style tags (Molmo) and system prompts (Cambrian-1) let short and long answers coexist. (Negative transfer)
  • Text replay can help both sides. VILA and NVLM saw text ability preserved or improved, with VLM accuracy steady or higher. (Language forgetting)
  • Safety forgetting is invisible to benchmarks. Prismatic and VLGuard found benign multimodal SFT can erode safety while benchmark scores stay flat. (Language forgetting)
  • Unfreezing the encoder needs care, and a VLM can fail while its encoder still knows the answer. Prismatic and Cambrian-1 disagree on unfreezing; Fu et al. found VLMs below their own encoders on vision-centric tasks. (Vision forgetting)
  • Teacher hallucinations are systematic. POPE ties hallucinated objects to frequent and co-occurring objects in instruction data, and LURE finds them late in long captions. (Data sources, Captions and QA)
  • A few thousand bad samples can cause loops. InternVL 2.5 traced repetitive generation to them. (Data sources)
  • Some English helps other languages; all English hurts them. Pangea's best multilingual result used 40% English. (Multilingual data)
  • A correct rationale does not prove the model looked. MathVerse found models scoring higher without the diagram. Use counterfactual images. (Reasoning SFT)
  • Choose benchmarks that need the image. Cambrian-1 found under 5% vision gaps on several popular suites. (Evaluation)
