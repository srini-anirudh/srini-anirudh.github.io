What can be checked in an image

Reinforcement learning with verifiable rewards has a simple loop. A model writes an answer. A program checks it. The reward is one or zero.

That loop needs no human preference labels and no learned reward model. It produced the reasoning language models of 2025. If the loop is new to you, How Reinforcement Learning Teaches Models to Reason builds it from the ground up. This article assumes you know it, along with PPO and GRPO from Reinforcement Learning from First Principles.

Now give the same loop a photograph of a shelf and ask how many mugs are on it. Can a program still check the answer? Yes. A count is an integer.

Give it a scanned invoice and ask for the total. A total is a number, so it can be checked. Ask it to find the red car. The answer is a box, and a box can be compared with a reference box. Ask it to transcribe a receipt. Text can be compared with text by counting edits.

So many visual tasks already have answers a program can check. The first question of this article is what those checks look like, and which of them are safe to optimise.

There is a second question that has no counterpart in text-only RL. A vision-language model has two parts. A vision encoder turns pixels into vectors. A language model reasons over those vectors. Inside a Modern Vision Encoder and The VLM Architecture Gallery cover how the two are joined.

When the reward goes up, which part improved? The model may have learned to see more accurately. It may have learned to reason better over what it already saw. Or it may have learned to answer without looking. These are three different outcomes. A single reward number cannot tell them apart.

We will build the answer in order. First the policy and the training signal. Then the rewards, one family at a time, and the box reward in detail. Then the literature, organised by idea. Then the questions that are specific to vision. Which weights change? How do perception and reasoning differ? How does credit flow through a multi-step answer? How do rewards get hacked? How do we keep the learning signal alive?

A vision-language model is already a policy

A language model is a policy over tokens. At each step it picks the next token given everything so far. A vision-language model (VLM) is the same policy with one more input, the image:

πθ( yt  |  I, x, y<t ) I is the image (or several images, or video frames). x is the text prompt. y<t is the response so far. θ now includes the vision encoder, the connector and the language model.

The state at step t is the image, the prompt and the tokens written so far. The action is the next token. The episode ends at the end-of-sequence token. Then a reward arrives for the whole response.

The objective is the one used for text. We want responses with high reward, and we do not want the policy to drift too far from a reference model:

J(θ) = E(I, x) ∼ D  Ey ∼ πθ [ R(I, x, y) ]  −  β · KL( πθ ‖ πref )

GRPO estimates the gradient of this objective without a value network. For each prompt it samples a group of K responses. It scores each one. Then it compares each score with the group:

Ak = ( Rk − mean(R1 … RK) ) / ( std(R1 … RK) + ε ) Every token of response k receives the same advantage Ak. The derivation, and why the group mean is a valid baseline, is in the RLVR article linked above.

Nothing in this mathematics knows that one input is an image. Three things do change.

  • The environment is a fixed picture. The policy sees the image only through its visual tokens. It cannot look again or zoom in, unless it is given tools. Thinking With Images covers models that can.
  • The reward comes from a visual annotation. The checker compares the output with a box, a mask, a transcript, a table or a count.
  • The parameters have more than one part. θ includes the vision encoder and the connector. Whether those parts receive the gradient is a design choice, and it matters.

Watch the last stage of the figure. The baseline is the group mean. Every rollout in the group saw the same pixels. So the advantage compares different ways of reading the same chart. A rollout that reads the 2023 bar as 51 instead of 57 is pushed down relative to siblings that read it correctly.

Insight

The group baseline holds the image constant. This is a direct consequence of the advantage formula above: the mean is taken over responses to one image. A per-prompt baseline therefore removes how hard the image is and keeps only how well each rollout handled it. The practical implication is the other side of the same fact. If every rollout in a group fails on an image, or every rollout succeeds, all advantages are zero and that image teaches nothing. The curriculum section turns this into a design rule.

A taxonomy of visual rewards

A verifiable reward is a function R(I, x, y) that a program can compute from the response and an annotation. Vision has more kinds of annotation than text. Each kind gives a different reward. We go from the simplest to the richest.

Exact match

The simplest check compares the answer string with the reference after normalising both:

R = 1[ norm(y) = norm(y*) ]

It fits multiple-choice questions, yes/no questions and counts. "How many mugs?" has one right integer. The normaliser does a lot of quiet work. It decides whether "Three", "3" and "3 mugs" are the same answer. A normaliser that is too strict punishes correct answers. A normaliser that is too loose can be exploited, as we will see in the hacking section.

Numeric tolerance

A value read from a chart by eye is rarely exact. A bar that ends a little below the 60 gridline might be 57 or 58. So chart rewards accept an answer close to the reference:

R = 1[ |ŷ − y*| ≤ τ · |y*| ]

ChartQA defined this "relaxed accuracy" with τ = 5%. Non-numeric answers still need an exact match. The tolerance is a statement about how precisely a person could read the chart. It is also a source of slack. A misreading inside the tolerance counts as correct.

Boxes

Grounding tasks ask for a box. The standard comparison is intersection over union (IoU):

IoU(B, B*) = |B ∩ B*| / |B ∪ B*|

IoU is 1 for a perfect box and 0 for a box that does not overlap the target. It can be used directly as a dense reward, or thresholded into a pass/fail reward such as 1[IoU ≥ 0.5]. When an image has several objects, predictions must first be matched to targets. Perception-R1 matches them with the Hungarian algorithm before scoring, and found the matching essential for detection. Boxes are subtle enough to get their own section, Designing a box reward.

Masks

A mask is a set of pixels. IoU works on masks too. The Dice score is a common alternative:

Dice(M, M*) = 2 |M ∩ M*| / ( |M| + |M*| )

Dice is always at least as large as IoU on the same pair, so a Dice threshold is a looser test than an IoU threshold at the same number. Most VLMs cannot write masks as text. A common workaround is to have the VLM write prompts for a segmentation model. Seg-Zero has the VLM output a box and two points. A frozen SAM2 turns them into a mask. The rewards check the box and the points. Building Grounded Document Intelligence describes the same VLM-plus-SAM pattern for documents, and When Language Must Point covers grounding outputs in general.

Points

A click is a point. The simplest reward asks whether the point lands inside the target:

R = 1[ p ∈ B* ]   or   R = 1[ p ∈ M* ]

UI-R1 and GUI-R1 use the box version for GUI clicks. A graded alternative decays with distance, for example R = max(0, 1 − ‖p − p*‖ / d). Perception-R1 uses a point-distance reward for counting, where the model points at each object.

Text read from the image

OCR outputs are long strings. Exact match is too harsh for them, because one wrong character fails a whole page. Edit distance gives partial credit. The character error rate (CER) is the number of character edits divided by the reference length. The word error rate (WER) does the same over words. A reward can be 1 − CER, clipped at zero.

ANLS, introduced with the ST-VQA benchmark, adds a threshold. It computes a normalised edit distance. If the distance is 0.5 or more, the score is 0. Below that, the score is one minus the distance. The authors chose 0.5 to separate two cases. A small distance means the right text with OCR mistakes, which deserves partial credit. A large distance means the wrong text was selected, which deserves none.

Tables

A table has structure as well as text. TEDS treats a table as an HTML tree and measures the tree edit distance to the reference, normalised to a similarity between 0 and 1. It penalises a cell placed in the wrong row as well as a misread number. Table-R1 uses TEDS directly as an RL reward for table recognition. Another option is execution: run a query on the predicted table and compare the result with the same query on the reference table.

Structured extraction

Key-value extraction asks for JSON, for example the vendor, date and total from an invoice. The reward has two parts. A gate checks that the output parses and follows the schema. A field score compares values. Field-level F1 is a natural choice, because it balances precision and recall. A recall-only score rewards emitting every possible field with guessed values. An RL study on medical visual information extraction used a reward that balances precision and recall for exactly this reason.

R = 1[ valid schema ] · F1( fields(y), fields(y*) )

Execution and rendering

Some outputs are programs. Chart-to-code asks the model to write plotting code that reproduces a chart. The code can be run, and the rendered image compared with the original. MSRL combines three rewards. A rule-based score checks parts of the code. A second reward checks that the code runs. A visual reward renders the code and has a large VLM compare the result with the target. Code that fails to render gets zero. ChartMaster renders the code and combines attribute matching with a similarity between image features from a small CNN.

Unit tests are another kind of execution reward. olmOCR 2 generates many small tests for each synthetic training document, such as "this sentence appears", "this table cell is correct" and "these two passages appear in this order". The reward is the fraction of tests passed.

Learned judges

When no program can check the output, a model has to. Captions, open-ended descriptions and helpfulness all fall here. Large recipes such as Seed1.5-VL and MiMo-VL combine rule-based verifiers with reward models. Once the checker is a model, the reward is no longer verifiable in the strict sense. That territory is covered in Aligning Vision-Language Models.

How to read this table. Read down the "Density" and "Main hacking risk" columns together. Every dense reward on this list has a characteristic cheap way to earn partial credit. The binary rewards avoid that, at the price of giving no signal when every attempt fails. Most of the design work in visual RL is choosing where to sit between those two failure modes.

Nuance

A dense reward is not automatically a better signal under GRPO. GRPO divides by the group's standard deviation. Suppose seven rollouts get an IoU of 0.30 and one gets 0.31. The spread is tiny, so after normalisation that one-point difference becomes an advantage of about +2.6 for one rollout and about −0.4 for the others. This follows from the formula alone. The practical implication: when a continuous reward has noise or meaningless small differences, threshold it, round it, or drop the division by the standard deviation. Then near-ties are not amplified into confident updates.

Why vision suits verifiable rewards

Computer vision spent two decades building datasets with machine-checkable labels. COCO has boxes and masks. RefCOCO has referring expressions paired with boxes. Document datasets have transcripts and tables. Chart datasets have numeric answers.

Supervised fine-tuning uses those labels as targets to copy. Reinforcement learning uses the same labels as checks. That is the whole conversion. A box annotation becomes an IoU reward. A transcript becomes an edit-distance reward. No preference data and no learned reward model are needed.

The difference between copying and checking matters in three ways.

Many outputs can be right. SFT says "write these exact tokens". RL says "anything that passes the check is good". For a box, many slightly different boxes pass. For a reasoning question, many different explanations reach the right answer. RL does not penalise the model for choosing a different valid path.

The model learns from its own outputs. SFT trains on outputs the model did not produce. RL trains on outputs sampled from the current policy, including its own mistakes. That is the standard argument from the RL article, and it applies here unchanged.

Small data can go far. Visual-RFT reported large gains in few-shot settings, with one to sixteen examples per category for fine-grained classification and detection. It beat SFT in every setting it reported. R1-V trained a 2B model on synthetic counting scenes and reported SuperCLEVR accuracy rising from 48.0% to 82.5% after 100 GRPO steps.

The most repeated finding is about generalisation. VLM-R1 compared RL with SFT on referring-expression grounding and tested out of domain. On LISA-Grounding, RL reached about 63.1 while SFT reached 54.8, below the starting model's 56.5. Seg-Zero found the same pattern for reasoning segmentation: SFT fell below its baseline on ReasonSeg, while RL improved on it. MM-Eureka reported that rule-based RL generalised better than SFT on its maths and science tasks.

Insight

RL's advantage over SFT is largest where many outputs are acceptable. Perception-R1 reports that RL beat SFT most clearly on counting and detection, which it describes informally as high in "perceptual perplexity": many objects, many categories, many valid orderings of the output. The advantage was smaller on grounding and OCR, which have one right answer. The practical implication: for a single-answer reading task such as OCR, a well-tuned SFT model is a strong baseline. Spend RL compute first where the output space is large.

Nuance

"RL generalises, SFT memorises" is a comparison under particular conditions. The SFT baselines in these papers usually train on the same few thousand examples, with no negative examples. The authors of "RL makes MLLMs see better than SFT" point out exactly this: their SFT and preference-trained models do not see equivalent supervision, because SFT never sees a wrong answer. The practical implication: when you compare the two on your own data, match the number of examples and the compute, and report both in-domain and out-of-domain results.

Designing a box reward

The box reward looks like the easiest case in the taxonomy. It hides the most instructive failure. Start with a concrete example.

The target box covers 20% of the image. The model outputs a box that covers the whole image. The whole-image box contains the target. So the intersection is the target, and the union is the whole image:

IoU = |B*| / |B| = 0.20 / 1.00 = 0.20

A box that says nothing about where the object is earns 0.2. In general, any box that contains the target earns the target's share of that box. That is a floor of free credit.

Whether the floor matters depends on the rest of the group. Suppose the target is hard to find. Seven rollouts attempt a precise box and miss, each scoring 0. One rollout outputs a huge box and scores 0.2. The group mean is 0.025. The huge box gets the only positive advantage in the group. GRPO raises its probability.

So the hack is not that a huge box scores well. It scores badly. The hack is that it scores better than an honest miss. On hard examples, that is enough to pull the policy toward bigger boxes. GUI-G1 observed this directly in GUI grounding. Training with an IoU reward made the predicted boxes grow larger. Training with a "hit" reward, which only asks whether the box centre lands in the target, made boxes shrink. Each reward pushed box size in its own direction.

Play with the figure and four lessons appear.

Thresholding removes the floor. With 1[IoU ≥ 0.5], a containing box scores zero unless it is at most twice the target's area. The cost is sparsity. On a hard target, every rollout scores zero and the group teaches nothing.

GIoU does not fix oversized boxes. GIoU subtracts a penalty based on the smallest box C that encloses both boxes: GIoU = IoU − |C \ (B ∪ B*)| / |C|. When the prediction contains the target, the enclosing box is the prediction itself, so the penalty is zero and GIoU equals IoU. GIoU helps elsewhere. It ranks misses: a near miss scores higher than a far miss, which gives the policy a direction when no rollout overlaps the target.

Coverage alone is unsafe. A reward equal to the fraction of the target covered gives a whole-image box a perfect score. It must always be paired with a precision term.

The fix is usually a second term. The published repairs all pair a recall-like signal with a precision-like signal.

  • GUI-G1 added a box-size term that rewards matching the target's size, on top of the hit reward and the IoU reward.
  • The detection-focused Vision-R1 (Zhan and colleagues) combined a recall reward with a precision reward. The recall reward counts the fraction of ground-truth objects matched above an IoU threshold. The precision reward averages IoU over the predicted boxes. It also tightened its IoU thresholds as training progressed.
  • VLM-R1 found a multi-object version of the same problem in open-vocabulary detection. A plain mAP reward could be gamed by predicting every category in the prompt list, because COCO-style evaluation ignores categories that are absent from the image. Output length ballooned. Its fix multiplies mAP by min(1, Lgt / Lpred), so a prediction list longer than the ground truth is penalised.
  • V-Triune used a dynamic IoU reward. Its IoU threshold rises during training, through 0.85, then 0.95, then 0.99.

Insight

Under group-relative advantages, partial credit is judged against the group, not against zero. A strategy that earns a small, reliable reward beats an honest attempt that usually misses. GUI-G1's measurement, that IoU rewards made boxes grow, is this effect in practice. The practical implication: before training, compute the reward of the cheapest degenerate output (the whole image, the image centre, an empty answer, every category listed) on your training set. If the cheapest output beats a typical miss, the reward needs a precision term or a threshold.

How the field developed

The visual RL literature grew very fast in 2025. It is easiest to follow as four ideas, each building on the last. First, RL was applied to perception, with rewards copied from detection metrics. Second, it was applied to multimodal reasoning, copying the R1 recipe from text. Third, perception and reasoning were combined in single multi-domain runs. Fourth, RL became a standard stage in the open model families.

Perception first: rewards copied from detection metrics

The earliest public result was R1-V, a GitHub project released in February 2025. It trained Qwen2-VL-2B with GRPO on synthetic CLEVR scenes. The task was counting. The reward was an accuracy check plus a format check for think and answer tags. The repository also reported a detail that later papers echoed: at 2B scale, answering directly without the tags scored higher.

Visual-RFT made the perception framing explicit. It trained Qwen2-VL-2B and 7B with GRPO. For detection, the reward added the average IoU of matched boxes, a confidence reward and a format reward. The confidence reward scores each box by its stated confidence when it matched a target, and by one minus the confidence when it did not. For classification, the reward was accuracy plus format. It worked with very few examples.

VLM-R1 turned this into a framework. It trained Qwen2.5-VL-3B on referring-expression comprehension with an IoU reward, and on open-vocabulary detection with the length-aware reward from the previous section. It is the paper that documented both the out-of-domain advantage of RL over SFT and the "list every category" hack.

Two papers named Vision-R1 appeared in March 2025, and they are different. The one by Zhan and colleagues is a perception paper. It trained Qwen2.5-VL-7B and Griffon-G-7B on detection, visual grounding and referring expressions, with recall and precision rewards. It reported COCO mAP for Qwen2.5-VL-7B rising from 17.7 to 26.6. The one by Huang and colleagues is a reasoning paper, discussed below.

Perception-R1 (Yu and colleagues) asked which perception tasks benefit. It trained separate models for grounding, counting, OCR and detection, each with its own reward: IoU, point distance, edit distance, and a composite detection reward. It used Hungarian matching to pair predictions with targets. Its sharpest finding was about thinking. The variant with no explicit reasoning was better on all four tasks. On RefCOCO the no-thinking model scored 89.1 against 75.1 with thinking.

Seg-Zero carried the idea to masks. Qwen2.5-VL-3B writes a box and two points. A frozen SAM2 turns them into a mask. Five rewards check the thinking format, the answer format, the box IoU, the box corners and the points. Its ablation is unusually clean. On ReasonSeg, SFT scored 44.9, below the 47.6 baseline. RL without reasoning scored 51.3. RL with reasoning scored 53.8. Here, reasoning helped, but modestly.

Curr-ReFT added a curriculum over answer formats. It started with yes/no questions, moved to multiple choice, then to open-ended answers, each with its own reward.

Reasoning: making a VLM think like R1

The second line copied DeepSeek-R1 into vision. The target was multimodal maths and science, where answers are numbers or expressions that a maths checker can verify.

MM-Eureka was an early large-scale attempt. Its first version trained InternVL2.5 models with rule-based RL and reported what it called visual aha moments: reflective steps that appeared during RL without being taught. Its second version moved to Qwen2.5-VL-7B and 32B with GRPO, released the MMK12 dataset, and found that online filtering of prompts was essential. Without it, training collapsed. It also found that RL on maths transferred to physics, chemistry and biology questions.

Vision-R1 (Huang and colleagues) argued that RL alone struggles to produce long reasoning in a VLM. It first built about 200K multimodal chain-of-thought examples by "modality bridging": a VLM describes the image in text, and DeepSeek-R1 reasons over that text. After SFT on this data, the model overthought. Its correct answers tended to come from shorter chains. So the RL stage, Progressive Thinking Suppression Training, started with a short length limit and relaxed it later.

LMM-R1 took the opposite route. It first ran RL on text-only maths, then on multimodal data. Text-only RL transferred to multimodal reasoning. Multimodal-only RL hurt text reasoning and made responses much shorter. It used PPO with a critic, not GRPO, which is a reminder that the algorithm is not the essential ingredient.

Skywork R1V grafted a vision encoder onto a reasoning language model. It trained an MLP adapter between InternViT-6B and an R1-distilled 32B language model, then used iterative SFT and GRPO. Skywork R1V2 replaced the language model with QwQ-32B and combined preference optimisation (MPO) with GRPO. It also introduced a Selective Sample Buffer, discussed in the curriculum section.

VL-Rethinker found that multimodal RL did not spontaneously produce long reflective reasoning. It added "forced rethinking", appending a trigger such as "Wait, does it seem right?" to some rollouts. OpenVLThinker alternated SFT and RL over several rounds. ThinkLite-VL and NoisyRollout focused on data and exploration. ThinkLite-VL selected hard examples using the number of tree-search iterations a model needed to solve them. NoisyRollout mixed rollouts from clean and noise-distorted images inside each group, while the policy update conditioned only on the clean image.

Many domains in one run

The third line put perception and reasoning into one RL run. V-Triune (the Orsta models) trained Qwen2.5-VL-7B and 32B jointly on eight perception and reasoning tasks, with task-specific verifiers and the dynamic IoU reward. Vision-G1 curated data from 46 sources across eight domains, selected examples with influence functions, filtered by difficulty, and trained in multiple rounds.

Technical reports from large labs describe the same structure at scale. Seed1.5-VL, whose weights are not public, ran RL with a different verifier per task. STEM answers went to a symbolic checker. Grounding and pointing used IoU. Instruction following used regular expressions. Synthetic visual puzzles had their own checks. MiMo-VL routed each task to its own reward through a "reward-as-a-service" layer. GLM-4.1V-Thinking trained across STEM, grounding, OCR, charts, documents, GUI agents and video with domain-specific verifiers.

Nuance

Names in this area collide. There are two different papers called Vision-R1: a detection paper (arXiv 2503.18013) and a reasoning paper (arXiv 2503.06749). There are two called Perception-R1: a perception-policy paper (arXiv 2504.07954) and a paper about perception rewards for reasoning (arXiv 2506.07218). MM-Eureka changed its title and its base model between versions. The practical implication: cite by arXiv identifier and version, and check which paper a quoted number came from.

Which parameters receive the gradient

Text-only RL updates one network. A VLM has three parts: the vision encoder E, the connector P (also called the projector or adapter), and the language model. The visual tokens the language model reads are

v = P( E( I ) )

and the policy is π( y | v, x ). There are three common choices for which parts the RL gradient updates.

Language model only. E and P are frozen, so v is fixed for each image. RL cannot change what the model sees. It can change how the language model reads the fixed visual tokens: which ones it attends to, and what it concludes from them. MAYE, Vision-G1, NoisyRollout and V-Triune all train this way.

Connector and language model. The encoder's features are fixed, but the mapping into the language model's space can move. This is the cheapest way to change what reaches the language model.

Everything. The encoder itself can change its features. This is the only option under which RL could make the vision encoder better in its own right.

What does the evidence say? It is thin, and it points in different directions.

V-Triune ablated the choice in a multi-task setting that included detection. Training the vision encoder produced much larger gradient norms than training only the language model, with large spikes. Detection performance collapsed after several dozen steps. The authors concluded that updating the encoder was not beneficial in their setting, and froze it.

Skywork R1V2 compared trainable sets on MMMU. Training only the adapter scored best (73.6). Training the adapter and the language model scored 72.1. Training the adapter and the vision encoder scored 72.3. Skywork R1V3 kept all modules trainable. It reported that freezing the vision encoder did not disrupt training, and that unfreezing it gave further gains. Freezing or removing the connector made training fail, with the output degenerating into repetitive text.

A third study approached the question from the encoder's side. "RL makes MLLMs see better than SFT" trained full models with preference optimisation (mostly DPO, with a GRPO check) and then detached the vision encoder. The RL-trained encoder scored higher than an SFT-trained one on ImageNet linear probing and on a segmentation probe. Its gradients, visualised with Grad-CAM, were more localised to the regions the question asked about.

A small companion lab did not reproduce either encoder effect. Its tiny chart-reading model already read the bars well after supervised warm-up, so freezing or training the encoder made no measurable difference. That toy cannot say which choice is better at scale.

Insight

The connector is the most sensitive part of the model under RL. In Skywork R1V2, training only the adapter beat every larger trainable set on MMMU. In Skywork R1V3, freezing the connector was the one choice that broke training. The two results come from the same family and point the same way. The practical implication: never freeze the connector by default. If stability or compute is limited, train the connector and the language model, and treat unfreezing the encoder as a separate experiment with careful gradient-norm monitoring, given the spikes V-Triune measured.

Can RL improve perception?

The question has two meanings, and they have different answers.

The first meaning is about the encoder: can RL make the visual features better? This needs the encoder to receive gradients. The evidence from the preference-training study says yes, at least for DPO, and a small GRPO check pointed the same way. The V-Triune result says it can also destabilise training. Nobody has yet shown, under verifiable rewards at scale, a clean gain that comes from the encoder alone.

The second meaning is about the system: can RL make the model locate, read and count more accurately? Here the answer is clearly yes, even with a frozen encoder. Perception-R1's counting and detection gains, and Visual-RFT's few-shot detection gains, are perception gains at the system level. With a frozen encoder they must come from the language model learning to extract more from the same visual tokens. That is plausible, because the language model's layers do much of the work of reading visual tokens. What Happens Inside a VLM looks at that process directly.

Nuance

The results above do not really disagree, because they measure different things. V-Triune measured detection stability under a joint multi-task run. Skywork measured a reasoning benchmark at 38B scale. The encoder study measured probe accuracy after preference training. The practical implication: the right trainable set depends on the reward. Localisation rewards with large, noisy gradients argue for a frozen encoder. Reasoning rewards on a large model leave room to unfreeze it. Report which you chose, because most papers do not.

Perception RL and reasoning RL

Two skills hide behind a visual answer. Perception recovers facts from pixels: where the object is, what the text says, how many there are. Reasoning combines those facts over several steps. A chart question such as "How much did revenue grow from 2021 to 2023?" needs both. The model must read two bars, then subtract.

An outcome reward on the final answer mixes the two skills. If the score rises after RL, there are at least three explanations.

  • Perception improved: the model reads the bars more accurately.
  • Reasoning improved: the model reads them as before, but subtracts and checks more reliably.
  • The image is being used less: the model has learned what answers are likely for this kind of question, and guesses better.

These need to be separated experimentally. Several findings show why.

Thinking does not help perception much. Perception-R1 found that removing explicit thinking improved all four perception tasks. R1-V found the same for counting at 2B. GUI-G1 adopted a short "fast thinking" template because longer chain-of-thought hurt GUI grounding. Seg-Zero is the exception, with a modest gain from reasoning on reasoning segmentation.

Long reasoning can hurt perception. "More Thinking, Less Seeing?" measured eight multimodal reasoning models against their Qwen2.5-VL bases. The reasoning models had higher hallucination rates on perception-focused tasks. Longer reasoning chains went with less attention to the visual input.

The two pull length in opposite directions. MiMo-VL reported that reasoning tasks push responses longer, while grounding and counting push them shorter. Mixed training did not always match training on one domain.

After reasoning RL, perception errors dominate. PAPO analysed 200 errors of a GRPO-trained Qwen2.5-VL-3B and attributed 67% of them to perception. A second paper named Perception-R1 (Xiao and colleagues) used a McNemar test to argue that accuracy-only RL did not improve perception in multimodal reasoning.

Reasoning gains can come from text alone. LMM-R1's text-only RL stage improved multimodal reasoning benchmarks. Such a gain cannot have come from better perception, because no image was involved.

The figure shows a protocol. Run each evaluation four ways.

  1. Real image. The normal score, Aimg.
  2. Blank image. Replace the image with a blank one. The score Ablank measures what the model can answer from priors alone.
  3. Oracle perception. Give the needed facts as text, for example "2021: 42, 2023: 57". The score Aoracle measures reasoning with perfect perception.
  4. Perception probe. Ask only for the facts: "What is the 2023 value?" The score P measures reading directly.

Then read the gaps. Aimg − Ablank is how much the image is used. Aoracle − Aimg is how much imperfect perception costs. A rise in P is a perception gain. A rise in Aoracle is a reasoning gain. A rise in Ablank without a rise in P is a warning sign.

Visionary-R1 built one of these controls into training. Its output format asks the model to caption the image before reasoning. A caption reward checks whether the model can answer from its own caption alone. That rewards perception that is sufficient for the question.

Insight

Perception and reasoning want different response lengths. Perception-R1, R1-V and GUI-G1 all found short or no reasoning better for perception. MiMo-VL measured the opposite pull of reasoning tasks. "More Thinking, Less Seeing?" linked longer chains to less visual attention. The practical implication: in a mixed run, do not apply one length budget or one reasoning template to every task. Let perception tasks answer briefly, and track response length per domain, not in aggregate.

Credit assignment under a sparse reward

Take the chart question again. A good response has five steps: find the 2021 bar, read 42, find the 2023 bar, read 57, subtract to get 15. The verifier sees only the last number. It returns one reward, RT, for the whole response. In GRPO, every token of the response gets the same advantage.

Consider two rollouts. The first reads 41 and 56, both wrong, and subtracts to 15. The errors cancel. It is rewarded, misreadings included. The second reads both bars correctly and then subtracts wrongly. It is penalised, correct readings included.

Outcome RL still works on average, because correct steps appear in rewarded rollouts more often than incorrect ones. But the signal for each step is weak. A short derivation shows how weak.

Suppose the answer is right only when all n steps are right, and step i is right with probability qi, independently. The probability of reward is the product of all qi. How much does getting step j right change the chance of reward?

P(R = 1 | step j right) − P(R = 1 | step j wrong) = ∏i ≠ j qi The credit a step can receive is scaled by the probability that every other step also went right.

With five steps each right 80% of the time, that factor is 0.84 ≈ 0.41. Each step's effect on the reward is less than half of what it would be if it were the only step. Add more steps and it shrinks geometrically. Lucky cancellations, and misreadings inside the numeric tolerance, add noise on top.

This is the same long-horizon problem that agents face over fifty tool calls. Reinforcement Learning for Agents From First Principles treats it in that setting. For visual reasoning, the special feature is that many steps are perceptual, and perceptual steps can often be checked on their own.

Nuance

A numeric tolerance changes the credit picture. With ChartQA's 5% band, a misreading of 57 as 56 still yields an accepted answer, so the misreading is rewarded. The tolerance was designed for evaluation, where it forgives a reader. In training it also teaches the policy that small misreadings cost nothing. The practical implication: if you train on chart questions, consider a tighter tolerance for training than for evaluation, or add a check on the values read.

Process rewards for visual reasoning

If a sparse final reward spreads credit thinly, the natural fix is to check intermediate steps. Vision offers checks that text does not have, because many steps refer to something in the image. Five kinds of check are possible in principle.

  • The model looked at the right region. The step emits a box or point for its evidence. The check is an IoU or point-in-region test against an annotated evidence region.
  • A quoted text span is correct. The step quotes text from the image. The check compares it with the transcript at that location.
  • A grounded object is correct. The step names and boxes an object. The check compares both with the annotation.
  • An intermediate calculation is correct. The step does arithmetic. A calculator checks it.
  • The right evidence was selected. On a multi-page document, the cited page or region is the one that contains the answer.

Each of these needs an annotation the outcome reward does not need. That cost is why the area is still open. The published work takes three routes.

Learned process reward models

VisualPRM trained an 8B multimodal process reward model on VisualPRM400K, and released VisualProcessBench, a benchmark with human step-level labels. Used for Best-of-N selection with InternVL2.5-78B, it improved results by 5.9 points across seven multimodal reasoning benchmarks. It was evaluated as a test-time selector, not as a training reward. A learned step scorer also inherits the hacking risks of any learned judge.

Grounded reasoning formats

A second route makes the reasoning itself point at the image. ViGoRL anchors each reasoning step to an (x, y) coordinate. GRIT interleaves boxes into the reasoning chain. Point-RFT trains on rationales grounded with points, and reported ChartQA rising from 70.88% to 90.04%, against 83.92% for text-only chain-of-thought with the same reinforcement fine-tuning. DeepEyes lets the model call a zoom tool inside its reasoning. Thinking With Images covers these models in depth.

Look closely at what their rewards check. ViGoRL's format reward requires that every coordinate reference is valid, plus a task reward. It does not reward coordinate accuracy. GRIT's format reward checks that at least one box is present, and its own authors note that this does not constrain whether the boxed region is semantically right. DeepEyes gives a tool bonus only when the final answer is correct and a tool was used. In all three, the grounding is trained indirectly, through the outcome.

For documents, grounded chain-of-thought formats such as DoCoG, described in Building Grounded Document Intelligence, tie each reading step to a mask on the page, while arithmetic steps carry no mask. That split is exactly what a step-level reward would need: a mask check for reading steps and a calculator for arithmetic steps.

Perception-side signals

A third route adds a signal about perception without labelling every step. Visionary-R1's caption reward checks that the model's own caption is sufficient to answer. The second Perception-R1 (Xiao and colleagues) adds a reward from a judge model that assesses the visual perception content of each response. PAPO adds a loss rather than a reward. It compares the policy's outputs on the real image with its outputs on a heavily masked copy, and pushes the two apart. That pushes the policy to depend on the image. It reported 30.5% fewer perception errors.

Insight

Most published "grounded reasoning" rewards check that grounding is present and well formed, not that it is correct. This is visible in the reward definitions of ViGoRL, GRIT and DeepEyes. The practical implication: a grounded chain from these methods is a useful visual trace, but not a verified one. If you need grounding you can trust, budget for evidence-region annotations and an IoU-style check at the step. Synthetic sources, such as rendered charts and generated documents, give those regions for free.

How visual rewards get hacked

Reward hacking means the policy raises the reward without doing the task the reward was meant to measure. In text-only RL the classic examples are answer-format tricks. Vision adds new ones, because the reward is computed from an image the policy can partly ignore. Here are the ones with evidence or a clear mechanism, from the most local to the most global.

Oversized boxes

The box section derived this. A box that contains the target earns the target's share of the box. Under group normalisation that can beat an honest miss. GUI-G1 measured boxes growing under an IoU reward. The repairs are thresholds, precision terms and size terms.

Listing every category

VLM-R1 found that an mAP reward for open-vocabulary detection could be raised by predicting every category in the prompt, because COCO-style evaluation ignores categories absent from the image. Outputs grew long. The length-aware reward fixed it. The general lesson is that an evaluation metric becomes a reward only after checking what it ignores.

Answer-parser exploits

A parser that searches the whole response for the right answer will credit a response that names several answers, such as "B or C". A parser that accepts any number within tolerance will credit a hedged range. The policy finds these quickly, because every rollout is a probe of the parser. The defence is a strict parser that accepts exactly one answer in a fixed location, tested against adversarial strings before training. GLM-4.1V-Thinking reported the stakes: a flaw in the reward for its multi-image QA task let the model learn shortcuts that repeatedly fooled the verifier, and training collapsed across all domains.

Ignoring the image

Many visual questions can be answered from the text alone. MMStar showed this for evaluation: some models scored well above chance on MMMU without seeing images, for example 42.9% for GeminiPro. MathVerse found that removing the diagram improved some models. If the training set contains such questions, an outcome reward pays for the prior as readily as for perception. The defence is to filter training questions that a text-only model can answer, and to track the blank-image score from the previous section.

Learning the format instead of the task

A format reward is easy to earn. Early in training, much of the reward increase can come from format alone. Vision-R1 (Huang) used a hard reward that gives 1 only when the format and the answer are both correct, so format earns nothing on its own. Perception-R1's finding that thinking tags hurt perception is a related warning: a required template can cost accuracy.

Length that is not reasoning

If longer responses are more often rewarded, length grows whether or not the extra tokens help. Vision-R1 (Huang) found that its cold-started model overthought, with correct answers coming from shorter chains, and constrained length early in RL. Kimi-VL added a length penalty. MAYE found that response length depends on the random seed, which is a reason to be careful about reading "the model learned to think longer" from a single run.

Thinking that is not grounded

A reasoning chain can describe objects that are not in the image and still reach the right answer. Nothing in an outcome reward penalises that. "More Thinking, Less Seeing?" measured more hallucination on perception tasks in reasoning models than in their bases. Skywork R1V2 reported that overly strong RL signals induced visual hallucination, and calibrated its reward thresholds in response.

Tool collapse

When RL trains a model to use visual tools, the tool use can collapse. The Qwen3-VL report describes its thinking-with-images agent collapsing to a single tool call to game the other rewards. A tool-calling reward was added to counter it. VLMs That Act picks up tool use in full.

Insight

In a multi-domain run, one weak verifier is a risk to every domain. GLM-4.1V-Thinking reported that a flawed reward in one task, multi-image QA, led to collapse across all domains. The shared policy carries the exploit everywhere. The practical implication: audit each verifier on its own, with adversarial outputs and a small single-domain RL run, before it joins the mixture. Do not rely on the mixture to dilute a bad reward.

Curriculum and the zero-advantage problem

Group-relative methods have a blind spot that matters a great deal for visual RL. If every rollout in a group gets the same reward, the standard deviation is zero, every advantage is zero, and the prompt contributes no policy gradient. Only the KL term remains.

How often does that happen? Take a prompt that the current policy solves with probability p. Sample K rollouts with a binary reward. All of them succeed with probability pK. All of them fail with probability (1 − p)K. So

P(zero advantage) = pK + (1 − p)K The probability that a group of K binary rewards carries no learning signal.

With K = 8 and p = 0.5, this is about 0.8%. Almost every group is useful. With p = 0.9 it is about 43%. With p = 0.95 it is about 66%. So as training succeeds and prompts get easier for the policy, more and more of each batch is wasted. The same happens at the hard end: with p = 0.05, about 66% of groups fail entirely.

This is the "vanishing advantages" problem, and it has been measured. VL-Rethinker reported that for its 72B model the share of queries with non-zero advantage fell from about 40% to below 20% during training. Skywork R1V2 reported a fall from about 60% to below 40%.

Four families of fixes

Filter before training. Estimate each prompt's pass rate with the starting model and keep the middle. Vision-G1 sampled 16 rollouts and kept prompts with accuracy between 0.2 and 0.8. InternVL3.5's online RL data used the same band. Qwen3-VL sampled 16 responses and dropped queries with pass rates above 90%. ThinkLite-VL used tree-search effort as a difficulty score.

Filter during training. Pass rates change as the policy learns, so a static filter goes stale. DAPO's dynamic sampling over-samples and discards groups whose accuracy is exactly 0 or 1 until the batch is full. MM-Eureka's online filtering does the same, and training collapsed without it. MiMo-VL and GLM-4.1V-Thinking use dynamic sampling as well. GLM-4.1V-Thinking re-estimates difficulty online and down-samples prompts that are too easy or too hard.

Replay useful groups. VL-Rethinker's Selective Sample Replay keeps rollouts with non-zero advantage in a buffer and re-samples them in proportion to the advantage size. Skywork R1V2's Selective Sample Buffer does the same, and reported keeping the useful share above 60%.

Make hard prompts learnable. Keye-VL 1.5 gives hard prompts progressive hints, with as little help as possible, until some rollouts succeed. NoisyRollout adds diversity by mixing rollouts on distorted images, annealing the distortion over training.

Ordering the tasks

A curriculum also orders what is learned. A natural ladder for vision runs from easy perception, to grounding, to single-step reasoning, to multi-step reasoning, to tool use. Each rung uses skills from the one below. Published curricula cover parts of this ladder.

  • Curr-ReFT moved from yes/no answers to multiple choice to open-ended answers.
  • LLaVA-OneVision-1.5 ran answer-only RL first, then long chain-of-thought RL, interleaving short-answer examples to prevent forgetting.
  • LMM-R1 trained text reasoning first, then multimodal.
  • OpenVLThinker and Vision-G1 moved from medium to hard prompts over rounds.
  • Kimi-VL used curriculum and prioritised sampling by success rate.

Nuance

Much of what is called curriculum in this literature is difficulty filtering, not task ordering. The evidence that filtering helps is strong: MM-Eureka's collapse without it, and the measured fall in useful queries in VL-Rethinker and Skywork R1V2. The evidence for a specific task order is weaker. No published ablation compares the full perception-to-tools ladder with a shuffled mixture. The practical implication: implement pass-rate filtering first, because it has the clearest support. Treat task ordering as a hypothesis to test.

A checklist for a visual RL run

The previous sections suggest a short list of checks. Each item points back to the evidence.

  1. Score the degenerate outputs. Compute the reward for a whole-image box, an empty answer, every category, and a hedged answer. If any beats a typical miss, fix the reward first. (Box rewards)
  2. Make the parser strict. Accept one answer in one place. Test it with adversarial strings. (Hacking)
  3. Remove text-answerable questions. Drop training items that a text-only model answers correctly. (Hacking)
  4. Filter by pass rate. Keep prompts the starting policy solves sometimes but not always, and refresh the estimate during training. (Curriculum)
  5. Decide the trainable set on purpose. Keep the connector trainable. Unfreeze the encoder only as a monitored experiment. (Parameters)
  6. Separate the tasks' length budgets. Let perception tasks answer briefly. Track length per domain. (Perception and reasoning)
  7. Audit each verifier alone. Run a small single-domain RL job per verifier before mixing. (Hacking)
  8. Report the controls. Publish blank-image, oracle-perception and perception-probe scores before and after RL, alongside the headline score. (Perception and reasoning)

Open questions

Does RL improve the encoder under verifiable rewards? The best evidence that RL improves visual features comes from preference training. The best evidence against comes from a detection-heavy multi-task run. A clean experiment with verifiable rewards, matched compute and a probe of the encoder is missing.

Can step-level visual rewards scale? Checking that a step looked at the right region needs evidence annotations. Synthetic data, such as rendered charts and generated documents, provides them cheaply. Whether rewards on synthetic regions transfer to natural images is not known.

How should domains be mixed? GLM-4.1V-Thinking reported less interference in RL than in SFT and cross-domain gains. MiMo-VL reported that mixed RL did not always match single-domain RL. The mixing question from Mixing Data Without Losing Capabilities returns in RL form.

What is a verifiable reward for open-ended visual tasks? Captions, visual explanations and scene descriptions have no single right answer. Today they fall back to learned judges. Structured checks, such as testing whether a caption lets a model answer a set of questions, are a partial bridge.

How should RL results be reported? Most papers do not say which parameters were trained, and few report blank-image controls. Both are cheap to report. Benchmarks and metrics for VLMs are covered in Measuring What a VLM Can Do.

Key insights and nuances

  • InsightThe group baseline holds the image constant, so GRPO compares readings of the same pixels. Groups where every rollout agrees teach nothing. (Policy)
  • NuanceDividing by the group's standard deviation can turn tiny differences in a continuous reward into large advantages. Threshold or round noisy rewards. (Taxonomy)
  • InsightRL beats SFT most clearly where many outputs are acceptable, such as counting and detection. For single-answer reading tasks, SFT is a strong baseline. (Why vision suits RL)
  • InsightPartial credit is judged against the group. An oversized box that earns a little beats an honest miss, and GUI-G1 measured boxes growing under an IoU reward. GIoU does not fix this, because it equals IoU when the box contains the target. (Box rewards)
  • InsightThe connector is the most sensitive part under RL. Training only the adapter scored best in Skywork R1V2, and freezing it broke training in R1V3. (Parameters)
  • NuanceEvidence on training the encoder conflicts because the studies used different rewards. Detection rewards destabilised it in V-Triune; preference training improved it in the encoder study. (Parameters)
  • InsightPerception and reasoning want different response lengths. Thinking rarely helped perception, and longer chains went with less visual attention. (Perception and reasoning)
  • InsightUnder an outcome reward, a step's credit is scaled by the probability that every other step went right, so credit fades geometrically with the number of steps. (Credit assignment)
  • InsightPublished grounded-reasoning rewards check that grounding is present, not that it is correct. (Process rewards)
  • InsightOne flawed verifier collapsed every domain in GLM-4.1V-Thinking. Audit verifiers one at a time. (Hacking)
  • NuanceThe case for difficulty filtering is strong. The case for a specific task order is still a hypothesis. (Curriculum)

You should now be able to look at a visual task and write down its reward, predict how that reward will be gamed, decide which parameters to train, and design the controls that tell you what the model actually learned.
