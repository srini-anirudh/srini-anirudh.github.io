Saying where, not only what

Show a vision-language model a bank statement and ask: “How much did I pay for electricity in March?” It answers “$84.20”. The answer may well be right. But you cannot tell which number on the page it read. It might have read the March row or the February row. It might have read the amount or the running balance. To check, you have to find the number yourself, and then the model has saved you nothing.

Now ask the model to show its evidence. A useful model highlights the one cell that holds $84.20. You glance at the highlight and see that it sits in the March row, under the Amount column. Checking now takes one second instead of one minute.

That second ability is called grounding. Grounding links a piece of language to a place in the image. The place can be a point, a box, an outline or an exact set of pixels. The language can be a noun (“the mug”), a referring expression (“the mug to the left of the laptop”), an answer, or one step of a longer argument.

This post is about one question. A vision-language model can say what it sees. How does it communicate where it sees it?

The question sounds narrow, but it is not. A language model produces a sequence of tokens. A location is geometry. Every grounding system therefore has to decide how geometry becomes tokens, or how tokens become geometry. That one decision reaches into the tokenizer, the loss, the decoder, the training data, the metrics and the reward. It also limits what kind of evidence the model can show at all. A rectangle cannot follow a curved line of text. A single point cannot cover a table row.

Earlier posts built the pieces we need. One Transformer, Two Modalities showed how an image becomes a sequence of tokens. Inside a Modern Vision Encoder showed how resolution and patch size decide what the model can see. How Models Know Where They Are showed how two-dimensional positions are encoded inside the model, for example with M-RoPE. Those posts move location into the model. Grounding is the other direction. It gets location back out, in a form a person or a program can check.

We will build the topic in order. First we place grounding on a ladder of vision tasks and list the task family. Then we compare four shapes an answer can take: point, box, polygon and mask. Next we look at how coordinates are written as tokens and what that costs. After that comes the main alternative, where the language model hands the location to a dedicated decoder such as SAM. Then come granularity, grounded reasoning, the uses of grounding, and how to measure it. A comparison of models and a short guide to choosing an interface close the post.

From recognising to localising

Vision tasks form a ladder. Each rung asks the model to commit to more about location. It helps to walk up the ladder with one picture and watch what the output gains at each step.

  1. Classification gives one label for the whole image, such as “office desk”. It says nothing about where anything is.
  2. Captioning writes a sentence. Objects now have names, but they still have no positions.
  3. Visual question answering (VQA) answers a question about the image. To answer “What colour is the mug on the left?” the model must find that mug inside its own computation. But the output is still only text, so nobody can see where it looked.
  4. Referring expression comprehension takes a phrase and returns the region it describes. For the first time the location is the output.
  5. Pointing and box grounding return that region as one point or one rectangle.
  6. Segmentation returns the exact pixels of the region.

The step from VQA to referring is the one that matters most. Below it, a location exists only as an internal state. Above it, the location is an output that a person, a program or a reward function can check. Everything in this post lives above that line.

Higher rungs do not replace lower ones. To draw a mask on “the mug left of the laptop” the model must still recognise mugs, laptops and the relation “left of”. Grounding adds a commitment. It does not add a new kind of understanding. That is why grounding is a basic multimodal ability and not a niche detection task. It is the part of perception that can be checked.

Insight

Grounding can be a means, not only an output. Molmo is trained to count by pointing at each instance first and then stating the number. The authors report that this point-then-count chain works clearly better than producing the count alone. The points also make the count checkable: each point is numbered, so the final count is the number on the last point. In practice, when a task requires enumerating things, ask the model to point at each one first. You gain both accuracy and something you can audit.

The family of grounding tasks

“Grounding” covers a family of tasks. They differ in three ways. The language can be the input or the output. There can be one target, many targets or none. The target can be a region in space, a span in time, or both. Here is the family, one task at a time.

Phrase grounding. The input is an image and a sentence. The output is a region for each noun phrase in the sentence. Flickr30k Entities is the standard dataset. It links phrases in Flickr30k captions to boxes in the images.

Referring expression comprehension (REC). The input is one expression that picks out one object, such as “the man in the red shirt on the right”. The output is that object’s box. ReferItGame started this line. RefCOCO, RefCOCO+ and RefCOCOg moved it onto COCO images. RefCOCO+ forbids location words, so the expression must use appearance. RefCOCOg has longer expressions.

Referring expression segmentation (RES). This is the same task with a mask as the output. Classic RES assumes that every expression matches exactly one object. GRES and its dataset gRefCOCO drop that assumption. Their expressions can match several objects, or no object at all.

Referring expression generation (REG). This is the inverse of REC. The input is a region and the output is text that describes it well enough to pick it out. Shikra and Ferret accept regions as input, so a user can point at something and ask about it. Ferret accepts free-form regions such as points, boxes and scribbles.

Grounded VQA and grounded captioning. The model writes an answer or a caption and attaches a region to the phrases it mentions. GLaMM calls the caption version grounded conversation generation. In it, every phrase in a multi-sentence reply gets its own mask.

Reasoning segmentation. The query names no object directly. LISA introduced this task with its ReasonSeg benchmark. A query might be “the part of the kitchen you would use to boil water”. The model has to reason its way to the kettle and then segment it.

Open-vocabulary detection. The input is one or more category names in free text. The output is a box for every instance of each category. MDETR, GLIP, OWL-ViT and Grounding DINO are the specialist models here. Unlike REC, the number of outputs is not known in advance.

Text grounding. Here the regions are pieces of text: characters, words or lines. Text spotting finds and reads text with its location. Region-specific OCR inverts it: “read what is written inside this box”. Kosmos-2.5 writes each text line of a page together with its box.

Document grounding. A question about a page is answered together with the regions that support the answer. The evidence is often a cell, a row, a paragraph, or several scattered places. BoundingDocs, DOGR-Bench and MMDocBench measure this. The next post, How VLMs Read Documents, covers document models in depth.

Chart-element grounding. The targets are parts of a chart: a bar, a pie wedge, a legend entry, an axis label. These shapes are often not rectangles, and they are tied to each other. A legend colour, for example, tells you which wedge to read.

GUI grounding. The input is a screenshot and an instruction such as “open the settings”. The output is a point to click. SeeClick introduced the ScreenSpot benchmark for this task. VLMs That Act covers it further.

Temporal and spatio-temporal grounding. In video, the target can be a time interval (“when does the person open the fridge?”). Charades-STA, built in the TALL paper, is a standard benchmark for this. The target can also be a mask that follows an object across frames, as in Sa2VA. Seeing in Time covers video.

Nuance

Classic REC data contains no expression that matches nothing. A model trained only on it learns that some box is always the right answer. Ask it for “the giraffe” in a kitchen photo and it will draw a confident box anyway. This is a grounding hallucination that comes straight from the data format. GRES added no-target expressions for exactly this case. Ferret’s GRIT data includes about 95K hard negatives, and Molmo’s pointing data includes “not present” examples. In practice, any grounding training mix should contain queries whose correct answer is “there is no such region”.

Point, box, polygon, mask

Before we ask how a model writes a location, we need to decide what kind of location it writes. There are four common shapes. Each one trades precision against cost.

A point is two numbers, (x, y). It is the cheapest answer to annotate: one click. It says “here” but not “how big”. That is enough for clicking a button, counting objects, or telling a robot where to grasp. It is checked with an inside test: does the point fall inside the target?

A box is four numbers, (x1, y1, x2, y2). It adds extent. It is the default of object detection, cheap to draw, and easy to compare with intersection over union. Its weakness is shape. A box always includes the background between the object and the box edges.

A polygon is a list of k vertices, so it costs 2k numbers. It can follow an outline as closely as you like, if you are willing to pay for more vertices. Florence-2 writes polygons as sequences of quantised vertices. PolyFormer predicts them one vertex at a time.

A mask marks every pixel as in or out. It can represent anything: holes, thin curves, and several disconnected parts at once. Masks used to be the most expensive annotation by far. The Segment Anything Model (SAM) changed that. An annotator clicks once or twice and SAM fills in the mask. That is how SAM’s own SA-1B dataset reached over a billion masks on 11 million images.

The cleanest way to compare boxes and masks is to ask a simple question. Suppose a model predicts the best possible box. How good is that box as a description of the region? Let S be the true region and B* its tightest enclosing box. Because S lies inside B*, their intersection is S itself and their union is B*. So:

Best-box quality equals fill ratioIoU(B*, S) = |B* ∩ S| / |B* ∪ S| = |S| / |B*| = f(S)

Here f(S) is the fraction of the box that the region fills. For a full rectangle, f = 1. For an ellipse, f = π/4 ≈ 0.79, because an ellipse fills that share of its bounding box. For a curved line of text, like the one in Figure 2, the figure is about 0.34. For a thin text line at 45 degrees it can fall below 0.1. Even a perfect box can therefore mostly describe background.

Figure 2 also shows a trap with points. The obvious point to emit is the centre of mass of the region. For a convex object such as a ball, the centroid lies inside the object. For a curved band, a crescent or a ring, it lies outside. A model that learns to point at centroids will point at background for exactly these shapes. Pointing datasets therefore ask annotators to click on the object, not at its centre.

Writing coordinates as tokens

Suppose the model must output a box. A language model can only emit tokens, so the box has to become tokens somehow. Here is the same box around a dog, written the way eight different systems write it. The box spans 26.8% to 58.4% of the image width and 37.2% to 81.1% of its height.

How to read this table. The rows look different, but they make only four choices. The choices are text numbers or new tokens, normalised or absolute, how many bins, and which axis comes first. The rest of this section takes the four choices one at a time.

Text numbers or new location tokens

The first choice is whether a coordinate is ordinary text or a new token. Shikra, Qwen-VL, CogVLM, MiniGPT-v2, Ferret and Molmo all write coordinates as ordinary text. Nothing is added to the vocabulary. The model reuses whatever it already knows about numbers, and the output stays readable by a person and parseable by a regular expression.

The cost is length. Many tokenizers split numbers into single digits. LLaMA’s tokenizer does this, for example. Then “584” is three tokens, and a box with brackets and commas runs to roughly twenty. Each digit is also a separate prediction, which matters for the error analysis in the next section.

The alternative is to add location tokens to the vocabulary. Pix2Seq did this first for detection. It cut each coordinate into a fixed number of bins and gave each bin a token. Those tokens share one vocabulary and one embedding matrix with the class labels. OFA carried the idea into a general vision-language model. Its official training scripts use 1,000 bins. Kosmos-2 split a 224-pixel input into a 32 × 32 grid of cells. That gives 1,024 location tokens, one per cell. A box is two of them: the top-left cell and the bottom-right cell. Florence-2 uses 1,000 bins per coordinate. PaliGemma uses 1,024 tokens named <loc0000> to <loc1023>.

Location tokens make a box short: two tokens in Kosmos-2 and four in PaliGemma. Each coordinate becomes one decision instead of three. But the embeddings of these new tokens start from nothing. The model has to learn from grounding data alone that <loc0500> lies between <loc0499> and <loc0501>. Text digits come with some of that order already learned during language pretraining.

Normalised or absolute coordinates

The second choice is the frame of reference. Most systems normalise coordinates by the image size. Shikra uses [0, 1]. Qwen-VL and Qwen2-VL use [0, 1000). MiniGPT-v2 uses 0–100, and so does Molmo for points. Gemini’s documented detection format is also normalised to 0–1000. A normalised box means the same thing at any resolution, so data from many image sizes can be mixed freely.

Qwen2.5-VL broke with this. Its report says it uses coordinates based on the actual size of the input image, for both boxes and points. The argument is that a model which sees images at their native resolution should also learn real scale. The catch is the word “actual”. These are pixels of the resized input that the model receives, not of the original file. The official cookbook rescales outputs using the resized width and height. One model generation later, Qwen3-VL went back. Its report states that, unlike Qwen2.5-VL, it uses a normalised system scaled to [0, 1000].

Nuance

Two models of the same family can write the same box with different numbers. Qwen2.5-VL writes pixels of its resized input. Qwen3-VL writes positions on a 0–1000 grid. PaliGemma, Gemini and Pix2Seq put y before x, while most others put x first. A parser that assumes the wrong convention still produces valid-looking boxes. They are simply in the wrong place, and nothing raises an error. In practice, treat the coordinate convention as part of the model’s interface. Pin the model version, write a test that draws a known box, and never reuse a parser across model families without checking it.

How many bins: the cost of a coordinate grid

The third choice is the number of bins, N. It sets how finely a coordinate can be stated. The arithmetic is short, and it is worth deriving. Take an image that is W pixels wide. Cut each axis into N bins, so each bin is Δ = W / N pixels wide. If a coordinate is rounded to the nearest bin centre, each edge of a box can be off by at most Δ/2.

What does that do to IoU in the worst case? Take a square object of side s. The worst case is when all four edges move inward by Δ/2. Then the predicted box is a square of side s − Δ that sits inside the true box. Its IoU is the ratio of the two areas. (A brute-force check over every combination of edge errors confirms that this is the minimum.)

Worst-case IoU from quantisation aloneIoUmin = ( (s − Δ) / s )2,   where   Δ = W / N

Two facts follow. First, the error is set by the original image width, not by the resolution the model sees. A 0–1000 grid on a 448-pixel image has bins narrower than a pixel. The same grid on a 3840-pixel screenshot has bins almost four pixels wide. Second, small objects suffer most, because Δ is compared with s. Kosmos-2’s 32-cell grid is fine for a dog that fills half the photo. On a full-page scan 2,000 pixels wide, each cell is 62 pixels, wider than most words on the page. Try it in Figure 4.

Insight

Bin count is a resolution budget, and it is spent in pixels of the original image. Take MiniGPT-v2’s 0–100 grid on a 3840-pixel 4K screenshot. Each bin is 38.4 pixels wide, so an edge can be off by up to 19.2 pixels. For a 24-pixel icon that error is larger than half the icon. Even a perfect model on this grid could click outside the icon. On a 1000-bin grid the bin is 3.8 pixels, and the worst-case IoU for the same icon is about 0.71. In practice, size the grid for the smallest target at the largest image you will serve. Do not size it for the training resolution.

Which axis first, and other conventions

The fourth choice looks trivial: the order of the numbers. Pix2Seq writes [ymin, xmin, ymax, xmax]. PaliGemma and Gemini keep that order. Qwen-VL, Shikra, Ferret and Florence-2 put x first. Kosmos-2 needs only two tokens, because each token already names a cell. A model trained on mixed conventions has to learn the convention from context. A pipeline that mixes conventions will fail silently, as the nuance above warned.

Points need one more convention: which point. A point for a button is its centre. A point for a curved object must be a point on the object, as Figure 2 showed. Molmo writes several points in a fixed order, top to bottom and then left to right. We return to ordering in the next section.

Grounding as next-token prediction

Once a box is a string of tokens, grounding becomes ordinary language modelling. The model reads the image and the question. Then it writes something like <box> 123 084 622 531 </box>, one token at a time. Training is the same cross-entropy loss used for every other token. This idea runs from Pix2Seq through OFA, Kosmos-2, Shikra, Qwen-VL, Florence-2 and PaliGemma to most open models today.

What this buys

  • One interface for every task. Detection, referring, grounded captioning and VQA all become “write the right tokens”. A single model can be trained on all of them with one loss.
  • No extra decoder. The architecture is the plain vision-language model described in The VLM Architecture Gallery. Nothing new has to be served.
  • Text and location mix freely. A box can sit in the middle of a sentence, a list or a JSON object.
  • The output is easy to check. A regular expression extracts the box, so a program can compute IoU. That is what makes grounding usable as a reward for reinforcement learning.

What it costs

The costs are less obvious. Each one comes from treating a quantity in space as a sequence of symbols.

The loss is blind to distance. Cross-entropy for one coordinate token is −log p(true bin). It depends only on the probability given to the correct bin. It does not care where the rest of the probability went. Missing by one bin and missing by three hundred bins cost exactly the same. Figure 5 shows this with two predictions that have identical loss and very different boxes.

Errors compound digit by digit. With text digits, one coordinate is several predictions in a row. The hundreds digit comes first, and every later digit is conditioned on it. An early mistake is large, and the following digits cannot repair it. Location tokens remove the chain, because each coordinate becomes one decision. They do not remove the blindness to distance.

Many objects need an order. A set of boxes has no natural order, but a token sequence does. Pix2Seq shuffles the object order during training, so the model learns that any order is acceptable. Molmo goes the other way and writes points in a fixed reading order, top to bottom and then left to right. A fixed order is easier to learn. But one skipped object then shifts the position of everything after it. Evaluation has to match predicted and true regions as sets, not as sequences.

Shapes beyond boxes get long. A polygon with 30 vertices is 60 numbers, which can mean more than 200 tokens as text. PolyFormer avoids quantisation altogether by predicting vertex coordinates as continuous values with a regression head. Masks are worse still as raw text. PaliGemma compresses a mask into 16 tokens drawn from a learned codebook of 128 entries, which a small decoder expands back into pixels. Text4Seg labels each cell of a 16 × 16 patch grid with a word and then compresses each row with run-length coding. That compression shortens the text by 74%.

Nothing anchors the numbers to the pixels. A coordinate token is predicted like any other word. The model can write a fluent, well-formed box for an object that is not there, just as it can write a fluent sentence that is false. Aligning Vision-Language Models covers hallucination in general. In grounding it takes the form of a confident box on empty background.

Insight

Supervised fine-tuning and IoU rewards teach different things about coordinates. Cross-entropy rewards only the exact bin. An IoU reward gives partial credit that grows smoothly as the box gets closer. VLM-R1 uses the IoU between the predicted and the true box directly as the reward for referring expression comprehension. Its authors report that the RL-trained model generalises better than a supervised baseline. Visual-RFT uses an IoU-based reward for detection. In practice, once a model writes parseable boxes, RL with an IoU reward is a cheap way to add the sense of distance that cross-entropy lacks. The post Rewarding What the Model Sees develops this.

Nuance

An IoU reward is only as good as its definition. VLM-R1 reports reward hacking in object detection. A policy rewarded for matched boxes can find ways to raise the score that are not better detection. Seg-Zero avoids a continuous IoU reward. It gives a binary reward when IoU exceeds 0.5 and another binary reward for small coordinate error. In practice, check what a grounding reward can be gamed by, such as many boxes, huge boxes or empty answers, before trusting a rising reward curve.

Handing the location to a decoder

Typing coordinates asks a language model to do geometry in text. There is another option. The language model can decide what to localise and leave where to a module built for it. Three interfaces follow from this. The model can type the location, select it from candidates, or emit an embedding that a decoder turns into a location.

Type, select or decode

Type. This is the approach of the previous section. The model writes coordinates as tokens. It is simple and portable, and it carries all the costs listed above.

Select. A separate detector proposes candidate regions. Each candidate becomes a token that the language model can refer to. Groma works this way. A class-agnostic proposer based on Deformable DETR finds candidate regions. A region encoder turns each one into a region token, registered as <r1> to <rn>. The language model grounds a phrase by writing <p>A dog</p> <roi><r4></roi>. Localisation becomes a choice among candidates. The model never writes a coordinate. The ceiling is the proposer: a region that was never proposed can never be selected.

Ferret uses region features in the other direction, for input. Its hybrid region representation pairs a region’s discrete coordinates with a continuous feature. A spatial-aware visual sampler extracts that feature from inside the region, whatever its shape. That lets a user refer to a scribble or a free-form outline. Ferret’s outputs are still coordinates written as text, on a 0–999 grid.

Decode. The model emits a special token, and that token’s hidden state, not its text, carries the location. LISA introduced this as “embedding as mask”. The recipe has four steps:

  1. Add a token <SEG> to the vocabulary. The language model writes it where a mask is needed: “It is the kettle <SEG>.”
  2. Take that token’s last-layer hidden state, hSEG.
  3. Project it with a small MLP into the prompt space of SAM’s mask decoder.
  4. SAM’s decoder combines this prompt with SAM’s own image features and outputs a mask.
Embedding as maskp = MLP(hSEG),    M = DecSAM(Fimg, p),    L = Ltext + λbceLbce(M, M*) + λdiceLdice(M, M*)

The mask losses compare the predicted mask M with the true mask M* pixel by pixel. Because every step is differentiable, the mask loss flows back through the decoder and the MLP into the language model. The language model therefore learns to put into hSEG exactly what the decoder needs. No coordinate is ever typed.

The VLM + SAM family

LISA showed that this design gives reasoning segmentation almost for free. The reasoning comes from the language model and the mask comes from SAM. Trained only on data without reasoning queries, LISA still handles reasoning segmentation zero-shot. Its authors report that fine-tuning on just 239 reasoning-segmentation samples improves it further. Many follow-ups change one part of the recipe each.

  • GLaMM adds a region encoder for region inputs and a SAM-based grounding encoder and pixel decoder for outputs. It writes multi-sentence replies in which every phrase carries its own <SEG> mask. Its GranD dataset was built by an automatic annotation pipeline. It holds 810M regions with masks on 11M images, along with 84M referring expressions and 33M grounded captions.
  • PixelLM drops SAM. It uses a lightweight pixel decoder and a learned segmentation codebook, which keeps the cost down and handles several targets in one reply. It was trained with MUSE, a set of 246K question-answer pairs covering 0.9M instances.
  • OMG-LLaVA uses a frozen universal segmenter, OMG-Seg, as both the visual encoder and the mask decoder. One encoder, one decoder and one language model handle image-level, object-level and pixel-level tasks.
  • Sa2VA joins SAM 2 to an InternVL-style model. A [SEG] token prompts SAM 2, and SAM 2’s memory carries the mask across video frames. The same model grounds images and videos.
  • NExT-Chat calls the idea pix2emb. Location embeddings are decoded into boxes by one decoder and into masks by another. VisionLLM v2 generalises it into a “super link” that routes embeddings to many task decoders. LLaVA-Grounding attaches a grounding model to a LLaVA-style chat model and introduces Grounding-Bench.

One hybrid sits between typing and decoding. Seg-Zero lets Qwen2.5-VL-3B write a box and points as text. A frozen SAM 2 then uses them as prompts and draws the mask. The language model is trained with reinforcement learning, with rewards on the box and the points. The output stays parseable text, and the mask still comes from a segmenter.

Grounding documents with masks

My own research applies the decode interface to documents. The framing behind it is simple. A person shows you where something is by pointing, underlining or highlighting. Nobody reads out coordinates. A single point works well in natural images, where the evidence is usually one object. Evidence in a document rarely looks like that. It is a paragraph, a table row, a line of text curving around a seal, a pie wedge, or several cells scattered across a page. For regions like these people reach for a highlighter. A mask is a smart highlighter. It covers exactly the evidence, at any shape and size, and nothing else.

Three models from this line of work share one recipe. A vision-language model writes text and grounding tokens, and SAM turns each token into a mask, trained end to end. M3Grounder (CVPR 2026) answers document questions and attaches masks to every cited span. Each grounding token yields three nested masks: the phrase, its line and its block. DoCoG (ECCV 2026) grounds every reading step of a chain of thought. DocLayout-VL (ECCV 2026) emits a layout token for every node of a page’s layout tree. The full story, with the data engines behind them, is in Building Grounded Document Intelligence.

Insight

For irregular and multi-region evidence, the interface matters more than more data. All three of these papers use the same 8B backbone, which makes the comparison clean. On DocLayout-VL’s hierarchical track, the backbone writing boxes as text reaches 32.5 open mIoU. Adding SAM as the segmenter lifts it to 58.3. A module that lets layout tokens follow the tree adds another 11 points, and structure-aware losses take it to 77.5. On M3Grounder’s benchmark, the same backbone fine-tuned on the same data reaches 60.6 grounding F1. The full model reaches 79.0. In practice, if the targets are not boxes, change the output interface before scaling the data.

Nuance

A decoder is not free. It adds a second image encoder or a large decoder to serve. M3Grounder reports about 63 ms of grounding overhead per sample. The output is also no longer plain text. A mask cannot be returned inside a JSON string without an encoding. It cannot be scored by a reward function that only parses text, and it cannot be produced by a closed API model that only emits tokens. Several regions also need several grounding tokens, each with enough information to separate them. In practice, choose decoding when the shape and the number of regions matter. Choose typed coordinates when portability and simple rewards matter more.

What counts as one region

So far each query has had one obvious target. Real queries often do not. Look at a single bank statement and three requests about it. “Cite the amount” wants one number. “Redact the transaction” wants the whole row. “Chunk the table for retrieval” wants the whole table. The page is the same in all three. Only the question changed, and with it the right size of region.

This is granularity: the level at which a region is defined. On a document the levels form a ladder of their own:

  • character and word,
  • span (a phrase or a number with its unit),
  • line and paragraph (also called a block),
  • table cell, row, column and whole table,
  • chart element: a bar, a wedge, a legend entry, an axis label,
  • figure, section and page region.

Natural images have their own ladder: part, object, group of objects, and amorphous regions such as sky or road. A question about the handle of a mug wants a part. A question about “all the mugs” wants a group. That group may be several disconnected regions, which is the multi-target case of gRefCOCO.

Several systems build granularity into the output. Kosmos-2.5 reads a page as a list of text lines, each with its own box, so its unit is the line. M3Grounder makes granularity explicit. Each grounding token has three small heads, which produce three SAM prompts. Those prompts become three nested masks for the phrase, the line and the block. A hierarchy loss keeps the phrase mask inside the line mask, and the line mask inside the block mask. DocLayout-VL goes further and outputs a whole tree of regions. Its attention module lets each region token look only at its parent, its children and its siblings. A headline therefore stays with its own article.

Multi-region answers need a separate mention. A query such as “which months were over budget?” can point at three cells in three rows. A point list handles this naturally, and so does a list of masks. One box around all three cells would cover most of the table. This is the plainest case where the answer is a set of regions, not one region.

Insight

Granularity belongs to the question, not to the image. The same pixels are the right answer at one granularity and a wrong answer at another. M3Grounder’s three nested masks exist because one citation is used in three ways downstream. Citing a value needs the phrase. Redacting it needs the row. Chunking the page for retrieval needs the block. In practice, decide which granularity each downstream use needs, and make the model emit it explicitly. Nested outputs are one way to serve several uses at once.

Nuance

Benchmarks usually annotate one granularity. A model that returns the correct line, when the label is a word inside that line, gets a low IoU and counts as wrong. Its evidence was correct. It was simply coarser than the label. Low scores on document grounding benchmarks can therefore mix two failures: wrong evidence and mismatched granularity. In practice, before comparing models on such a benchmark, check whether their output unit matches the annotation unit.

Grounding each reasoning step

Some questions cannot be answered by pointing at one place. Take a pie chart of revenue by region and ask: “By how many points does Asia’s share exceed Europe’s?” The answer, 24 points, is printed nowhere. The model must find Asia in the legend, then find the wedge with that colour, then read its label, and then do the same for Europe. Only then can it subtract. Grounding only the final answer gives nothing to point at. Chain-of-thought alone says “Asia is 42%” without showing which label it read.

The fix is to ground the steps. Step 1 points at region A. Step 2 points at region B. Each later reading step points at its own region, up to the answer. Steps that only do arithmetic point at nothing. Thinking in Tokens explains why written reasoning steps help a language model. Grounded steps add one thing: each reading step becomes checkable against the image.

Three lines of work show the range of designs.

Visual CoT builds a dataset of 438K question-answer pairs, each with a box around the key region. About 98K of them also have detailed reasoning steps. The model first predicts the box, then looks again at that region, and then answers. Here grounding is a step that decides where to look, which is the theme of Thinking With Images.

GRIT (Fan and colleagues, 2025) trains a model to interleave boxes inside its reasoning text. It uses reinforcement learning with only two rewards: a correct final answer and a well-formed grounded reasoning format. The paper reports that as few as 20 training samples are enough to learn the behaviour. (This GRIT is a method. Ferret’s dataset is also called GRIT, and Kosmos-2’s dataset is called GrIT. They are three different things.)

DoCoG, from my own work, grounds every reading step of a document chain with masks across text, tables, charts and flowcharts. It adds a module that sees all grounding tokens of one chain together before they reach SAM. That lets related pointers agree, such as a legend entry and its wedge, or a value and its column. The language model is causal: when it writes the first pointer, it cannot yet see the second, so it cannot make them agree itself. Training starts with supervised fine-tuning on step-wise data and continues with preference training over whole chains.

Nuance

Boxes inside a chain of thought are not automatically evidence. GRIT’s rewards check only the final answer and the format. No reward checks whether a box covers the right region. Those boxes show where the model chose to look. Nothing guarantees that they mark the correct evidence. In practice, when a paper reports grounded reasoning, find out whether the regions were supervised or scored. If not, measure their accuracy separately before using them as citations.

Insight

Answer accuracy and grounding accuracy can come apart completely. On DoCoG-Bench, Gemini 3 Pro scores 84.2 on answer quality but 11.4 on grounding. DoCoG scores 85.8 on answers and 81.9 on grounding. A model can reach the right answer and still be unable to show where it read it. In practice, never use answer accuracy as a proxy for grounding. If you need evidence, evaluate the evidence.

Why grounding matters beyond explanation

Grounding is often presented as explainability: the model shows its work. That is true, but it undersells it. A location is also an input to the next step, whether that step is taken by a program, a robot or a training loop. Here are the main uses, each with what it needs from the representation.

Verifiable perception. A grounded claim can be checked in seconds, and an ungrounded one cannot. This is the bank-statement example from the start. It needs regions at the right granularity. A box around a whole table does not verify a number.

Region-specific reading. “Read the text inside this box” turns grounding into a tool for OCR. Kosmos-2.5 reads a page as text lines paired with their boxes. The location tells you where each piece of text came from. It also lets later steps read one region again at higher resolution.

Crop and zoom. A box is an action as well as an answer. A model that can name a small region can crop it, zoom in, and look again with more visual tokens. Visual CoT trains exactly this. Thinking With Images covers how reasoning models use it at test time.

Clicking in interfaces. A GUI agent acts by clicking points. SeeClick showed that GUI grounding is the bottleneck for visual GUI agents and built ScreenSpot to measure it. ScreenSpot has over 600 screenshots and about 1,200 instructions across mobile, desktop and web. UGround scaled the training data to 10M GUI elements on 1.3M screenshots. Here precision is measured in pixels of a large screen, so the grid arithmetic of Figure 4 applies directly. See VLMs That Act.

Robotics. A robot needs a target in the image: where to grasp, where to place, where to go. RoboPoint predicts sets of image points as spatial affordances. The Molmo authors expect pointing to let models act by pointing at waypoints, objects and buttons. From VLMs to VLAs picks this up.

Rewards for reinforcement learning. A box or a mask can be scored against a reference with IoU, without a learned judge. That makes perception a verifiable reward, much like a math answer checked by a program. VLM-R1, Visual-RFT and Seg-Zero all use this. Rewarding What the Model Sees covers the method.

Visual citations. A document assistant that cites the cell it read can be audited by its users. This is the strongest argument for mask-level, multi-region grounding on documents. How VLMs Read Documents and Searching With Pixels cover documents and visual retrieval.

Less hallucination. A model that must place every object it mentions has a harder time mentioning objects that are not there. Ferret’s authors report that training with GRIT, including its hard negatives, reduces object hallucination. The mechanism matters more than the size of the effect. Grounding turns “is there a dog?” into “where is the dog?”, and “nowhere” must be a valid answer.

Insight

One output shape serves many consumers. A point is a click for a GUI agent, a grasp target for a robot, a count marker for Molmo, and a prompt for SAM in Seg-Zero. A box is a crop for a zoom step and a scorable answer for an RL reward. In practice, a reliable grounding head is reusable infrastructure. Teaching a model to point well pays off in agents, robotics and training at once. Each use differs only in what consumes the point.

Measuring grounding

Each output shape comes with its own metric, and each metric rewards something slightly different. Measuring What a VLM Can Do covers VLM benchmarks in general. This section goes deeper on grounding.

Points

A point is scored with an inside test. The pointing game, introduced to evaluate attention maps, counts a hit when the maximum of the map falls on an annotated instance, allowing a tolerance of 15 pixels. GUI grounding uses the same idea as click accuracy: a click counts if it lands inside the target element’s box. Point metrics say nothing about extent, and they are lenient for large targets.

Boxes

Boxes are scored with intersection over union, IoU = |A ∩ B| / |A ∪ B|. Referring expression comprehension on the RefCOCO family reports Acc@0.5: the share of expressions whose predicted box has IoU of at least 0.5 with the true box. Phrase grounding on Flickr30k Entities reports a similar recall at the same threshold. Detection reports average precision. In the COCO style, AP is averaged over IoU thresholds from 0.5 to 0.95, which rewards tight boxes more than Acc@0.5 does.

Masks

Masks are also scored with IoU, but at the pixel level, and there are two ways to average it. Referring segmentation papers such as LISA report both.

Two averages of mask IoUgIoU = (1/n) ∑i |Pi ∩ Gi| / |Pi ∪ Gi|     cIoU = ∑i |Pi ∩ Gi| / ∑i |Pi ∪ Gi|

Here Pi is the predicted mask and Gi the true mask for example i. gIoU is the mean of per-example IoUs, so every example counts equally. cIoU adds up all intersections and all unions before dividing. Large objects contribute many pixels, so they dominate cIoU. LISA prefers gIoU for exactly this reason. IoU over a whole mask is also forgiving at the edges, because a large interior hides a ragged boundary. Boundary IoU computes IoU only in a thin band around the contours, so it rewards sharp edges.

Nuance

“gIoU” means two unrelated things. In referring segmentation it is the per-example mean IoU defined above. In detection, “GIoU” is generalised IoU from Rezatofighi and colleagues. That is a loss and metric for boxes that adds a penalty based on the smallest box enclosing both. The two numbers are not comparable. In practice, when a paper reports gIoU, check which definition it uses before putting the number in a table next to another paper’s.

Many regions, no region, and phrases

When an answer has several regions, a single IoU no longer works. The usual approach is to match predicted regions to true regions first, typically one-to-one at an IoU threshold. Then precision, recall and F1 are computed over the matches. M3Grounder and DoCoG report grounding scores of this matched kind. When a query may have no target, as in gRefCOCO, the metric must also reward the model for correctly answering “nothing”. Grounded captioning has to score two things together: the text and whether each phrase got the right mask. GLaMM therefore evaluates grounded conversation generation with caption metrics and mask metrics side by side.

Time

Temporal grounding uses the same idea in one dimension. Temporal IoU compares the predicted interval with the true interval. Charades-STA results are usually reported as recall at temporal IoU thresholds such as 0.5 and 0.7.

Choosing a grounding interface

There is no single best interface. The right choice follows from the shape of the evidence, the number of regions, and what consumes the output.

  • The target is a small, compact object, and the consumer clicks, counts or grasps. Use points as text. They are cheap to label and cheap to emit, and they are checked by an inside test. Make sure the points are trained to land on the object, not at its centroid.
  • The consumer crops, zooms or computes a reward. Use boxes as text on a normalised grid. Check that the grid is fine enough for the smallest target at the largest resolution you serve. If the boxes will be scored, consider RL with an IoU reward after supervised training.
  • The evidence is irregular, nested or spread over several places. Use masks from a decoder. Typed polygons and masks get long and lossy. A grounding token that prompts a segmenter keeps the language model’s job to deciding what and at which granularity.
  • The answer needs several reading steps. Ground each reading step, and leave arithmetic steps ungrounded. Measure the regions directly, because a correct answer says little about whether they are right.
  • The input is video. Use a segmenter with memory across frames, such as SAM 2 in Sa2VA, or interval outputs for purely temporal questions.
  • The model is behind an API that only returns text. Typed coordinates are the only option. Pin the version and test the coordinate convention, as the nuance on coordinate frames advised.

The thread through all of this is a division of labour. Language models are good at deciding what a question refers to and at what granularity. Geometry is better handled by something that works in pixels, whether that is a fine coordinate grid, a proposer, or a promptable segmenter. The next posts build on this. How VLMs Read Documents applies grounding to pages. Rewarding What the Model Sees turns IoU into a training signal.

Key insights and nuances

  1. InsightGrounding can be a means as well as an output. Molmo’s point-then-count beats counting directly, and the points make the count checkable. From recognising to localising
  2. NuanceData in which every query has exactly one target teaches the model to always draw a box. Training needs queries whose answer is “no such region”. The family of grounding tasks
  3. InsightThe best possible box has IoU equal to the shape’s fill ratio. That is about 0.34 for a curved text line and below 0.1 for a thin diagonal one. Point, box, polygon, mask
  4. InsightQuantisation error is set by the original image width divided by the bin count. A 0–100 grid cannot localise a 24-pixel icon on a 4K screen. Writing coordinates as tokens
  5. NuanceCoordinate conventions change across models and even across versions of one family. Qwen2.5-VL uses absolute pixels, while Qwen3-VL returned to a 0–1000 grid. Wrong parsers fail silently. Writing coordinates as tokens
  6. InsightCross-entropy cannot tell a near miss from a far miss. IoU rewards can, which is why RL helps grounding. Grounding as next-token prediction
  7. InsightFor irregular, multi-region evidence, changing the interface from typed boxes to a segmentation decoder helps more than more data on the same backbone. Handing the location to a decoder
  8. InsightGranularity belongs to the question. The same pixels are right for “cite” and wrong for “redact”. What counts as one region
  9. NuanceBoxes inside reasoning chains are not evidence unless something checks them. Answer accuracy and grounding accuracy can differ by 70 points. Grounding each reasoning step
  10. Nuance“gIoU” means a per-example mean in segmentation and generalised IoU in detection. cIoU favours large objects. Measuring grounding
