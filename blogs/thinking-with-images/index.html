The question

Show a reasoning vision-language model a street photo and ask when the bakery closes. The model encodes the image once. Then it writes five thousand tokens of reasoning.

The reasoning is careful. It notes that the shop is a bakery. It recalls that bakeries often close in the early evening. It considers the light in the sky and the parked cars. It concludes that the bakery closes at 18:00.

The answer is wrong. The opening hours were printed on a small plaque in the top-right corner of the photo. The plaque said 9:00–17:30.

So here is the question this post answers. If a model looks at an image once and then generates 5,000 reasoning tokens, is it really doing visual reasoning?

The short answer is: only as far as the first look allows. Reasoning tokens can rearrange, combine and check what the image encoding kept. They cannot add what the encoding threw away. When the missing piece is a pixel-level detail, the fix is not more thinking. The fix is looking again.

That idea organises the whole post. We first split a visual answer into a perception stage and a reasoning stage. We show how to find out which stage failed. We then sort multimodal reasoning into three forms and trace how the field moved through them. After that, we prove the limit on what reasoning can recover, and we look at evidence that long reasoning can pull a model away from the image.

The second half treats perception as something you can spend compute on at test time. We add perception and tools to the usual test-time compute axes. Then we cover active perception, search over image regions, visual verification, overthinking, and visual tools used as reasoning steps. The post ends with a comparison of the main methods.

This post extends two earlier posts on language models. Thinking in Tokens explains chain of thought as serial compute. How Models Improve Without Changing Their Weights covers test-time scaling: sampling, search, verification and budget allocation. We reuse their results and do not re-derive them. For how pixels become tokens, see Inside a Modern Vision Encoder. For the reinforcement learning that trains most of these models, see Rewarding What the Model Sees.

Perception and reasoning are separate stages

Start with the simplest reasoning VLM. It does three things in order.

First, it turns the image into visual tokens. An encoder E reads the image I after it has been resized or tiled by some resolution policy ρ. The result is a sequence of vectors zv.

Second, the language model writes reasoning tokens r1, …, rT. Each one is conditioned on the visual tokens, the question q, and the reasoning so far.

Third, it writes the answer y.

zv = Eρ(I) rt ∼ pθ( · | zv, q, r<t),   t = 1, …, T y ∼ pθ( · | zv, q, r1:T) The image enters once, through zv. Everything after that is computed from zv, the question, and the model's own text.

This pipeline has one structural property that matters for the rest of the post. The image I is touched exactly once. After the encoder runs, the model never sees pixels again. It only sees zv.

Three ways the answer can fail

A visual answer can go wrong in three distinct places. It helps to name them precisely, because each one has a different fix.

The information was never extracted. The fact needed for the answer is not in zv. In the bakery example, the plaque text is under four pixels tall after the photo is resized for the encoder. The resize already blurred the letters together. No later step can read them.

The information was extracted but not used. The fact is in zv, but the reasoning does not consult it. The model writes "bakeries usually close at 18:00" from its language prior instead of reading the plaque it encoded. This failure is common and easy to miss, because the trace looks reasonable.

The reasoning failed. The model read the plaque correctly as 9:00–17:30. Then it reported the opening time instead of the closing time. Or, in a chart question, it read every bar correctly and then made an arithmetic slip.

We can write the accuracy of the model as a product of three probabilities. Let X be the event that zv contains the needed fact. Let U be the event that the reasoning uses it. Let R be the event that the reasoning steps are correct.

P(correct) ≈ P(X) · P(U | X) · P(R | X, U) + P(lucky guess | otherwise) Perception sets P(X). Attention to the evidence sets P(U | X). Reasoning sets P(R | X, U). The last term is what language priors earn without the image.

This is an approximation, not an identity. Partial information and partial use blur the three events. But it is the right mental model. Each method in this post raises one of the three factors. Some methods raise one factor while lowering another.

Insight

The factorisation says which kind of compute can help. Reasoning tokens act on P(R | X, U) and, through prompting, on P(U | X). They have no path to P(X), as the data processing inequality below shows. So before buying a larger thinking budget for a visual task, measure whether the needed facts reach the visual tokens at all.

Why the first failure is special

The three failures are not equally fixable. The second and third failures happen after the information is inside the model. Better reasoning, better training or more reasoning tokens can, in principle, fix them.

The first failure is different. Information theory gives a hard limit here. The true answer Y* is a property of the image. The visual tokens are computed from the image. The reasoning and the answer are computed from the visual tokens, the question and independent sampling noise. These variables form a chain.

Y* ← I → zv → (r, y)  given q 𝕀(Y*; y | q) ≤ 𝕀(Y*; zv | q) ≤ 𝕀(Y*; I | q) This is the data processing inequality. Processing cannot create information about Y* that its input did not contain. Here 𝕀 is mutual information.

The model's weights do carry knowledge. But that knowledge is the same for every photo. It can tell the model that bakeries often close around six. It cannot tell the model what this particular plaque says. Only zv carries information about this particular image.

We return to this limit with numbers in a later section. First, we need a way to tell the three failures apart in practice.

Finding the stage that failed

A wrong answer does not tell you which stage failed. A good trace does not prove that perception worked either. You need probes: controlled changes to the input or the pipeline that switch one stage on or off.

Each probe below changes one thing and watches what happens to accuracy. Probes work on sets of examples, not single cases. One example can mislead. A few hundred examples give a clear signal.

The blind probe

Remove the image and ask the same question. If accuracy barely drops, the item does not test vision. The model answers from the question text and its prior.

This sounds like a formality, but it is not. The MMStar authors found that many items in popular benchmarks can be answered without the image. In their study, GeminiPro scored 42.9% on MMMU with no visual input at all. MathVerse makes the same point for diagram math. It rewrites each problem into versions that move information from the text into the diagram. Models that do well when the text states the key facts often drop sharply when the facts live only in the diagram. Measuring What a VLM Can Do covers these benchmark issues in depth.

Nuance

A benchmark score mixes perception with language priors. In the MMStar study, GeminiPro reached 42.9% on MMMU with no image at all. A reasoning model that improves on such a benchmark may have improved only its priors. Report the blind baseline next to any claimed gain in visual reasoning.

The oracle perception swap

Replace the image with a perfect text description of the facts the question needs. For the bakery, that is the line "a plaque in the top-right reads OPEN 9:00–17:30". Keep the same model and the same question.

If the model now answers correctly, the original failure was perceptual. It was failure 1 or failure 2. If the model still fails with perfect facts in hand, the failure is in reasoning.

One caveat matters. The oracle description must state the facts, not the answer. "The bakery closes at 17:30" turns the probe into a reading test.

Caption, then reason

Ask the model to describe what it sees, with the question in mind. Then give only that description to a reasoner, either the same model or a stronger text model, and ask the question.

This splits perception from reasoning using the model's own perception. The Prism framework formalises this. A VLM writes a question-aware description. A separate language model answers from the description alone. Prism uses the split to score perception and reasoning separately, and it finds that a small VLM paired with a strong text reasoner can match much larger VLMs on some benchmarks.

The diagnostic value is in the comparison. Suppose the caption contains "9:00–17:30" but the direct answer was 18:00. Then the fact was extracted and then ignored. That is failure 2. Suppose the caption has no hours at all. Then the fact was probably never extracted. That points to failure 1.

Captions are lossy. A caption can miss a fact the visual tokens do contain. So a missing fact in the caption is evidence for failure 1, not proof.

The crop probe

Crop the region that holds the answer and ask again. A crop of a small region, resized to the same encoder input size, shows that region at a much higher effective resolution.

If the crop fixes the answer, the original failure was resolution-limited perception. That is failure 1 in its most common form. Zhang and colleagues ran this intervention systematically. They showed that VLM accuracy depends strongly on the size of the visual subject, and that the effect is causal: enlarging the subject fixes answers. They also found that the models' attention often lands on the right region even when the answer is wrong. The models know where to look. They cannot read what is there at the given resolution.

Insight

A wrong answer about a small detail is usually not a localisation failure. Zhang and colleagues found that model attention lands on the right region even when the answer is wrong, and that enlarging the subject fixes the answer causally. The model knows where to look and cannot read what is there. In practice, a training-free crop guided by the model's own attention is the first fix to try, before any retraining.

The representation probe

Train a small linear classifier on the visual tokens to predict the needed fact. If a linear probe can read the fact from zv, the information was extracted. If the model's answer is still wrong, the language model failed to use it.

The "VLMs are blind" study used this probe on simple geometry tasks: counting line intersections, checking whether two circles overlap, naming the circled letter. Strong VLMs did poorly. Yet linear probes on the vision encoder features solved the tasks. The information was there. The language model did not decode it. That is a clean case of failure 2. What Happens Inside a VLM covers the interpretability tools behind probes like this one.

The mid-trace image ablation

Let the model reason halfway. Then remove the image and let it finish. If accuracy barely changes, the second half of the reasoning was not using the image.

The Take-along Visual Conditioning (TVC) authors ran exactly this test on a long-reasoning VLM. They truncated reasoning midway and re-completed it with the image removed. Accuracy on the MathVista test-hard subset dropped by only about 2%. Later reasoning was driven by the model's own text, not by the picture. We return to this in the section on drift.

Three forms of multimodal reasoning

Now that perception and reasoning are separate in our minds, we can sort reasoning VLMs by one question: when and how does the model get visual information? The answer gives three forms.

Form 1: textual reasoning over static visual tokens

The image is encoded once. All reasoning happens in visible text. This is the pipeline from the previous section, and it describes most reasoning VLMs: LLaVA-CoT, QVQ, Kimi-VL-Thinking, GLM-4.1V-Thinking, and the thinking modes of general VLMs.

Perception happens once, before any reasoning. The model can re-attend to zv at every reasoning step. It cannot change zv.

Form 2: interleaved perception and reasoning

The model reasons for a while. Then it takes a visual action: it outputs a box to crop, a zoom, a rotation, or a tool call. The environment runs the action on the original image and returns new visual tokens. The model reads them and continues.

ak = crop(bk)  ⟶  z(k) = Eρ( crop(I, bk) )  ⟶  context ← context ⊕ z(k) The crop goes back to the original pixels, not to zv. That is what lets this form recover detail the first look lost.

This is what OpenAI called "thinking with images" when it released o3 and o4-mini. It also describes V*, Visual CoT, DeepEyes, Chain-of-Focus, and the tool-using mode of Qwen3-VL.

Perception is spread through the reasoning. The model looks, reasons, decides where to look next, and looks again.

Form 3: latent multimodal reasoning

Some intermediate steps are not text at all. They are hidden states, or special visual tokens, that the model writes and then reads back. Coconut does this for text-only models: it feeds the last hidden state back as the next input instead of decoding a word. Thinking in Tokens covers it.

The multimodal versions write visual latents. Mirage trains a VLM to emit "latent visual tokens", first supervised against real image embeddings, then refined with text supervision and RL. Latent Visual Reasoning (LVR) trains the model to generate hidden states that reconstruct the visual tokens most relevant to the question. Perception Tokens, from the AURORA work, let the model write a depth map or box layout as discrete tokens and reason over them.

A close relative generates explicit images as thoughts. Multimodal Visualization-of-Thought (MVoT) and Visual Planning generate pictures of intermediate states, for example a maze after each move. Models That See and Draw covers the models that can generate images natively.

One point is easy to miss. Most latent methods still compute their visual latents from zv. They re-represent what the first look kept. They can make it easier to use. They cannot recover pixels the first look discarded, unless they also re-encode the image.

Nuance

Latent reasoning helps, but on the "used" factor rather than the "extracted" one. LVR reports 71.67% on MMVP against 66.67% for Qwen2.5-VL, and MMVP tests patterns the encoder often does carry but the model fails to use. That fits the derivation: latents computed from zv can raise P(U | X) but not P(X). Expect latent methods to help on fine-grained visual patterns, and expect no help on detail that resizing already removed.

How multimodal chain of thought developed

The field moved through the three forms roughly in order. Each step answered a limitation of the one before. This section follows that thread, organised by idea.

Rationales as supervision

ScienceQA (2022) is the starting point. It collected about 21,000 multimodal science questions, each annotated with a lecture and an explanation. The authors trained models to write the explanation as a chain of thought before answering. Chain of thought improved few-shot GPT-3 by 1.20 points and a fine-tuned UnifiedQA model by 3.99 points. The early lesson: rationales help, but the models of the time saw the image only through a caption.

Multimodal-CoT (2023) split the task into two stages. A first model generates a rationale from the text and image features together. A second stage infers the answer from that rationale. With under one billion parameters it reached the best ScienceQA result at the time. The authors reported that feeding vision features into rationale generation reduced hallucinated rationales. That is an early sign of failure 2: without good access to the image, the rationale invents visual facts.

Grounded steps

The next idea was to make a step point at the image. Visual CoT (2024) built a dataset of 438,000 question-answer pairs, each annotated with a bounding box around the key region. About 98,000 pairs also have reasoning steps. The model first predicts the box, then the region is cropped and re-encoded, and then it answers. Chain-of-Spot (2024) did the same for LLaVA-1.5: find the region of interest, re-encode it, answer. Both are early Form 2 systems, though they take a single fixed look.

Structured long reasoning through supervised fine-tuning

After OpenAI's o1, the goal became long, structured reasoning. LLaVA-CoT trained a VLM to write four explicit stages: a summary of the problem, a caption of the relevant visual content, logical reasoning, and a conclusion. It used 100,000 training samples. It also added a stage-level search at test time, called SWIRES, that samples and retraces at the level of stages rather than tokens. Notice the caption stage. It is a built-in caption-then-reason step.

Insight-V generated long reasoning data with a pipeline and split the work between a reasoning agent and a summary agent, refined with iterative DPO. Mulberry used a collective Monte Carlo tree search across several models to find reasoning paths, and built the Mulberry-260k dataset from them. LlamaV-o1 trained with a curriculum and introduced a step-level reasoning benchmark.

Borrowing reasoning from text

A surprising result came next. Virgo fine-tuned a VLM on a small amount of text-only long-thought data. That was enough to give it slow-thinking behaviour on multimodal problems. The authors found that text reasoning data could be even more effective than visual reasoning data for this purpose. Their reading: slow thinking lives mostly in the language model.

Several pipelines then made the conversion explicit. R1-Onevision turns each image into a formal text description and reasons over that. Vision-R1 built a 200,000-example cold-start set by describing images in detail and letting a text reasoning model write the chain of thought. These recipes work well on math and science benchmarks. They also make the dependence on Form 1 explicit: perception is reduced to text before reasoning starts.

Insight

Slow thinking appears to live in the language model. Virgo showed that text-only long-thought data was enough to give a VLM slow-thinking behaviour on multimodal problems, and possibly more effective than visual reasoning data. Several popular recipes also convert the image to text before reasoning. So a gain on multimodal math benchmarks says little about perception. Evaluate perception separately from reasoning when you compare reasoning VLMs.

Reinforcement learning with verifiable rewards

Next came reinforcement learning on problems with checkable answers. Kimi k1.5 trained a multimodal model with large-scale RL and reported 74.9 on MathVista. MM-Eureka applied rule-based RL to a curated multimodal math set. Vision-R1 combined its cold start with GRPO and a schedule that suppresses overlong thinking early in training. The algorithms and reward design are the subject of the previous post, Rewarding What the Model Sees.

Looking again, as a trained skill

In April 2025, OpenAI described o3 and o4-mini as able to "think with images". The models can crop, zoom and rotate an input image inside their chain of thought. OpenAI reported 95.7% on V*Bench, a benchmark of small details in high-resolution images. It also listed limitations: reasoning chains that are too long with redundant image operations, perception errors even when the tool use is correct, and inconsistent behaviour across repeated attempts.

Open replications followed within weeks. DeepEyes, Chain-of-Focus, Pixel Reasoner, GRIT, ViGoRL, Mini-o3 and ACTIVE-o3 all train a model to choose regions and re-inspect them, mostly with RL. We cover them in the active perception section.

Tools and imagined images

A parallel line treats image edits as thoughts. VisProg and ViperGPT (2022–2023) had a language model write a program that calls vision modules. Visual Sketchpad (2024) let a model draw lines, boxes and marks on the image and look at the result. VTool-R1, OpenThinkIMG and Thyme (2025) train models with RL to use image-editing code. MVoT, Visual Planning and Mirage push towards models that imagine visual states instead of only editing real ones. We cover this line in the section on visual tools.

What the reasoning VLMs actually do

Before we derive limits, it helps to be concrete about the models people use. This section applies the survey checklist from the series to the main reasoning VLMs. It covers only what matters for reasoning. How the Open VLM Families Were Built covers each family in full.

QVQ-72B-Preview (Qwen, December 2024) is an experimental open-weight visual reasoning model built on Qwen2-VL-72B. The release post lists its limits plainly. One of them is central to this post: during multi-step visual reasoning, the model "may gradually lose focus on the image content, leading to hallucinations". Training data and recipe are not reported.

Kimi-VL-Thinking (Moonshot AI, April 2025) is a mixture-of-experts model with 16B total parameters. About 2.8B language-model parameters and a 0.4B vision encoder are active per token. The encoder, MoonViT, works at native resolution and starts from SigLIP-SO-400M. A pixel shuffle and a two-layer MLP connect it to the decoder. The thinking variant gets a long chain-of-thought SFT warm-up, then RL with a 0/1 reward and a length penalty against overthinking. The later 2506 release raised the encoder's limit to about 3.2 million pixels per image and cut average output length by about 20%. It reported 56.9 on MathVision and 83.2 on V*Bench, up from 36.8 on MathVision for the first Thinking release.

GLM-4.1V-9B-Thinking (GLM-V team, July 2025) pairs an AIMv2-Huge encoder with the GLM-4-9B decoder through an MLP adapter. It reads images at native resolution and aspect ratio, using 2D-RoPE in the encoder and 3D-RoPE in the decoder. After a long chain-of-thought cold start, it uses reinforcement learning with curriculum sampling (RLCS). The rewards are domain-specific: numeric matching for math, edit distance for OCR, and an IoU threshold for grounding. Its traces live inside think tags, and the report does not describe image operations during thinking. It is a Form 1 model.

Qwen3-VL Thinking (Qwen, 2025; technical report November 2025) comes in dense sizes from 2B to 32B and in two mixture-of-experts sizes, 30B-A3B and 235B-A22B. The encoder follows the SigLIP-2 architecture with dynamic resolution, and DeepStack feeds features from three encoder levels into the first three decoder layers. Thinking variants get a long chain-of-thought cold start, distillation from stronger teachers, and RL. The report also trains a "thinking with images" mode: a cold start of about 10,000 grounding examples, about 120,000 distilled multi-turn agentic interactions, and tool-integrated RL. With tools, the 235B-A22B model reports 93.7 on V*Bench. The report states that tools add about 5 points on V* across the family. That is a direct measurement of Form 2 over Form 1 within one model family.

OpenAI o3 and o4-mini (April 2025) are the reference Form 2 systems. Architecture, data and training are not reported.

Insight

The cleanest evidence for perception compute comes from holding the weights fixed. Qwen3-VL reports about 5 points on V* from enabling tools within the same family. DeepEyes lifts the same Qwen2.5-VL-7B base from 71.2 to 90.1 on V* by teaching it to zoom. When you compare reasoning VLMs on detail benchmarks, check whether tools were enabled. That setting can matter as much as the model choice.

What reasoning tokens cannot recover

We can now make the opening example quantitative. The goal is to see exactly where the plaque text disappears, and why no amount of reasoning brings it back.

Where the pixels go

Take a 12-megapixel phone photo, 4032 pixels wide and 3024 tall. The plaque text is 32 pixels tall in the original.

A VLM cannot afford to encode every pixel. With 14-pixel patches and no token merging, the full photo would need (4032/14) × (3024/14) = 288 × 216 = 62,208 visual tokens. So the resolution policy resizes it. (The Cost of a Picture covers the token-compression side of this budget.) Suppose it resizes the long side to 448 pixels. The image becomes 448 × 336. The patch grid is 32 × 24, which is 768 tokens.

The text height scales with the image. It becomes 32 × 448 / 4032 ≈ 3.6 pixels. The whole line of text now fits inside a single row of 14-pixel patches.

Resizing is a low-pass filter. Detail finer than the new pixel grid is averaged away before the encoder runs. The encoder never sees the letters. It sees a small grey smudge on a dark plaque.

What it costs to keep the text

Assume, for illustration, that a glyph needs about 12 pixels of height to be read reliably. The exact threshold depends on the encoder and the font. The arithmetic does not.

Keeping 12-pixel text means the long side must be at least 12 × 4032 / 32 = 1512 pixels. The patch grid becomes 108 × 81, which is 8,748 tokens. That is more than eleven times the budget, spent on the whole image to read one plaque.

Now crop instead. Take the top-right region, one quarter of the width and one quarter of the height. In original pixels that is 1008 × 756. Resize it to 448 × 336, the same 768-token budget as before. The text height becomes 32 × 448 / 1008 ≈ 14 pixels. The plaque is readable.

henc = horig · Wenc / Wregion The full image has Wregion = 4032, so henc ≈ 3.6 px. The top-right crop has Wregion = 1008, so henc ≈ 14 px. The token cost is the same 768 in both cases.

This is the core trade-off of multimodal test-time compute. A crop spends the same tokens on a smaller region, so it buys resolution where the answer is. It only works if the model knows where to look.

Nuance

A crop is a bet on localisation. It buys four times the linear resolution at the same token cost only if the answer lies inside the crop. Questions that need the whole scene, such as counting every person in a crowd, gain nothing from one crop and need tiling or higher global resolution instead. Choose the perception method by asking whether the answer is local or global.

Why reasoning cannot help once the detail is gone

At 448 pixels, the visual tokens carry almost no information about the closing time. By the data processing inequality from the first section, nothing computed from those tokens can carry more.

So consider giving the model ten times more reasoning tokens, then a hundred times more. Each extra token is another function of the same zv. The model can reason about which shops usually close when. It can sample many chains and take a majority vote. All of that converges on the language prior: something like 18:00. The plaque says 17:30, and that fact is not in the input to any of these computations.

Principle

Test-time reasoning cannot always compensate for perception failure. Reasoning rearranges the information in the visual tokens. It cannot create information that the encoding discarded. When the missing fact is a visual detail, the remedy is more perception: higher resolution, a crop, another view, or a tool that reads the pixels.

The word "always" matters. Reasoning does help with two kinds of perception problem.

First, it can raise P(U | X). Writing "first, describe the plaque" before answering can make the model attend to evidence it already has. The caption stage in LLaVA-CoT works this way.

Second, the information may be partly present. A blurry "17:3?" still rules out many answers. Reasoning over partial evidence, combined with priors, can narrow the answer. The bound says reasoning cannot exceed what is there. It does not say reasoning gets nothing from a weak signal.

The interactive figure below lets you see both effects. Move the resolution slider and watch the plaque dissolve into patches. Then move the reasoning slider and see when it changes the outcome and when it does not.

Long reasoning drifts away from the image

The previous section covered failure 1. Long reasoning also makes failure 2 worse. The longer a model thinks, the less it tends to look.

The evidence

Several independent studies point the same way.

"More Thinking, Less Seeing?" (Liu and colleagues, 2025) studied multimodal reasoning models directly. As generations get longer, the models drift away from image-grounded content and rely more on language priors. Attention analysis shows that longer chains put less attention on visual inputs. The authors propose RH-AUC, a metric that tracks how perception accuracy changes with reasoning length. They also find that larger models balance reasoning and perception better, and that the type of training data matters more than its volume.

The TVC ablation from the diagnosis section gives the sharpest number. Removing the image halfway through reasoning cost only about 2% accuracy on a hard math subset. The second half of the trace was mostly talking to itself.

The QVQ release post lists the same behaviour as a known limitation. MME-CoT, a benchmark for multimodal chain of thought, found that chain-of-thought prompting often lowers accuracy on perception-heavy tasks. The authors describe it as harmful overthinking.

Insight

In a long trace, the image can stop mattering halfway through. In the TVC ablation, removing the image mid-reasoning cost only about 2% accuracy on a hard math subset. A longer trace therefore does not mean more visual reasoning. If a task depends on visual evidence late in the reasoning, bring the image back explicitly: re-inject it, ground steps in regions, or re-encode a crop.

Why it happens

Two simple mechanisms explain most of it.

The first is dilution. The visual tokens are a fixed block at the start of the context. Reasoning tokens pile up after them. With 768 visual tokens and 5,000 reasoning tokens, the image is about 13% of the context. Attention is not forced to follow those proportions. But as the trace grows, the recent text becomes a stronger predictor of the next token than the distant image, and the measured attention to the image falls.

The second is self-conditioning. Once the trace states "bakeries usually close at 18:00", that sentence is in the context. Later tokens condition on it. A prior stated as text becomes evidence in the model's own eyes, and the actual evidence in the image loses the competition.

What helps

The fixes all bring the image back late in the reasoning.

  • Re-inject the image. TVC moves the image input to critical reasoning stages and prunes redundant visual tokens so the extra copies stay cheap.
  • Teach the model to look back. Look-Back trains the model to decide when to re-focus attention on the visual input, without adding new image tokens.
  • Ground each step. GRIT and ViGoRL make reasoning steps cite boxes or coordinates. A step that must name a region is a step that must look.
  • Re-encode a crop. Form 2 does this by construction. Each new crop puts fresh visual tokens at the end of the context, where the model attends most.
  • Think less on perception tasks. Adaptive methods, covered in the overthinking section, skip long reasoning when the question is mainly perceptual.

The axes of multimodal test-time compute

We now have two facts. Reasoning cannot recover lost pixels. Long reasoning can stop using the pixels it has. Both point to the same conclusion: perception itself must be something a model can spend compute on at test time.

The language-model axes

For text models, How Models Improve Without Changing Their Weights sorts test-time compute into a few axes. A model can reason longer, which is serial compute. It can sample more answers and vote, which is parallel compute. It can search over partial solutions. It can verify candidates with a reward model or a checker. That post also covers why sampling has a scaling law and when verification breaks down.

All four axes still apply to VLMs. But all four take zv as given.

Two new axes

Perception compute changes zv itself. It includes encoding at higher resolution, tiling the image into crops, zooming into a region, re-encoding a region, rotating or enhancing an image, and taking several views. For video it includes sampling more frames.

Tool compute calls a specialised program on the pixels. Examples include an OCR engine, an object detector, a segmenter, a depth estimator, and code that measures or edits the image.

Ctest = Creasoning + Csampling + Cperception + Ctools Search and verification spend from the sampling and reasoning budgets: they generate and score candidates. Perception and tools are the two axes that can raise P(X).

How each axis scales

Let Nv be the number of visual tokens and T the number of reasoning tokens.

Reasoning cost grows faster than linearly in T. Each new token attends to all Nv + t earlier positions. So the attention cost of a trace grows like T · Nv + T2/2, on top of the per-token weight cost.

Sampling multiplies the whole decode cost by the number of samples k. The image prefill can be shared through a cached prefix.

Perception cost has two parts. The encoder cost grows with the number of patches, and quadratically inside the encoder's own attention. The less obvious part comes later: every new visual token joins the context, and every later reasoning token attends to it. A 768-token crop added early in a long trace is paid for again at every step.

Tool cost is mostly latency and returned tokens. A tool result can be very compact. An OCR call that returns "OPEN 9:00–17:30" adds a handful of text tokens. A crop of the same region adds hundreds of visual tokens.

The sampling trap

One interaction between the axes deserves its own warning. Majority voting works when errors are independent across samples. Perceptual errors are not independent. Every sample is computed from the same zv. If the plaque is a smudge in zv, it is a smudge in all 64 samples, and the vote converges confidently on the language prior.

The fix is to decorrelate perception. Sample over views instead of only over text: different crops, scales or rotations. Then the errors that come from one view do not repeat in the others.

Insight

Self-consistency, which works well for text reasoning, is weak against perception errors. Majority voting assumes errors that differ across samples, but every sample shares one encoding. If the encoding lost the plaque, all samples guess the same prior and the vote becomes confidently wrong. Spend the sampling budget on different views of the image, not only on different text samples.

Active perception: looking again

Perception compute only pays off if it is spent in the right place. A crop of the wrong region costs 768 tokens and buys nothing. So the model needs to decide where to look. That decision is the subject of active perception.

Looking as a policy

Think of the image as an environment. The model's state is the question, the views it has taken so far, and its reasoning text. Its actions are visual operations: crop a box, zoom, rotate, call OCR on a region. It also has a final action: answer. Each visual action returns an observation, which is new visual tokens or tool output.

sk = ( q, 𝒱k, r≤k ),   ak ∼ πθ( · | sk ),   ak ∈ { crop(b), zoom, rotate, tool, answer } maxθ  𝔼[ 1{y = Y*} − λ · cost(a1:K) ] Visual processing becomes a sequence of decisions. This is a partially observed decision problem: the model never sees the full-resolution image at once.

This turns visual processing into a policy, which is why reinforcement learning shows up everywhere in this area. The reward is usually only the final answer, sometimes with a format term and a cost term. The RL machinery is covered in Reinforcement Learning from First Principles and, for VLMs, in Rewarding What the Model Sees.

Four ways to decide where to look

A separate search module. V* (Wu and Xie, 2023) was the first clear statement of the idea for VLMs. Its framework, SEAL, pairs a question-answering VLM with a visual search model. When the VLM cannot find a target, it names what it needs. The search model then looks for it, guided by the language model's knowledge of where such things usually are. A plaque, for example, is usually near a door. Found targets go into a visual working memory that the VLM reads. The same paper introduced V*Bench, built around small details in high-resolution images.

The model's own attention. Zhang and colleagues showed that VLMs often attend to the right region even when they answer wrongly. Their training-free method uses the model's attention or gradient maps to choose a crop, then re-asks on the crop. No new training is needed.

Tree search over regions. ZoomEye treats the image as a tree. The root is the whole image and each child is a zoomed sub-region of its parent. The model's own confidence decides which branch to expand. It is training-free and works with several base models. We return to it in the next section.

A learned policy. The largest group trains the model to emit regions itself.

  • DeepEyes trains Qwen2.5-VL-7B with GRPO and no supervised cold start. The model outputs a box. The box is cropped from the original image and appended as a new image. The reward adds a tool bonus only when the answer is correct and at least one zoom happened. V*Bench accuracy rose from 71.2 to 90.1.
  • Chain-of-Focus fine-tunes on 3,000 agent-generated zoom traces, then runs RL on outcome and format rewards. It reports gains on V* across input resolutions from 224 to 4K.
  • Pixel Reasoner gives the model zoom-in and frame-selection operations. It found that models are reluctant to use new visual operations at first. It adds a curiosity reward to keep them exploring.
  • GRIT trains reasoning chains that interleave text with explicit box coordinates, with RL on answer and format alone. It reports learning from as few as 20 training examples.
  • ViGoRL anchors each reasoning step to a coordinate and zooms there in a multi-turn loop. It reports 86.4% on V*Bench.
  • Mini-o3 scales to tens of turns of trial-and-error search. It trains with at most six turns and does not penalise answers that hit the turn limit. At test time its traces grow to tens of turns, and accuracy rises with the number of turns.
  • ACTIVE-o3 formalises active perception for MLLMs and trains region selection with GRPO, including small-object and remote-sensing tasks.

What the learned policies have in common

Three design choices recur.

The crop always goes back to the original pixels. This is what lets these systems raise P(X). A crop of zv would gain nothing.

The reward is mostly outcome-only. The model is not told where to look. It learns to look where looking pays. That makes data selection important. DeepEyes, for example, keeps training items that are neither always solved nor never solved, and items whose answers can be found by zooming into the true region.

New visual actions need encouragement early in training. Pixel Reasoner adds curiosity. DeepEyes adds a conditional tool bonus. Without such terms, a model that already answers reasonably from the first look has little reason to try a new action.

Nuance

Two closely related papers seem to disagree about cold starts. DeepEyes learned to zoom with RL alone. DeepEyesV2 found that RL alone did not produce robust use of code and search tools, and added a cold-start stage. The difference is the action. Zooming reuses the grounding the base model already has. Code and search are new skills. Use pure RL for actions the model can already almost do, and give it demonstrations first for genuinely new tools.

Active perception is the first place where a VLM acts. Its actions only touch the image, and the image does not change in response. The next post, VLMs That Act, removes that restriction. There the actions are clicks and keystrokes, and the environment changes after each one.

Searching over visual evidence

A single look is a guess about where the answer is. When the guess is uncertain, the model can branch: inspect region A, inspect region B, run OCR, read the chart legend. Then it must decide which branch matters. This is search, but over evidence rather than over sentences.

Two kinds of search

Text search explores different reasoning paths over the same visual tokens. LLaVA-CoT's stage-level search, Mulberry's tree search and the Vision Value Model (VisVM) all work this way. VisVM is a good example. It scores each candidate sentence by its expected long-term quality and steers decoding away from sentences likely to lead to hallucination. It improves detailed captions, and self-training on those captions improves the model further.

Evidence search explores different observations. Each branch acquires new visual tokens. Text search re-weights interpretations of a fixed zv. Evidence search changes zv. Only evidence search can fix failure 1.

Nuance

Text search and evidence search look alike in a trace, since both branch and backtrack. They fix different failures. VisVM-guided search reduces hallucination in captions by steering towards better sentences over the same visual tokens, which raises P(U | X). Only evidence search raises P(X). When a search method reports gains, ask which kind of search it is before assuming it will help on small details.

Which branch to expand

The ideal rule is the value of information. Look where you expect to learn the most about the answer, per unit cost.

j* = argmaxj  [ H(Y | 𝒱) − 𝔼 H(Y | 𝒱, lookj) ] / costj H is the model's uncertainty about the answer. The numerator is the expected information gain of looking at region j.

No system computes this exactly. They use proxies. ZoomEye asks the model how confident it is that the target exists in a sub-region, and how confident it is that it could answer from it. V* uses the language model's prior about where objects tend to be. Attention-based cropping uses the model's attention map. Learned policies fold the estimate into the weights.

Backtracking and distractors

Real images contain distractors. The street photo also has a bus-stop sign with a time on it: "Bus 12 · 17:45". A search that stops at the first time-shaped string answers 17:45.

Good evidence search needs two things here. It needs to judge whether a piece of evidence answers the question that was asked, not a similar one. And it needs to back out of a branch that turned out irrelevant. Mini-o3's traces show exactly these behaviours: depth-first search, trial and error, and keeping track of the goal. The next section turns that judgement into an explicit check.

Verifying against the image

Verification is one of the strongest levers for text models. The generator–verifier gap explains why: checking an answer is often easier than producing it. The same holds for images, with a twist. A visual verifier can check much more than the answer.

What a text verifier sees

A text-only verifier reads the question, the answer and the rationale. For the bakery, it sees "the plaque reads 9:00–17:30, so the bakery closes at 17:30". It can check that the conclusion follows from the stated reading. It cannot check the reading itself.

What a visual verifier can see

Grounded traces leave evidence behind: boxes, crops, OCR strings and coordinates. A visual verifier can test each piece.

  • Region check. Re-crop the cited box at high resolution and ask a narrow question: "Is this a plaque with opening hours?"
  • Reading check. Run an independent OCR on the region and compare the string with the one in the trace.
  • Coordinate check. Confirm the box is inside the image, covers a plausible area, and agrees with other cited boxes.
  • Relevance check. Ask whether the cited evidence answers the question asked. The bus timetable fails this check.
  • Counterfactual check. Mask the cited region and ask again. If the answer does not change, the trace did not depend on the evidence it cited.

Each check is easier than the original task. "Does this crop say 17:30?" is a much smaller problem than "find the closing time anywhere in a 12-megapixel photo". That is the generator–verifier gap, extended to pixels.

Process reward models for vision

VisualPRM is an 8B multimodal process reward model. It scores each step of a reasoning trace and is used for best-of-N selection. Applied to InternVL2.5-78B, it added 5.9 points across seven multimodal reasoning benchmarks. It beat outcome reward models and self-consistency in the same setting. The authors also released VisualProcessBench, with human labels for step correctness.

A step-level verifier is most useful when steps make checkable visual claims. Grounded traces from GRIT, ViGoRL and DeepEyes make such claims. A free-text trace that says "the chart shows growth" gives the verifier little to test.

Nuance

VisualPRM's 5.9-point gain on InternVL2.5-78B was measured on multimodal reasoning benchmarks, which are mostly math and science. There, many errors are reasoning errors that a step-level checker can catch. The result does not show that a process reward model fixes misreadings of small details. For perception-heavy tasks, pair a reward model with checks that re-read the cited region.

The shared blind spot

One failure mode carries over from sampling. If the verifier sees the same low-resolution image as the generator, it shares the generator's blind spot. A verifier that cannot read the plaque cannot confirm or reject 17:30. To verify a visual claim, the verifier must look at least as closely as the claim requires.

Overthinking with images

Active perception adds a new way to waste compute. A model can look too much, just as it can think too much.

What overthinking looks like

The patterns are easy to recognise in traces.

  • Inspecting regions that do not matter. The model crops the car and the tree before the plaque.
  • Repeating a crop. It zooms into the same region three times, each time at a slightly different box.
  • Re-reading. It calls OCR five times on a plaque it has already read correctly.
  • Hallucinating after correct perception. It reads 9:00–17:30, then writes "but bakeries usually close at 18:00", and answers 18:00. The prior replaces the evidence.
  • Long reasoning on a perception question. It writes a thousand tokens about a question that needed one look.

These are not hypothetical. OpenAI's own notes on o3 name redundant image operations. DeepEyes reports a clear phase in RL training where tool use spikes and the model over-queries in a "broad sweep", before settling into fewer, better-placed zooms. MME-CoT measures the cost of long reasoning on perception-heavy questions.

Insight

Over-querying is a training phase, not a fixed trait. DeepEyes tracked tool use during RL on V*. It saw a first phase of unfocused exploration, then a phase of frequent zooms that swept the image broadly, then a phase with fewer zooms and high accuracy. A snapshot from the middle of training would suggest the model overthinks by nature. Track tool calls per correct answer over training, and judge efficiency at the end.

Adaptive allocation

The fix is to spend compute where the uncertainty is. A simple rule follows from the factorisation in the first section.

  • If the uncertainty is perceptual, look. The model is unsure what the plaque says.
  • If the uncertainty is inferential, think. The model knows every bar value but not the answer to the question.
  • If neither, answer now.

A stopping rule for looking follows the same logic. Stop when a new view no longer changes the model's belief about the answer.

Training for it

Several methods train this behaviour directly.

  • TON ("Think or Not") randomly replaces reasoning traces with empty thoughts during supervised training. GRPO then lets the model learn when to skip thinking. It reports up to 90% shorter outputs than vanilla GRPO without losing accuracy.
  • FAST-GRPO estimates question difficulty and adapts length rewards and the KL term to it. It reports 32.7–67.3% fewer tokens than earlier slow-thinking models, with higher accuracy than its base model.
  • Kimi-VL-Thinking adds a length penalty during RL. Its 2506 release cut average output length by about 20%.
  • Vision-R1 suppresses long thinking early in RL and relaxes the limit later.
  • Cost terms in the reward. The λ · cost term in the active perception objective penalises each look. DeepEyes takes a different route: it pays a tool bonus only when the answer is correct, so extra looks earn nothing on their own.

The opposite risk exists too. Mini-o3 deliberately does not penalise trajectories that hit the turn limit, because hard search problems need many turns. The right budget depends on the task. That is why adaptive allocation beats a fixed cap.

Visual tools as reasoning steps

Cropping is the simplest visual operation. It only selects pixels. Other operations change the image: drawing a line, marking objects, masking a region, rotating, enhancing contrast. The resulting image becomes an intermediate thought that the model can look at.

Why drawing helps reasoning

Consider a geometry problem. Prove that the angles of a triangle sum to 180 degrees. A student draws a line through the top vertex, parallel to the base. Suddenly the proof is visible. Two angles at the top equal the two base angles, because they are alternate angles. Together with the top angle they form a straight line.

The drawn line did three things. It stored part of the reasoning outside working memory. It turned a hard judgement ("how do these angles relate?") into an easy perceptual one ("these two marked angles look the same"). And it created a new image that the same visual system could read again.

Charts work the same way. To answer "how many bars exceed 40?", draw a horizontal line at 40 and mark each bar above it. Counting marked bars is easier than comparing each bar height to an axis tick.

From programs to sketches

Programs over vision modules. VisProg and ViperGPT had a language model write a Python program that called detectors, segmenters and other vision modules, then executed it. No training was needed, and the program is a readable rationale. The weakness is brittleness: any module error flows through the program unchecked.

Marks as visual prompts. Set-of-Mark prompting overlays numbered marks on regions from a segmenter. The model can then refer to "region 3" instead of describing a location. It is a visual tool used before reasoning starts.

Sketching during reasoning. Visual Sketchpad gives a multimodal model a sketchpad and drawing tools. The model can draw lines, boxes and marks, and call detectors and segmenters, then look at the result and continue. It reported average gains of 12.7% on math tasks and 8.6% on vision tasks over the same models without sketching. With GPT-4o, it reached 80.3% on V*Bench. Sketchpad is training-free.

Training tool use with reinforcement learning

VTool-R1 trains a VLM with RL to use Python-based visual editing tools, on chart and table questions. The reward is outcome-only. The model learns when an edit helps the final answer, without step-level supervision. OpenThinkIMG builds shared infrastructure for vision tools and trains with V-ToolRL. On chart reasoning, its RL agent on Qwen2-VL-2B beat its own supervised starting point by 28.83 points. Thyme lets the model write and run image-processing and math code. It trains with 500,000 supervised examples and then RL. Visual-ARFT trains models to write image-manipulation code and to search the web. DeepEyesV2 extends DeepEyes to code execution and web search. Its authors found that RL alone did not produce robust tool use, so they added a cold-start stage first.

Insight

For small models, how tool use is learned matters more than having the tools. With the same tools, OpenThinkIMG's RL-trained Qwen2-VL-2B agent beat its own supervised starting point by 28.83 points on chart reasoning. Demonstrations teach the format of a tool call. Outcome rewards teach when a call helps. Budget for an RL stage whenever tool use has to transfer beyond the demonstrations.

Imagined images

The last step is to generate the intermediate image instead of editing a real one. MVoT generates visualisations of a spatial reasoning trace, such as the state of a grid after each move. Visual Planning goes further and plans purely in images, trained with RL on navigation tasks. "Thinking with Generated Images" generates visual subgoals and critiques them. Mirage and LVR, from the three forms section, keep the imagined state as latent vectors instead of pixels.

These methods are promising for spatial and planning problems. Note one limit, though. An imagined image is computed from what the model already knows. Like latent reasoning, it can restructure information. It cannot read a plaque the model never saw clearly.

What to carry forward

We started with a model that looked at a photo once and reasoned for 5,000 tokens to a wrong answer. We can now say precisely what went wrong and what would have fixed it.

  • Split every visual answer into perception and reasoning. A wrong answer comes from one of three places: the fact was never extracted, it was extracted but ignored, or the reasoning failed.
  • Diagnose before you fix. Blind probes, oracle swaps, caption-then-reason, crops, linear probes and mid-trace ablations tell the three failures apart.
  • Reasoning is bounded by the encoding. By the data processing inequality, no amount of reasoning recovers a detail the encoder discarded.
  • Long reasoning can stop looking. Bring the image back late in the trace: re-inject it, ground steps in regions, or re-encode a crop.
  • Perception is a test-time compute axis. Crops buy resolution where the answer is. They need a policy that knows where to look.
  • Sample over views, not only over text. Perceptual errors repeat across samples that share one encoding.
  • Verify with pixels. Grounded traces let a verifier check regions, readings and counterfactuals.
  • Match the spend to the uncertainty. Look when unsure what is there. Think when unsure what follows. Answer when neither.

One idea connects the second half of this post. Once looking is an action, a VLM is a policy acting on an environment. In this post, that environment was a single image that never changed. In the next post, VLMs That Act, the environment is a screen, a browser or a robot's camera. The actions are clicks, keystrokes and movements, and the environment changes after each one.

Key insights and nuances

  • Reasoning cannot buy perception. Reasoning tokens act on the reasoning and attention factors, never on whether the fact reached the visual tokens. Measure that first. (Perception and reasoning, What reasoning tokens cannot recover)
  • Models often know where to look but cannot read it. Attention finds the right region even on wrong answers, so a crop guided by attention is the first fix. (Finding the stage that failed)
  • Benchmark gains can be gains in priors. GeminiPro scored 42.9% on MMMU without the image. Always report a blind baseline. (Finding the stage that failed)
  • Slow thinking lives in the language model. Text-only long-thought data transfers to multimodal problems, so math-benchmark gains say little about perception. (History)
  • Looking again is worth points with the same weights. Tools add about 5 points on V* within Qwen3-VL, and DeepEyes lifts its base from 71.2 to 90.1. (Reasoning VLMs)
  • A crop is a bet on localisation. It buys resolution only where the answer is. Global questions need tiling or higher global resolution. (What reasoning tokens cannot recover)
  • Long traces stop looking. Removing the image halfway through cost only about 2% in the TVC ablation. Bring the image back late in the trace. (Drift)
  • Votes share the encoder's blind spot. Sample over views, not only over text. (Compute axes)
  • Latents help use, not extraction. Latent visual reasoning improves fine-grained patterns the encoder carries, not detail resizing removed. (Three forms)
  • Pure RL works for actions the model can almost do. Zoom learned without a cold start. Code and search tools needed one. (Active perception)
  • Over-querying is a phase. Tool use in DeepEyes went from exploration to a broad sweep to efficient use. Judge efficiency at the end of training. (Overthinking)
  • Process reward gains were measured on reasoning-heavy benchmarks. Pair them with checks that re-read cited regions for perception-heavy tasks. (Verification)
